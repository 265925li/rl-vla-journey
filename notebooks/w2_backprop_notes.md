## 〇、一句话结论

把「分类损失对 logits 的梯度」一口气推完，结果是

```
∂L/∂z = p - onehot
```

其余四步全是这句话加**形状约束**推出来的，不需要任何额外记忆。

## 一、问题设定

两层的 MLP，做 C 类分类，batch 大小 N：

```
z1 = X  @ W1 + b1        (N,D) @ (D,H) -> (N,H)
a1 = relu(z1)           逐元素
z2 = a1 @ W2 + b2        (N,H) @ (H,C) -> (N,C)     ← z2 就是 logits
p  = softmax(z2)        按行归一化
L  = -(1/N) Σᵢ log p[i, yᵢ]                         ← 标量
```

目标是求 `∂L/∂W1, ∂L/∂b1, ∂L/∂W2, ∂L/∂b2` 四个梯度。

**反向传播不是算法，是链式法则的机械应用**：每个算子只需知道自己的
「本地导数」，把上游传下来的梯度乘上去、再传给下游。所以推导从后往前，
一次只处理一个算子。

---

## 二、第 1 步：`∂L/∂z2`（唯一需要真推的一步）

单样本（先去掉 `/N`）：`L = -log p_y`，其中 `y` 是正确类的下标。

### 2.1 `∂pᵢ/∂z_k`

关键观察：`z_k` 恒在分母（分母是全类的指数和），只在 `k == i` 时出现在分子。
于是分两种情形，用商的求导法则 `(u/v)' = (u'v - uv')/v²`，记 `S = Σⱼ e^{zⱼ}`：

**情形 A（i == k）**

```
∂p_k/∂z_k = (e^{z_k}·S - e^{z_k}·e^{z_k}) / S²
          = e^{z_k}/S - (e^{z_k}/S)²
          = p_k - p_k²
          = p_k (1 - p_k)
```

**情形 B（i ≠ k）**

```
∂p_i/∂z_k = (0·S - e^{z_i}·e^{z_k}) / S²
          = -p_i p_k
```

**合并**（`δ_ik` 当 i==k 时为 1，否则 0）：

```
∂p_i/∂z_k = p_i (δ_ik - p_k)
```

验算：δ=1 → `p_k(1-p_k)` ✅；δ=0 → `-p_i p_k` ✅

### 2.2 代回 `∂L/∂z_k`

`L = -log p_y`，所以 `∂L/∂p_y = -1/p_y`。

`L` 只通过 `p_y` 依赖 `z_k`（其它 `p_i` 不进 loss），链式法则只有一项：

```
∂L/∂z_k = (∂L/∂p_y) · (∂p_y/∂z_k)
        = (-1/p_y) · p_y (δ_yk - p_k)
        = -(δ_yk - p_k)
        = p_k - δ_yk
```

**`p_y` 被约掉了**——这正是交叉熵配 softmax 好算的原因。

### 2.3 三个自检

| 情形 | 结果 | 含义 |
|---|---|---|
| `k == y` | `p_y - 1` | 永远 ≤ 0，预测越准越接近 0 |
| `k != y` | `p_k` | 永远是 ≥ 0，只把错类的分数往下压 |
| `Σ_k ∂L/∂z_k` | `1 - 1 = 0` | 行和恒为 0 |

第三行的原因不是巧合：softmax 对 `z` 整体加常数不变（`p(z+c) = p(z)`），
意味着 `∂L/∂z` 在「全 1 方向」上的分量必须为 0，也就是与 `1` 向量正交。
**任何正确实现都必须满足这条**，它是最省事的自检。

### 2.4 批量 + mean

`L = (1/N) Σ_i L_i`，每个样本的梯度贡献被均摊，所以整体乘 `1/N`：

```python
onehot  = np.zeros_like(p)
onehot[np.arange(N), y] = 1.0
dlogits = (p - onehot) / N          # (N, C)
```

**自检**：`dlogits.sum(axis=1)` 全为 0。

## 三、第 2~4 步：全靠形状凑

有了 `dlogits`（N,C），剩下三个算子都是「线性 + 广播 + 逐元素非线性」，
每一步只有**一种**拼法能凑出正确形状。这就是自检工具：**形状不对，公式必错。**

### 3.1 `∂L/∂W2` 和 `∂L/∂b2`

`z2 = a1 @ W2 + b2`。`W2` 形状 `(H,C)`，已知量只有 `a1 (N,H)` 和 `dlogits (N,C)`。

要凑 `(H,C)`，`(N,H)` 必须放在**左边并转置**：

```python
dW2 = a1.T  @ dlogits        # (H,N) @ (N,C) = (H,C)  ✅
```

`b2` 被广播加到 `(N,C)` 的每一行 → 梯度要把所有行的贡献加起来：

```python
db2 = dlogits.sum(axis=0)    # (C,)  ✅
```

`axis=0` 的意思就是「把这根轴消掉」，`(N,C)` 消掉 `N` 剩下 `C`。

### 3.2 `∂L/∂a1` 和 `∂L/∂z1`

`a1` 通过 `a1 @ W2` 影响 `z2`。要凑 `a1` 的形状 `(N,H)`：

```python
da1 = dlogits @ W2.T         # (N,C) @ (C,H) = (N,H)  ✅
```

**转置方向的口诀**：前向是 `左乘 @ W`，反传就用 `@ Wᵀ`；前向是 `W @ 右乘`，反传就用 `Wᵀ @`。

ReLU 是**逐元素**的，`a1[i,j]` 只依赖 `z1[i,j]`，不跨位置混合，所以用 `*` 不用 `@`：

```python
dz1 = da1 * (z1 > 0)         # 形状不变
```

注意是 `z1 > 0`（ReLU 的**输入**）而不是 `a1 > 0`。这两种写法**完全等价**，不是近似：
`z1 > 0` 时 `a1 = z1 > 0`；`z1 <= 0` 时 `a1 = 0`，而 `0 > 0` 为假——连 `z1 == 0` 处也一致
（实测 `np.array_equal(z1>0, a1>0)` 恒为 `True`，人为把某个元素置 0 后仍为 `True`）。

语义上仍建议写 `z1 > 0`，因为它表达的是「ReLU 对输入求导」，而不是「对输出求导」。

### 3.3 `∂L/∂W1` 和 `∂L/∂b1`

把 3.1 里的 `a1` 换成 `X`、`dlogits` 换成 `dz1`，结构完全一样：

```python
dW1 = X.T   @ dz1            # (D,N) @ (N,H) = (D,H)  ✅
db1 = dz1.sum(axis=0)        # (H,)  ✅
```

## 四、七行汇总（这就是全部答案）

```python
dlogits = (p - onehot) / N       # (N, C)
dW2     = a1.T @ dlogits         # (H, C)
db2     = dlogits.sum(axis=0)    # (C,)
da1     = dlogits @ W2.T         # (N, H)
dz1     = da1 * (z1 > 0)         # (N, H)
dW1     = X.T @ dz1              # (D, H)
db1     = dz1.sum(axis=0)        # (H,)
```

**记忆方式：不要背这七行，背两条规则**

1. `dW = 输入ᵀ @ 上游梯度`，`db = 上游梯度.sum(axis=0)`
2. 前向用 `@ W` 的，反传用 `@ Wᵀ`

第 1 条对**任何**线性层都成立（Day 17 手写 Linear 时原样照抄），
第 2 条对任何线性映射成立。

## 五、验证：三层裁判

公式对不对，不能靠「看着像」。用了三层独立程度递增的裁判：

| 裁判 | 独立性 | 能发现什么 |
|---|---|---|
| 手算小例子 | 低（同一套公式） | 算错、抄错 |
| `torch` autograd | 中（别人的实现） | 公式错、实现错 |
| **有限差分** | **高（不依赖任何公式）** | 公式本身错了 |

第三层最关键：有限差分只是把 `L(θ+h) - L(θ-h)` 除以 `2h`，
**它根本不知道什么叫链式法则**。所以它能抓住「我以为对的公式其实是错的」。

### 5.1 有限差分的 `h` 怎么选

中心差分的误差是两种误差的拉扯：

- `h` 太大 → 泰勒展开的三阶项没被消掉，**截断误差** ~ `h²`
- `h` 太小 → `L(θ+h)` 和 `L(θ-h)` 在浮点上几乎相等，相减后相对误差爆炸，**舍入误差** ~ `ε/h`

实测（`f(x) = log x`，`x = 2`，真值 `f' = 0.5`）：

| `h` | 误差 | |
|---|---|---|
| 1e-1 | 4.17e-04 | 截断误差主导 |
| 1e-2 | 4.17e-06 | h 每小 10 倍，误差小 100 倍 |
| 1e-3 | 4.17e-08 | ↑ 正好是 `h²` |
| 1e-4 | 4.17e-10 | |
| **1e-5** | **8.83e-12** | **最优** |
| 1e-6 | 1.44e-11 | 舍入误差开始接管 |
| 1e-7 | 2.63e-10 | |
| 1e-8 | 3.04e-09 | |
| 1e-10 | 4.14e-08 | 平台，降不下去了 |
| 1e-12 | 4.45e-05 | 灾难性抵消 |

**实用结论**：不用纠结最优值。`h` 取 `1e-4 ~ 1e-6` 之间，误差都在 `1e-10 ~ 1e-11` 量级，
比「判断公式对不对」需要的精度（`1e-6`）还高 4 个数量级。取 `1e-5` 是个安全的默认值。

**前提**：必须用超越函数（`exp`/`log`/`tanh`）来测。三次多项式下中心差分是**精确**的，
误差恒为 0，测不出任何东西——这是个很容易踩的坑。

### 5.2 本次实测数字（`scripts/backprop_numpy.py`，float64，N=8 D=5 H=4 C=3）

```
loss = 1.1758884322        （numpy 与 torch 差 4.4e-12）

参数      numpy vs torch      numpy vs 有限差分
W1            5.551e-17              1.712e-11
b1            2.776e-17              6.826e-12
W2            2.776e-17              1.808e-11
b2            2.776e-17              1.555e-11

dlogits 单行对拍（只测这一步）         1.479e-11
大规模 N=100 D=20 H=16 C=10            4.857e-17
```

**怎么读这张表**：

- `1e-17` 这个量级是 **float64 的机器精度极限**（`2⁻⁵³ ≈ 1.11e-16`）。numpy 和 torch
  走到 `1e-17`，说明两条独立实现的浮点路径**几乎逐位相同**，不存在「公式不同但结果接近」的可能。
- `1e-11` 是有限差分的**方法误差下限**，不是我们算错了。它比 torch 那边大 6 个数量级，
  是因为差分本身只有 `O(h²)` 精度。
- 两个量级各自对齐，才说明**公式对 + 实现对**。

**技巧**：把 `dlogits` 抽成一个独立函数 `grad_logits(p, y)` 单独对拍。
如果第 1 步就错了，后面四步全错，混在一起查是灾难；先锁死第 1 步，后面才有意义。
（这就是「一次只怀疑一个东西」。）

## 六、四种写错的代价（实测）

这部分比公式重要——**它说明为什么必须用有限差分，而不能只看 loss 对不对。**

### 6.1 错误的可见性：一个在 N 小时隐身，一个永远「差三成」

相对误差倍数 = `||错梯度 - 对梯度|| / ||对梯度||`。实测（`_probe_vis.py`，D=5 H=4 C=3，float64）：

| N | 漏 `/N` | 忘乘 ReLU 导数 |
|---|---|---|
| **1** | **0.0000（完全隐身）** | 1.51 |
| 2 | 1.0000 | 1.14 |
| 4 | 3.0000 | 0.63 |
| 8 | 7.0000 | 0.69 |
| 16 | 15.0000 | 0.69 |
| 32 | 31.0000 | 0.51 |
| 64 | 63.0000 | 0.31 |
| 128 | 127.0000 | 0.33 |
| 256 | 255.0000 | 0.51 |

两个错误看起来都像「公式的一部分没写」，但可见性完全不同：

- **漏 `/N`：误差恰好是 `N-1` 倍，且 `N=1` 时精确为 0。**
  这意味着你手算验证、或者写单元测试时最自然的那个例子（单样本），**这个 bug 完全不存在**。
  等你换成 `N=64` 才发现时，误差已经 63 倍了——问题是你未必会去换。
- **忘乘 ReLU 导数：误差倍数一直卡在 0.3 ~ 1.5 之间，不随 N 增大而暴露。**
  任何 batch 大小下它都只是「差三成左右」，看上去像「数值误差」「实现细节差异」，
  而不像一个 bug。加大数据量也不会让它变明显。

结论：**这两个 bug 都不会被「跑通了、loss 降了、数字看着差不多」发现。**
只有有限差分能抓——因为它是唯一一个「知道你漏了哪一项」的裁判。

### 6.2 一个「写法不同但结果完全一样」的例子

`dz1 = da1 * (z1 > 0)` 和 `dz1 = da1 * (a1 > 0)` 是**严格等价**的：
`a1 = max(z1, 0)`，所以 `a1 > 0` 与 `z1 > 0` 在每一处判定都相同，包括 `z1 == 0`
（此时 `0 > 0` 为假，两边都给 0）。实测 `np.array_equal` 恒为 `True`。

**区分这两类**：一种是结果错了但不报错（6.1），一种是写法不同但结果一样（6.2）。
后者不用管，前者才致命。判断方法只有一个：**跑能覆盖边界的数值实验，
并且必须有一个不依赖你自己公式的裁判**。

### 6.3 为什么「形状对」不等于「公式对」

`dW1 = X.T @ dlogits` 形状是 `(5,3)`，期望 `(5,4)` → 当场报错，很好。
但如果 `H == C`（比如 4 分类、4 个隐藏单元），它形状也能对上，**静默算错**。

所以形状断言是第一道也是最便宜的一道，但**不能当作唯一一道**。

## 七、口述版

### 30 秒版

> 分类损失对 logits 的梯度是 `p - onehot`。因为 `-log p_y` 求导给出的 `1/p_y`
> 正好抵消 softmax 求导里的 `p_y`，剩下的就是「预测概率减标签」。
> 从这一步往回，每个线性层只要记住两条：`dW = 输入ᵀ @ 上游梯度`，
> 反传用 `@ Wᵀ`；ReLU 是逐元素的，乘一个 `(z>0)` 掩码。
> 验证靠有限差分——它不依赖任何公式，是唯一的独立裁判。

### 3 分钟版（面试可用的展开顺序）

1. **设定**：两层 MLP，`z1 → a1=relu → z2 → softmax → 交叉熵`，说明 `z2` 是 logits。
2. **核心一步**：`∂pᵢ/∂z_k = pᵢ(δ_ik - p_k)`，分 `i==k` / `i≠k` 两种情况用商法则推，再合并。
3. **约掉**：`(∂L/∂p_y)·(∂p_y/∂z_k) = (-1/p_y)·p_y(...)`，`p_y` 消失。
4. **自检**：行和为 0，原因是 softmax 平移不变。
5. **往回传**：只讲形状，`dW2 = a1ᵀ @ dlogits`，`da1 = dlogits @ W2ᵀ`，`dz1` 用掩码。
6. **验证**：三层裁判，为什么必须用有限差分，为什么它只能用超越函数测，
   `float64` 下 torch 对到 `1e-17`（机器精度）、有限差分到 `1e-11`（方法误差）。
7. **踩过的坑**：漏 `/N` 的误差恰好是 `N-1` 倍，`N=1` 时精确隐身；
   忘 ReLU 导数的相对误差一直在 0.3~1.5 倍之间，**不随 batch 变大而暴露**。

## 八、autograd 到底帮我做了什么

（这是 W2 周报的核心问题，答案放在这里，周报里引用。）

如果没有 autograd，上面这七行要**对每一个新结构重推一遍**：

- 换激活函数（`tanh`/`GELU`/`SiLU`）→ `dz` 那行改掉
- 加 BatchNorm / LayerNorm → 多两条反传公式，还涉及跨样本的统计量
- 加残差连接 → 梯度要**分成两路**再相加，人推极易漏一路
- 换成注意力（`QKᵀ → softmax → @V`）→ 三个矩阵乘 + 一个 softmax 的反传

autograd 把这件「每换一个结构就要重推一遍、而且推错了不报错」的活，
变成了「前向怎么写，反向自动就有」。它**不是帮我省打字，是帮我省掉一整类
无声错误**——6.1 那两种 bug 就是这类错误的样本。

但它有代价，也是我必须手推一遍的原因：

1. **不报错的地方它也帮不了**。漏 `/N`、用错上游梯度，autograd 全盘接受，
   算出来的就是一个「自洽但错误」的梯度。
2. **自定义算子必须自己写反传**。P2 之后写 PPO 的 clip 目标、写 VLA 的动作头，
   会遇到 autograd 不认识的操作，这时要手写 `backward`，而正确性只能靠有限差分验。
3. **显存优化要懂它在存什么**。`z1`、`a1` 中间量是为反传留的，懂这个才知道
   梯度检查点（checkpointing）在省什么。

一句话：**autograd 负责「不写错」，我负责「判断它对不对」。**
第二件事它做不了，而那正是需要练的能力。

## 附：这些结论后面在哪用

| 结论 | 后续出现的地方 |
|---|---|
| `dlogits = p - onehot` | 所有分类任务的起点；PPO 的 ratio 也从「策略对动作的概率」推 |
| `dW = 激活值ᵀ @ 上游梯度` | 手写线性层（Day 17）、LoRA 层的梯度 |
| `da = 上游 @ Wᵀ` | 上面那条的反向 |
| `dz = da * (z>0)` | 所有逐元素非线性；GRU/LSTM 的门控同理 |
| `db = 上游.sum(axis=0)` | 所有带广播的偏置 |
| 有限差分当裁判 | P2 之后调试任何自定义 loss / 自定义算子 |
