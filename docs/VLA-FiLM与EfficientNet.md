# 支线 · FiLM 与 EfficientNet-B3：怎么把一句话「注进」一张图里

## 0. 这一章要回答的问题

一个机器人的相机每秒拍 3 张图，同时收到一句指令：

- 「把苹果拿起来」
- 「把抽屉拉开」

**同一张图，需要提取的特征完全不同。** 图里既有苹果也有抽屉把手。要抓苹果，网络该放大「圆形、红色、可抓握」的通道；要开抽屉，该放大「横向长条、边缘」的通道。

问题于是变成：

> **怎么让一个固定的卷积网络，根据输入的那句话，改变自己「看什么」？**

这件事的术语叫 **条件化（conditioning）**。FiLM 是其中一种具体做法。

注意这里有个容易含混的地方：**图和话必须融合，那么在哪里融合、用什么算子融合？** 这一个问题的不同答案，就是这一章的全部内容。

---

## 1. 先看最朴素的做法：把话拼进输入

最直接的想法 —— 指令编码成 512 维向量 `z`，图像是 `3×300×300`，那就把 `z` 复制成 `512×300×300` 贴到通道维上，变成 `515×300×300`，一起送进去。

**为什么这样不好？三笔账：**

1. **第一层权重全废。** EfficientNet 的第一层卷积是 `3→40` 通道、在 ImageNet 上训好的。你把它改成 `515→40`，原来那 `3×40` 部分虽然能搬过来，但**新增的 `512×40` 是随机初始化的**，而且是 512 个通道的噪声灌进第一层——相比之下原来那 3 个通道的信号被淹掉了。预训练的价值基本被这一改抵消。
2. **位置错了。** 语言是全局的（一句话描述整个场景），把它铺在输入的空间维上，等于告诉网络「每个像素旁边都写着这句话」。网络得自己学会「这句话其实该整体使用」，但这没有先验。
3. **深层用不上。** 拼接只发生在入口。可「抓苹果」这种语义，要到网络很深的层才存在。浅层只知道边缘和颜色，你在浅层放一句话，它没法用。

第 1 条是致命的。**预训练权重才是这个骨干的全部价值**，任何改动都不该破坏它。

## 2. 四种注入方式的谱系（本章骨架）

后面所有做法都是同一个式子的特例：

```
y_c = a_c · x_c + b_c          c = 1..C 是通道下标
```

`(a_c, b_c)` 这组系数**由指令 `z` 算出来**，而不是学成固定参数。四种选择的区别只在「允许 `a`、`b` 取什么」：

| 方式 | 式子 | 参数量（`C=d=512`） | 相对 FiLM |
|---|---|---|---|
| 输入拼接 | 改第一层输入通道 | 2,359,296 | 4.49× |
| 加法偏置 | `y = x + b(z)` | 262,656 | 0.50× |
| 乘性缩放 | `y = a(z) · x` | 262,656 | 0.50× |
| **仿射（FiLM）** | `y = (1+γ(z))·x + β(z)` | **525,312** | 1.00× |
| cross-attention | `Q,K,V` 四组投影 | 1,048,576 | 2.00× |

（上表由脚本实验 E 打印，`C` 取 512、`d` 取 512。）

关键在于**它们的能力差别，不是精度的差别，是「能不能表达」的差别**：

**只加 `b` 不够。** `y = x + b` 相当于把每个通道整体「调亮或调暗」。它能表达「更重视第 7 号通道」，但表达不了「**把第 7 号通道相对第 3 号通道放大**」。因为整体平移不改变通道之间的比例关系。

**只乘 `a` 也不够。** `y = a·x` 能改比例了，但**必须过原点**：它没法做「不管输入多小，都加一个底」这种平移。而且如果某个通道的 `x` 恰好是 0，乘什么都没用。

**两个一起，才是「每个通道各自的一次完整线性变换」。** 这是 1 维仿射群，是保持「通道之间不混合」的前提下**最一般**的变换。少一个自由度就表达不全。

**为什么不做通道混合（`C×C` 全连接）？** 两个原因：
- 参数量 `C² = 262144`，是仿射的 500 倍，而且每层都做一遍
- 更重要的：卷积之所以有效，是因为它假设「每个通道是一种特征检测器」。做 `C×C` 混合等于说「通道的含义可以被任意重组」，这会破坏预训练学到的通道语义 —— 又回到第 1 节那个问题

所以 FiLM 选的是**对角矩阵**：`diag(a₁,...,a_C) · x + b`。够用，且不破坏结构。

## 3. 「逐通道」到底逐的是什么（实测）

`γ` 和 `β` 都是长度 `C` 的向量，而特征图是 `C×H×W`。怎么对上？

```python
gamma[:, :, None, None]     # (B, C)  →  (B, C, 1, 1)
```

然后 PyTorch 广播：`(B,C,1,1)` 与 `(B,C,H,W)` 相乘，**沿 H、W 两个方向复制**。

实测验证（实验 B，`C=8, H=W=5`）：

- `(y − β)/x` 在**同一通道内**的极差 `5.245e-06`（float32 舍入量级 → 处处相等）
- 该比值与 `1+γ` 的最大偏差 `1.192e-07`
- `std(y)/std(x)` 与 `|1+γ|` 的偏差 `1.192e-07`

结论只有一句：**同一个通道的所有空间位置，乘的是同一个数。**

这句话有两个后果，一个好一个坏：

- **好**：`γ,β` 的大小与分辨率无关。`300×300` 和 `224×224` 用同一套系数，模型可以换分辨率。参数量也不随像素数涨。
- **坏**：它**没有空间定位能力**。「抓左边那个杯子」里的「左边」，FiLM 表达不出来 —— 因为整张图共用一组系数。这是后面第 8 节要付的代价。

---

## 4. `γ`、`β` 从哪来：一个「产出参数的参数网络」

`z` 是 512 维，`γ` 要 `C` 维。这中间是一个线性层：

```
γ = W_γ z + b_γ        W_γ ∈ R^{C×512}
β = W_β z + b_β        W_β ∈ R^{C×512}
```

这类「**用网络的输出当作另一个网络的参数/调制系数**」的结构，一般叫**超网络（hypernetwork）**。它不是这一章独有的技巧，后面会反复见到。

## 5. identity 初始化：本章最实用的一条

现在把 FiLM 插进预训练网络。**插进去那一瞬间，网络就坏了。**

原因：预训练的每一层激活值，都是「前面所有层的权重配合好」的结果。你在中间插一个随机的仿射变换，等于在一条精心校准的链条中间拧了一下 —— 后面的层收到的输入分布全变了，ImageNet 那套权重白学。

RT-1 的解法：**把 `W_γ` 和 `W_β` 初始化为全零。**

那么一开始 `γ ≡ 0`、`β ≡ 0`，式子变成：

```
y = (1+0)·x + 0 = x
```

**这是精确的恒等映射。** 不是「接近恒等」，是逐位相同。

实测（实验 C，随机初始化但**同一个**骨干实例、`train` 模式）：

| 情况 | 与原始输出的最大偏差 |
|---|---|
| identity 初始化 | `0.000e+00`，`torch.equal = True` |
| 普通随机初始化 | `4.812337`，**占激活尺度的 108.5%** |

两行读完：**零初始化让整个网络行为一字不变；随机初始化直接把输出打烂（偏差比激活本身还大）。**

> ⚠️ **这里踩了两个坑，都值得记。**
>
> **坑 1：基准错了，结论全错。** 第一版我用 `eval()` 模式做对比，结果测出「原始输出 \|max\| = 0.000000」，随机初始化偏差反而是「激活的 6e15 倍」这种荒唐数。查下去发现：随机初始化的网络在 `eval` 模式下，BN 用的是 `running_mean=0, running_var=1`（初始值，等于什么都没做），激活**逐阶段衰减** —— 实测 std 从 `2.005e-01` 一路掉到 `3.720e-14`。在 1e-14 量级的信号上比较偏差，什么结论都能编出来。必须换 `train()` 模式，让 BN 用批统计。
>
> **坑 2：随机深度让前向不确定。** 换成 `train()` 后「逐位相同」还是 False，两次同样的前向就差 `5.93`。原因是 torchvision 0.28 的 `StochasticDepth` 用 `p`（丢弃概率）字段，而我按老版本去改 `survival_prob = 1.0` —— 改了等于没改。现在脚本里两个字段都设，并且**先断言前向是确定的**，不确定就抛异常，不让测量在噪声里进行。
>
> 这两条合起来是同一个教训：**「逐位对比」这种判据，前提是被测系统本身确定、基准本身可信。两个前提都不会自己声明，得你亲自验。**

### 零初始化会不会把梯度卡死？

这是最常见的反问 —— 零初始化听上去像 ReLU 死亡。

**不会。** 因为

```
∂L/∂W_γ = (∂L/∂γ) · zᵀ,     而 ∂L/∂γ_c = Σ_{h,w} (∂L/∂y_c,h,w) · x_c,h,w
```

梯度里带着**输入 `x`**。`W_γ = 0` 只是让 `γ = 0`，`x` 不为 0，所以梯度不为 0。

实测（实验 D，`loss = 1.368083`）：

| 量 | 值 |
|---|---|
| `‖∂L/∂W_γ‖` | `8.373e-02` |
| `‖∂L/∂W_β‖` | `1.740e-08` |
| 其中恰好为 0 的比例 | `0.00%` |

**两个都非零，一个都没卡。** 但注意这里有个**量级差 6 个数量级**的现象：`β` 的梯度只有 `1.7e-8`。

原因藏在式子里：`γ` 的梯度是 `Σ (∂L/∂y) · x`，**乘了 x**，而 `β` 的梯度是 `Σ (∂L/∂y)`，**只是把上游梯度在空间上求和**，正负容易抵消。所以从恒等点出发时，**`γ` 先动、`β` 慢半拍**。

这不是缺陷，是结构决定的。但如果你哪天做 FiLM 微调发现「怎么只有缩放生效、偏置几乎没学到」，先回来看看这条。

## 6. EfficientNet-B3 那一半：为什么是它

### 6.1 MBConv 块在干什么

一个 MBConv（Mobile Inverted Bottleneck Convolution）块，四步：

```
1×1 升维  →  3×3 depthwise  →  SE 重标定  →  1×1 降维  →  (+ 残差)
```

- **升维**：把通道数放大 6 倍左右，让后面的卷积在高维空间里做
- **depthwise**：每个通道单独卷，通道之间不混合。计算量是普通卷积的 `1/C`
- **SE（Squeeze-Excitation）**：全局平均池化 → 小 MLP → 得到每个通道一个权重 → 加权。**注意：这就是 FiLM 的近亲**，只不过 SE 的条件来自图像自己，FiLM 的条件来自语言
- **降维** + 残差

**depthwise 为什么便宜**：普通 `3×3` 卷积从 `C` 进 `C` 出要 `9C²` 个乘加；depthwise 只要 `9C`。差 `C` 倍。这是 MobileNet 系列的全部秘密。

**代价**：depthwise 的访存效率差（算术强度低），在真实硬件上跑不到理论 FLOPs。你的 1660 Ti（TU116）尤其是这样 —— 这解释了为什么 B3 在纸面上「应该很快」但实测常常不是。

### 6.2 复合缩放

EfficientNet 的核心贡献不是某个模块，是**怎么同时放大三个维度**：深度（层数）、宽度（通道数）、分辨率。

只放大其中一个会很快饱和（层数多了梯度难传，宽度大了收益递减，分辨率高了计算量平方涨）。EfficientNet 的做法是让三者按一组固定比例一起放大，再网格搜索比例。`B0` 是基线（`224×224`，宽度/深度系数都是 1.0）；`B3` 这一档是**宽度系数 1.2、深度系数 1.4、输入 `300×300`**，共 26 个 MBConv 块。

### 6.3 实测的规模（实验 A）

| 项 | 数值 |
|---|---|
| MBConv 块数 | **26**（和 RT-1 论文说的 26 一致） |
| 各块输出通道之和 | 3264 |
| 骨干 `features` | 10,696,232（**10.70M**） |
| 分类头（不用） | 1,537,000 |
| **FiLM 增量（γ,β 各一套）** | **3,348,864（3.35M）** |
| 末层 1×1 投影到 512 | 786,944（0.79M） |
| 合计（去掉分类头） | **14,832,040（14.83M）** |
| FiLM / 骨干 | **31.3%** |

RT-1 论文说这个 tokenizer 是 16M 参数。我算出来 14.83M —— **差 1.2M 我不硬凑**，可能的来源是末层投影的口径、或他们对 d 的取法略有不同。**记「实测 14.83M，论文报 16M，差 7.5%」比编一个吻合的数诚实。**

顺带纠正一个常见的误读：**「FiLM 很轻量」说的是 FLOPs，不是参数量。** 它占了骨干的 31%，一点不轻；但它是逐元素运算，不比卷积贵。实验 E 的量级差能把这件事说清：

| | FLOPs（81 个 token） |
|---|---|
| 仿射 FiLM | 82,944 |
| cross-attention | 84,934,656 |

**差 1024 倍。** 这才是「轻量」的含义。

## 7. 拼起来：RT-1 的视觉 tokenizer

```
指令文本
  └→ Universal Sentence Encoder  ──→ z (512 维)
                                        │
                                        ├→ 每个 FiLM 层的 W_γ, W_β（identity 初始化）

图像 6 帧 300×300×3
  └→ Conv 3→40
     └→ 26 × [ MBConv ──→ FiLM(γ,β from z) ]
        └→ Conv 1×1 → 512
           └→ 9×9×512  = 81 个视觉 token / 帧
              └→ TokenLearner 压到 8 个 → 6 帧共 48 个 token
                 └→ Transformer（8 层、19M）→ 动作 token
```

几点值得注意：

- **FiLM 加在「块之后」，不是「块之内」**，而且**每块都加**。浅层的 FiLM 在调「看哪种纹理/颜色」，深层的在调「看哪种物体」。同一句话在不同深度需要不同的调制 —— 这也是为什么只加一次不够。
- **语言模型很小**：USE 是冻结的，只有两层线性把它接到每条通道上。整个 tokenizer 的语言理解能力，全部来自「512 维向量 + 26×2 组线性映射」。真正的语义容量在后面的 Transformer 里。
- **81 → 8 的压缩（TokenLearner）** 是为了延迟：Transformer 的注意力是 `O(tokens²)`，81×6 = 486 个 token 太贵；压到 48 个才能跑到 3Hz。

## 8. 这套做法的边界

**能做的**：让编码器「偏置」到当前任务相关的特征子空间。便宜、稳、易插。

**做不到的**：

1. **空间定位** —— 整张图共用一组 `γ,β`，说不清「左边那个」。
2. **组合性** —— 「把红杯子放到蓝碗左边」需要两个物体之间的关系，一个全局向量表达不了。
3. **指代消解** —— 图里有两个杯子时，「那个杯子」指向谁，FiLM 没有机制去比对。

**替代/补充方案**：
- **cross-attention**：把语言 token 和视觉 token 放在一起做注意力。能空间定位、能组合，代价是 FLOPs（上面那 1024 倍）以及需要更多数据才训得动。
- **两者并用**：RT-2 / OpenVLA 这类做法是让 VLM 直接输出视觉 token，语言和视觉在同一套注意力里 —— 相当于放弃了「轻量编码器」这条路，换通用性。

**一句话总结这个取舍**：RT-1 只有 16M 的 tokenizer 预算、要跑 3Hz，所以选 FiLM；你要做「抓桌上的红色积木」这类需要空间精度的任务，FiLM 会不够。

## 9. 和 BatchNorm 的关系（这条能让整章落地）

你在 Day 22 手写过 BN，它的式子是这个：

```
BN(x) = γ · (x − μ)/σ + β
```

**和 FiLM 长得几乎一样**，都是逐通道仿射。区别只有一处，而且是本质的一处：

|  | BN 的 `γ, β` | FiLM 的 `γ, β` |
|---|---|---|
| 从哪来 | **梯度学出来的固定参数** | **由输入 `z` 实时算出来的** |
| 训练完 | 冻结 | 每帧都不同 |
| 作用 | 把激活拉回标准尺度 | 按任务挑选通道 |

BN 的 `γ,β` 是**统计校正**；FiLM 的 `γ,β` 是**任务条件**。同样的算子形状，完全不同的用途。

同时注意两者的共同前提：**都假设「通道」是有意义的单位**。BN 逐通道统计，FiLM 逐通道调制，SE 逐通道加权 —— 整个 CNN 生态都建立在这个假设上。
