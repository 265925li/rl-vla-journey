# Day 25 · BatchNorm：第一个有两套前向的算子

> 前四天的算子（SGD / CrossEntropy / Linear / Conv2d）都是"一个公式，一种算法"。
> 今天这个不是。**BatchNorm 的前向有两套完全不同的计算，而且必须分。**
> 这一条决定了今天所有的坑从哪来。

---

## 一、为什么是今天讲

不是"轮到它了"。是 Day 24 跑出的一组数字，直接指向它：

| 组别 | 最低 `val_loss` 出现在 | 15 轮 → 25 轮 test acc |
|---|---|---|
| baseline | **ep7**（25 轮里都是 ep7） | 0.9900 → **0.9900**（白跑） |
| aug3（增强） | **ep20** | 0.9915 → **0.9936** |

baseline 多跑 15 轮，精度一位没变；`train_acc` 从 ep21 起就是 `1.0000`。

**结论：当前的瓶颈不是精度，是「收敛得太早」**。而 BN 恰好就是治这个的。

它和 Day 23/24 的增强是一对：

```
增强    把输入分布**搞得更散**   → 模型更难靠记住 54000 张图过关
BN      把中间层分布**重新收紧** → 每层输入始终均值 0 方差 1
```

一个往外推，一个往回拉，方向不冲突。

同时也补上 P0 复盘 §四 挂的第二笔账（「知道 `eval()` 会切换行为，没实现过」）。

## 二、BN 到底在做什么

### 2.1 它要解决的问题

第 3 层的输入分布，取决于第 1、2 层的参数。而那两层一直在变。

于是第 3 层的梯度目标一直在移动 —— 它刚学会"在这种分布下该怎么调"，分布就变了。
后果很直接：**学习率不敢开大，收敛慢**。

BN 的做法：在每层输入处插一道"重新标准化"，让第 3 层永远收到均值 0 方差 1 的东西，
不管前两层怎么变。

### 2.2 但它不是"限制输出"

标准化之后立刻跟一个**可学习的**仿射变换：

```
y = γ · x̂ + β
```

如果"均值 0 方差 1"不是最优的，`γ` 和 `β` 会把分布重新拉回去。

所以 BN 的真实作用是「**改变参数化的形状，让优化更容易**」，
不是「限制输出范围」。这是理解 BN 的分水岭：

| 说法 | 对错 | 为什么 |
|---|---|---|
| BN 是正则化，降低表达能力 | ❌ | `γ`/`β` 能还原任意分布，表达能力不减 |
| BN 是重参数化，优化景观更平滑 | ✅ | 同一族函数，换了参数化方式 |

**一个可以检验的推论**：如果 BN 只是"限制输出"，那加了 BN 必然掉精度。
但实测（见 §六）它不掉。这只能用"更好优化"解释。

### 2.3 数学（训练态）

对**每个通道** `c` 独立做，输入形状 `(N, C, H, W)`：

```
m   = N · H · W                  一个通道里有 m 个数
μ_c = (1/m) Σ x                  批内均值
σ²_c= (1/m) Σ (x − μ_c)²         批内方差，**除以 m 不是 m−1**
x̂   = (x − μ_c) / √(σ²_c + ε)
y   = γ_c · x̂ + β_c
```

三个容易写错的地方：

**① 求和维度是 `(0,2,3)`，保留通道维**

写成 `x.mean()` 会把 `N,C,H,W` 全平均 → 所有通道用同一个均值。
**不报错**，只是每个通道的标准化都做错了。

**② 方差除以 `m`，不是 `m−1`**

统计学里样本方差常用 `m−1`（贝塞尔校正）。但 PyTorch 的 BN 用 **biased** 版本。
两者差一个 `m/(m−1)` 的因子 —— `m=128` 时差 0.8%。
训练照样跑，但和官方实现对不上，也偏离论文。

**③ `ε` 加在方差上**

`1/√(σ²+ε)`，不是 `1/√σ² + ε`，也不是 `1/(√σ²+ε)`。
目的只有一个：`σ²=0` 时不除零。`ε=1e-5` 时分母至少是 `3.16e-3`。

### 2.4 为什么要 `γ`/`β`

如果不加，BN 就强制每层输出都是标准正态。这会损失表达能力 ——
有些层确实需要表达"均值偏移"。

`γ` 初始化为 **1**、`β` 初始化为 **0**，于是 BN 一开始等价于纯标准化。

> ⚠️ 如果 `γ` 初始成 0：整个通道输出恒为 `β`，
> 梯度对 `x` 也是 0，这层永远学不动。和 Day 10 的"全零初始化"是同一类问题。

## 三、核心：两套完全不同的计算

这是今天和 P0 所有手写算子的根本区别。

```
┌── 训练态 training=True ────────────────────────────────────┐
│ 用**当前这一批**数据算 μ、σ²，然后标准化                    │
│ 同时把这对统计量按滑动平均**存下来**（running stats）        │
│ 输出的每个值都依赖同批其它样本 —— **批内耦合**               │
└────────────────────────────────────────────────────────────┘

┌── 推理态 training=False ──────────────────────────────────┐
│ 用存下来的 running stats，**完全不看当前批**                │
│ 输出对每个样本独立 —— 和 Linear / Conv 一样是逐点运算        │
└────────────────────────────────────────────────────────────┘
```

### 3.1 为什么推理不能用当前批

**语义上**：一张图进来就该得到一个确定的答案，不能因为"和它一起送进来的
另外 99 张不同"而改变。

**工程上**：线上服务经常一次只来一张。这时若用批内统计量，后果见 §七 的坑 1。

### 3.2 为什么训练不能用 running stats

`running_mean=0`、`running_var=1` 是初始值，等于什么都没做。
而且它是"逐渐逼近"的（见 §五 关 6：跑 5 步才到目标的 41%），
训练早期用它标准化，等于用错误的分母，梯度方向会系统性偏掉。

### 3.3 两种状态的切换是**模块级**的

```python
model.train()   # 之后所有 BN 层走训练态
model.eval()    # 之后所有 BN 层走推理态
```

不是某一层的属性，是整棵树的递归设置。
`trainer.py` 里的 `evaluate` 必须保证前后状态对称 —— 这个 P0 就做对了，
今天正好用上。

## 四、手写反向：三项公式

### 4.1 为什么这是今天最难的地方

前两个手写算子只有一条路径：`x_i` 直接影响 `y_i`。
BN 不是 —— **`x` 的每个元素通过三条路径影响输出**：

```
路径 1  直接：x̂_i 依赖 x_i
路径 2  通过均值 μ：μ 依赖**所有** x_j
路径 3  通过方差 σ²：σ² 依赖**所有** x_j
```

路径 2、3 是 BN 特有的，也是最容易漏掉的。

### 4.2 推导

记号：`m = N·H·W`，Σ 表示对该通道所有元素求和。

`x̂_i = (x_i − μ)/σ`，其中 `μ`、`σ` 都依赖全部 `x_j`。所以

```
dx_i = Σ_j (∂L/∂x̂_j)·(∂x̂_j/∂x_i)                    ← 直接项
     + Σ_j (∂L/∂x̂_j)·(∂x̂_j/∂μ)·(∂μ/∂x_i)            ← 均值项
     + Σ_j (∂L/∂x̂_j)·(∂x̂_j/∂σ)·(∂σ/∂x_i)            ← 方差项
```

五个偏导（都很简单，但符号最容易错）：

```
∂x̂_i/∂x_i = 1/σ
∂x̂_j/∂μ   = −1/σ
∂μ/∂x_i   = 1/m
∂x̂_j/∂σ   = −(x_j−μ)/σ²  = −x̂_j/σ
∂σ/∂x_i   = (x_i−μ)/(m·σ)        ← σ=√(σ²)，链式带 1/(2σ) 后化简
```

逐项算：

```
直接项 = dxhat_i / σ
均值项 = Σ_j dxhat_j · (−1/σ) · (1/m)
       = −(1/(m·σ))·Σ dxhat
方差项 = Σ_j dxhat_j · (−x̂_j/σ) · (x_i−μ)/(m·σ)
       = −(1/(m·σ))·x̂_i·Σ(dxhat_j·x̂_j)      ← 因为 (x_i−μ)/σ = x̂_i
```

合并（提出公因子 `1/(m·σ)`）：

```
dx_i = (1/(m·σ)) · [ m·dxhat_i − Σ dxhat − x̂_i·Σ(dxhat·x̂) ]
```

三项的经济含义：

| 项 | 含义 |
|---|---|
| `m·dxhat_i` | 这个元素自己**想往哪走** |
| `−Σ dxhat` | 整批的**平均走向**（因为 μ 被拉动了） |
| `−x̂_i·Σ(dxhat·x̂)` | 整批的**缩放走向**（因为 σ 被拉动了） |

代码就是 4 行：

```python
sum_dxhat = dxhat.sum(dim=(0, 2, 3), keepdim=True)
sum_dxhat_xhat = (dxhat * x_hat).sum(dim=(0, 2, 3), keepdim=True)
dx = inv_std / m * (m * dxhat - sum_dxhat - x_hat * sum_dxhat_xhat)
```

### 4.3 一个必须自己验的性质

把 `dx` 对该通道求和：

```
Σ dx = (1/(mσ))·[ m·Σdxhat − m·Σdxhat − Σx̂·Σ(dxhat·x̂) ]
     = 0                                    ← 因为 Σx̂ = 0
```

**恒为 0，且不依赖任何假设。** 这是关 2 的核心断言。

它的物理含义：BN 的输出对整批做**平移不变** ——
把 x 整体加一个常数，`x̂` 完全不变，所以梯度之和必须是 0。

如果只写第一项 `inv_std·dxhat`，这个和会立刻不成立。

## 五、七关

`src/utils/batchnorm.py --train`

### 关 1 · 训练态前向 vs `F.batch_norm`

```
y     最大差  2.66e-15
mean  最大差  0.00e+00     （自己算 vs x.mean）
var   最大差  3.55e-15     （自己算 vs x.var(unbiased=False)）
纯标准化后：|均值| 最大 2.43e-16，|方差−1| 最大 2.65e-06
```

最后一行值得注意：**纯标准化后方差不是 1，而是略小于 1**，差 `ε` 的量级。
因为 `x̂ = (x−μ)/√(σ²+ε)`，分母比 `σ` 大一点点。
`2.65e-06` 正好是 `ε/(σ²+ε)` 在这个数据尺度下的值 —— 这验证了 `ε` 加对了位置。

### 关 2 · 三个梯度逐个对拍

```
∂L/∂x   最大差  6.66e-16
∂L/∂γ   最大差  7.11e-15
∂L/∂β   最大差  7.11e-15

Σ(∂L/∂x)               1.55e-15     （应为 0）
Σ(∂L/∂x·x̂)  ε=0        2.00e-15     （应为 0）
Σ(∂L/∂x·x̂)  ε=1e-5     1.62e-05     （**不**为 0）
```

最后两行是今天最值得看的地方，见 §八 错误 1 ——
**我的第一版把这两行断言成同一个值，失败了。**

### 关 3 · gradcheck + gradgradcheck

一阶二阶都过。

它证明的是"forward 只存了 `x`，没存中间量"：
如果存了 `x̂`/`inv_std`，一阶照样过，**二阶会全 0 而且不报错**
（Day 16 的坑，Day 22 的 conv 也踩过，今天原样避开）。

### 关 4 · 训练态 vs 推理态（必须不同）

这一关的断言方向**和别处相反**：别处都要求"两个结果一样"，这里要求"**不一样**"。

```
同一批数据，两种模式的最大差   27.0442
训练态输出均值  −0.0500    （≈0，按批标准化了）
推理态输出均值  +7.5291    （≈7，因为 running_mean 还是 0）
推理态连跑 5 次，running stats 变了吗：没变 ✓
num_batches_tracked = 1（只在训练态 +1）
推理态两次结果逐位相同 ✓
```

"一样"才是 bug —— 说明只实现了一套计算，另一套是复制过去的。

### 关 5 · running stats 手算 3 步

```
  步      手算 running_mean        实际        差
   1        0.2000000000    0.2000000000    0.00e+00
   2        0.5800000000    0.5800000000    0.00e+00
   3        1.1220000000    1.1220000000    0.00e+00
```

手算部分是**写死在代码里**的（`rm = 0.9*rm + 0.1*batch_mean`），
不是调用同一个公式 —— 否则就是自己证明自己。

注意这三个数永远追不上真值（2 → 4 → 6），**这就是滑动平均和"平均值"的区别：
它是个低通滤波器。**

### 关 6 · `momentum` 的语义

```
初始 running_mean = 0，批均值 = 10，momentum = 0.1
一步后 running_mean = 1.000000

  若理解成『新值占 10%』→ 0.9·0 + 0.1·10 = 1.0   ← 实测
  若理解成『新值占 90%』→ 0.1·0 + 0.9·10 = 9.0
```

连续 5 步（批均值都是 10）：

| 步 | 实测 | `1−0.9^k` × 10 |
|---|---|---|
| 1 | 1.000000 | 1.000000 |
| 2 | 1.900000 | 1.900000 |
| 3 | 2.710000 | 2.710000 |
| 4 | 3.439000 | 3.439000 |
| 5 | 4.095100 | 4.095100 |

**第 5 步才到 4.10，离 10 还差 59%。** 所以 `momentum=0.1` 的记忆长度约 `1/0.1 = 10` 批。

对照：`momentum=1.0` → 一步就到 10.0（完全丢弃历史）。

> ⚠️ 这和很多教科书写法**相反**。教材常用 `ρ` 表示"保留旧值的比例"，
> 写成 `new = ρ·old + (1−ρ)·batch`。PyTorch 的 `momentum` 是"**新值的权重**"。
> 两种理解都不报错，数值差 9 倍。

### 关 7 · conv 的 bias 在 BN 前失效

```
conv(bias=True)  → BN
conv(bias=False) → BN
最大差  1.78e-15

对照（不接 BN）：最大差 3.0000 ≈ bias 本身的大小

参数账：conv(bias=True) 40 vs conv(bias=False) 36，省 4 个（= C_out）
```

**bias 加的是逐通道常数，而 BN 减的正是逐通道均值 —— 常数被原样减掉。**
方差又不受常数平移影响。所以 bias 根本传不到输出。

推论：`conv + BN` 时应该写 `bias=False`。这不是省参数的小事 ——
留着的话会在 `state_dict` 里留下一批**永远收不到有效梯度的死参数**。

## 六、剂量扫描（5 组 × 25 轮）

### 6.1 设计

**为什么必须扫 lr**：BN 的经典卖点是"允许更大学习率"。
如果只测「加 BN / 不加 BN」一个点，等于默认 BN 和 lr 无关 ——
而 Day 15 的教训正是「参数之间不独立，单点结论会反」。

| 组 | lr | BN | 目的 |
|---|---|---|---|
| A | 0.05 | 无 | 基线（= Day 24 的 aug3） |
| B | 0.05 | 官方 | BN 本身的效果 |
| C | 0.1 | 无 | 大 lr 无 BN（对照组） |
| D | 0.1 | 官方 | **BN 的卖点**：大 lr 下能不能稳住 |
| E | 0.05 | 手写 | 手写实现能不能真的训练 |

其余配置全部相同（增强 ±2px/±10°、batch 128、SGD momentum 0.9、25 轮、**早停关闭**）。
早停关掉是因为它截断曲线，不同组停在不同轮，比较就不公平。

### 6.2 结果

| 组 | test acc | best val acc | 最低 val_loss | `@ep`(loss) | 末 `train_acc` | 末 `gap` | `wnorm` |
|---|---|---|---|---|---|---|---|
| A 无BN lr.05 | **0.9936** | 0.9933 | 0.0232 | 20 | 0.9936 | +0.27 | 23.84 |
| B 官方BN lr.05 | 0.9917 | 0.9933 | **0.0211** | **25** | 0.9940 | **+0.06** | 21.85 |
| C 无BN lr.10 | 0.9916 | 0.9932 | 0.0301 | 25 | 0.9920 | −0.12 | 35.19 |
| D 官方BN lr.10 | 0.9930 | 0.9932 | 0.0231 | 25 | 0.9926 | −0.06 | 35.57 |

### 6.3 精度：**全部测不出差异**

| 对比 | 差值 | `SE_diff` | t | 判定 |
|---|---|---|---|---|
| A vs B（BN @lr.05） | +0.19pt | 0.121pt | 1.57 | 不显著 |
| C vs D（BN @lr.10） | −0.14pt | 0.124pt | 1.13 | 不显著 |

而且四组的 `best val_acc` 是 **0.9933 / 0.9933 / 0.9932 / 0.9932** —— 几乎完全相同。

> **这是今天最重要的诚实结论：在 MNIST 这个已经饱和的任务上，
> "加 BN 能提分"测不出来。** 五组 test acc 的极差只有 0.25pt，
> 而单个比例的标准误就有 0.11pt。

如果只看这一张表，结论会是"BN 没什么用"。

### 6.4 真正显著的地方：收敛速度

| 组 | ep1 `val_loss` | ep1 `val_acc` | 达到 `val_acc≥0.985` 需几轮 |
|---|---|---|---|
| A 无BN lr.05 | 0.1004 | 0.9700 | **4** |
| B 官方BN lr.05 | **0.0590** | **0.9822** | **2** |
| C 无BN lr.10 | 0.0923 | 0.9735 | 3 |
| D 官方BN lr.10 | 0.0755 | 0.9770 | 2 |

**第 1 轮的 `val_loss` 就差 41%（0.1004 → 0.0590），`val_acc` 差 1.22pt。**
到达 0.985 的轮数从 4 减到 2。

这才是 BN 的真实作用 —— 和 §二 的理论对得上：
它让每层不用追着上一层漂移的分布去适应，所以**起步就快**。

> 这和 Day 23/24 的增强形成完全对称的两条结论：
>
> | 手段 | 提高上限？ | 加快收敛？ | 抑制过拟合？ |
> |---|---|---|---|
> | 数据增强 | 否 | 否（更慢） | **是**（窗口 7→20 轮） |
> | BatchNorm | 否 | **是**（4→2 轮） | **是**（gap +0.27→+0.06） |
>
> 两者都**不提精度上限**，但都在别的维度上有明显效果。
> 只看 acc 的话，两个结论都会被判成"没用"。

### 6.5 过拟合也被抑制了

末轮 `gap`：A `+0.27pt` → B `+0.06pt`（收窄 78%）。
最低 `val_loss`：0.0232 → **0.0211**（−9%）。

方向和 Day 23 的增强一致：BN 也有正则化效果（因为每批的统计量不同，
相当于往输入里注入了噪声）。

### 6.6 BN 和 lr 有交互，不能单点测

| | 无 BN | 有 BN | BN 的效果 |
|---|---|---|---|
| lr=0.05 | 0.9936 | 0.9917 | **−0.19pt** |
| lr=0.10 | 0.9916 | 0.9930 | **+0.14pt** |

**方向反了。**

怎么解释：BN 使梯度对参数的尺度不敏感，**有效步长变大**。
所以同一个 `lr`，对加了 BN 的网络来说"相对更快"。
`lr=0.05` 时 BN 已经"够快"甚至"过快"，收益被吃掉；
`lr=0.1` 时无 BN 明显吃力（末 `train_acc` 只有 0.9920，`gap` 变成 −0.12 的欠拟合侧），
BN 才显出价值。

两处差距各自都不到 2 SE，所以**不能据此说"BN 在 lr=0.1 下更好"**。
能说的是：**BN 的效果依赖 lr，这是必须一起扫的原因。**

### 6.7 ⚠️ 25 轮对 BN 组不够

四组里 **B、C、D 的 `@ep` 全是 25**（`val_loss` 最低点在最后一轮）。

按 Day 24 刚立下的判据：**`@ep` 落在最后一轮 = 曲线还在降 = 这个轮数下的对比没有意义。**

所以 §6.3 那个"不显著"要读成：**"在 25 轮内、这个 lr 下，测不出差异"**，
而不是"BN 没有用"。要回答后者，BN 组得跑到 40 轮以上。

这一条是 Day 24 教训的**第一次主动应用**：不是事后发现没跑够，
而是在看结果的当下就认出"这个轮数不够"。

### 6.8 手写 BN 能不能训练

能。`test acc 0.9941`、`best val acc 0.9940`，是五组里最高的。

但**不能因此说"手写 BN 更好"**：

| 对比 | test acc | 差值 | t |
|---|---|---|---|
| 官方BN lr.05 | 0.9917 | — | — |
| 手写BN lr.05 | 0.9941 | **+0.24pt** | **2.02** |

两者是同一个算法（七关对拍 `2.66e-15`），差 2 个标准误只能是浮点分叉。

逐轮 `val_loss` 从**第 1 轮**就分叉了：

| ep | 官方 BN | 手写 BN | 差 |
|---|---|---|---|
| 1 | 0.058966 | 0.068069 | 9.10e-03 |
| 4 | 0.033879 | 0.035960 | 2.08e-03 |
| 8 | 0.030180 | 0.026170 | 4.01e-03 |
| 16 | 0.036291 | 0.028003 | 8.29e-03 |
| 24 | 0.027265 | 0.022907 | 4.36e-03 |

探针测出来：单步相对差 `1e-7`（float32 的精度极限），422 步后放大到 ep1 的 15%。

> **这是今天最该带走的一条元结论：**
>
> 在这个任务上，**换一个实现（算法完全相同、单步差 1e-15 级）
> 就能让 25 轮后的 test acc 差 0.24pt = 2.0 个标准误。**
>
> 也就是说，**0.2pt 以内的"显著/不显著"判断本来就很脆弱。**
> 回过头看：
>
> | 结论 | 差值 | t | 在实现噪声（2.0 SE）之下吗 |
> |---|---|---|---|
> | Day 23 增强（15 轮） | 0.15pt | 1.11 | 是 → 当时判"不显著"是对的 |
> | Day 24 增强（25 轮） | 0.36pt | 2.82 | **否** → 这个结论站得住 |
> | Day 25 BN（lr.05） | 0.19pt | 1.57 | 是 |
> | Day 25 BN（lr.10） | 0.14pt | 1.13 | 是 |
>
> 这不是说前面的结论都错了，而是说：**要下"某手段有效"的结论，
> 效应量得明显大于 2 SE。** 0.3pt 是这条线附近的值。
>
> 真正的解法是多 seed（3–5 个）比较均值，而不是单 seed 比 test acc。
> 这件事记进了欠账。

## 六·补、一个被训练结果揪出来的真 bug

### 事情经过

五组跑完后，`官方BN lr.05` 是 0.9917、`手写BN lr.05` 是 0.9941，
差 **0.24pt = 2.02 个标准误**。

这不该发生：七关对拍里两者只差 `2.66e-15`，是同一个算法。
差 2 个 SE 说明要么手写实现有 bug，要么浮点分叉比我以为的大得多。

写了一个探针去查（`_probe_bn.py`），结果两者都有 —— 先查出了 bug。

### Bug：`running_var` 存的是 **unbiased** 方差

```
官方 running_var  vs biased     差 1.683e-03
官方 running_var  vs unbiased   差 4.441e-16   ← 官方用 unbiased
手写 running_var  vs biased     差 2.220e-16   ← 我用了 biased
```

**同一个 BN 层里有两个方差**：

| 用途 | 公式 | 除以 |
|---|---|---|
| 标准化时的分母 | `σ²_biased = (1/m)Σ(x−μ)²` | `m` |
| 存进 `running_var` 的 | `σ²_unbiased = (1/(m−1))Σ(x−μ)²` | `m−1` |

差一个 `m/(m−1)` 的因子。

为什么这么设计（合理的部分）：`running_var` 是给推理用的，那时代替的是"总体方差"，
总体方差的无偏估计该用 `m−1`。而训练时标准化用的是"这一批的描述性统计量"，
除以 `m` 才是定义。

**为什么容易错**：两者都对，但用错地方**不报错**。后果是推理时分母系统性偏小：

| `m` | 相对偏差 `1/(m−1)` | 影响 |
|---|---|---|
| 6272（128×7×7） | 0.016% | 几乎看不出来 |
| 128（MLP 一层） | 0.8% | 已经能影响结论 |

修完之后：与 `nn.BatchNorm2d` 的直接差 **`0.00e+00`**。

### 为什么七关没抓到它

**因为关 5 用常数批验证**：

```python
batches = [torch.full((2, 1, 3, 3), v) for v in (2.0, 4.0, 6.0)]
```

常数批的方差**恒为 0**，除以 `m` 和除以 `m−1` 都是 0 —— 两种写法结果完全一样。
七关全过，bug 完好无损地活着。

> **教训：关卡用特殊数据（常数、全零、单位阵）时，
> 它测不到的性质会被悄悄放过。**
> 特殊数据验"简单性质"很好用（关 5 验 momentum 语义就是靠常数批），
> 但它**不能代替**"随机数据 + 对拍官方实现"。

修法不是删掉关 5，而是**补一段随机数据的检查**：
用 `m=18` 的随机批，同时算出 biased 和 unbiased 的期望值，看实测落在哪边，
再直接和 `nn.BatchNorm2d` 比一次。

### 另一个发现：分叉的机制

探针顺带量化了"同 seed、同配置，换实现"的分叉速度：

```
初始 state_dict 逐位相同：True
同一批前向：       2.72e-07   （相对 4.01e-07）
一步反向：         1.04e-07   （相对 1.16e-07）
一步更新后：       3.89e-05   （在 bn2.running_var ← 就是那个 bug）
20 步后参数最大差：3.62e-04
```

单步是 `1e-7` 的相对差异，422 步后累积成 ep1 的 `val_loss` 差 0.009。

**这就是 Day 16 那条结论的第三次复现**：
「两实现完全一致」应该读成「**单步一致、多步分叉、终值差远小于统计噪声**」。

## 七、四个坑

### 坑 1 · 忘了 `model.eval()` —— 不报错，但结果全错

训练完直接评估，走的是训练态逻辑（用当前批统计量）：

| `batch_size` | 后果 |
|---|---|
| 128 | 每批的均值方差都不同 → 同一个模型两次评估差好几个百分点 |
| 1 | 见坑 4：统计量只有 `H×W` 个样本，估计很糙 |

你会看到"模型训崩了"，然后去调学习率 —— 真正原因是 4 个字符没写。

关 4 专门验这条：推理态连跑 5 次 `running stats` 不变、两次结果**逐位相同**。
如果它变了，说明 `forward` 里忘了判断 `self.training`。

### 坑 2 · `running_var` 存的是 **unbiased** 方差

这是今天真正抓到的 bug，比参数量的坑隐蔽得多。**同一个 BN 层里有两个方差**：

| 用途 | 公式 | 除以 |
|---|---|---|
| 标准化时的分母 | `σ²_biased = (1/m)Σ(x−μ)²` | `m` |
| 存进 `running_var` 的 | `σ²_unbiased = (1/(m−1))Σ(x−μ)²` | `m−1` |

差一个 `m/(m−1)` 的因子。两者都对，但**用错地方不报错**：

| `m` | 相对偏差 `1/(m−1)` | 后果 |
|---|---|---|
| 6272（128×7×7） | 0.016% | 看不出来 |
| 128（MLP 一层） | 0.8% | 已经能影响结论 |

我第一版用了 biased，七关全过 —— 因为关 5 用常数批，常数批方差恒为 0，
除以 `m` 和 `m−1` 都是 0。修完后与 `nn.BatchNorm2d` 差 `0.00e+00`。
完整经过见 §六·补。

### 坑 3 · 参数量手算会错两处，而且方向相反

加 BN 后 `expected_params_cnn` 要改两个地方：

| | 变化 | 为什么 |
|---|---|---|
| conv 的 bias | `+1` → `0` | 被 BN 抵消（关 7 实测 1.8e-15） |
| BN 自己的参数 | `0` → `2·C` | `γ` 和 `β` 各 `C` 个 |

净效果 **+48**（`c1+c2 = 48` 个 bias 被 `2×(16+32) = 96` 个 `γ/β` 顶掉，还多 48）。

实测对账：

| `bn` | 程序 | 手算 |
|---|---|---|
| `none` | 206,922 | 206,922 ✓ |
| `torch` | 206,970 | 206,970 ✓ |
| `my` | 206,970 | 206,970 ✓ |

> 注意方向：**BN 是"多花一点参数换优化性质"，不是省参数。**
> 这和直觉相反 —— 关 7 证明了 bias 无用，容易顺口说成"加 BN 省参数"，
> 但 `γ/β` 比省下的 bias 还多。

### 坑 4 · `momentum` 语义反了

见 §五 关 6。`momentum=0.1` 是"记住 90% 历史"。

### 坑 5 · `batch_size=1` 一定会崩吗？—— **不一定**

> ⚠️ 这条我自己原先讲错了，是关 4 的实测否掉的。

我原来的说法是"`batch_size=1` 时批内方差为 0，BN 直接崩"。实测差得远：

```
batch_size=1、图 5×5：每通道元素数 m = 25，方差 = 9.272
→ **不崩**。它会正常输出，只是统计量只有 25 个样本。
  方差的相对标准误约 √(2/m) = 28% —— 估计很糙，running stats 会抖。
```

**错在哪儿**：BN2d 的"批"是 `N×H×W` 个元素，不是 `N` 个元素。
`batch_size=1` 时仍有 `H×W` 个数，方差当然不为 0。

真正让方差为 0 的是 `m = N·H·W = 1`：

```
m = 1 时（1×1 特征图）：方差真的为 0
输出 = [0.0, 0.0, 0.0, 0.0]     ← 恒等于 β
β    = [0.0, 0.0, 0.0, 0.0]
x̂ = (x−μ)/√(0+eps) = 0 → 输出恒等于 β，信息全丢但**不报错**
```

这在 CNN 里少见（除非特征图已经池到 1×1），但在
**BatchNorm1d 作用在 `(N,C)` 上**时是常态 —— MLP 最后一层、
RL 里 `(batch, action_dim)` 的输入，`batch_size=1` 时 `m` 恰好等于 1。

这才是小 batch 场景（GAN、检测）改用 InstanceNorm / GroupNorm / LayerNorm 的
真实原因：**它们不跨样本求统计量**。

## 八、我自己犯的错（今天六个）

### 1. 把"数学性质"当成了"实现要求"，忘了 `ε`

关 2 我断言 `Σ(dx·x̂) = 0`，用 `ε=1e-5` 的数据，实测 `1.62e-05`，挂了。
但三个梯度都是 `1e-16` 量级 —— **实现是对的，错的是我的性质**。

推导漏了一步：`x̂` 的方差**不是恰好 1**，是 `σ²/(σ²+ε)`
（因为分母用的是加了 `ε` 的 `σ`）。所以

```
Σ(dx·x̂) = (Σ(dxhat·x̂)/σ)·ε/(σ²+ε)
```

它**正比于 `ε`**，不是 0。实测 `1.62e-05`，理论因子 `ε/(σ²+ε) ≈ 2.35e-06`，量级对上。

修法不是"把阈值放宽"，是**把 `ε` 关掉验严格性质，再单独验 `ε` 的残差量级**：

```
Σ(∂L/∂x·x̂)  ε=0        2.00e-15     ← 严格为 0
Σ(∂L/∂x·x̂)  ε=1e-5     1.62e-05     ← 正比于 ε，不是 0
```

> **教训**：「我的数学推导」和「实现」是两份独立的东西。
> 断言挂了要先怀疑哪一份，不要默认是实现错了。

### 2 和 3. 容差卡在了被测精度的边界上

关 5 差 `2.1e-08`、关 7 差 `1.19e-06`，两个都刚好卡在我设的阈值上。

原因：手算期望值用的是 Python `float`（float64），实现跑的是 float32。
float32 的相对精度 `1e-7`，在数值 0.5 上就是 `1e-8` 的绝对误差。

**这不是 bug，是精度差异。但阈值卡在那里，关卡会随环境误报。**

修法：统一到 **float64**，阈值才能收到 `1e-12`。

关 7 改完之后：`1.19e-06` → **`1.78e-15`**。误差小 9 个数量级，
这才是"精确抵消"，而不是"差不多抵消"。

> **规律：容差必须和被测算子的精度匹配。**
> 用 float32 跑却断言 `1e-9`，等于在噪声里找信号。

### 4. 打错变量名，看起来像公式错了

```python
bn_hi = MyBatchNorm2d(1, momentum=1.0)
bn(x)          # ← 应该是 bn_hi(x)
```

`bn_hi` 的 `running_mean` 一次都没更新，打印出来 `0.0000`。
**看起来完全像"`momentum=1.0` 的公式反了"**，实际只是漏了个下标。

差了一个数量级以上才暴露 —— 如果 `momentum=1.0` 本来就该得到接近 0 的值，
这个 bug 会一直藏着。

### 5. 我的"三个问题"里有一个预设了错误答案

文件头我写了「为什么 `batch_size=1` 时 BN 会崩」，这个提问本身预设了"一定会崩"。
关 4 的实测把它推翻了（见 §七 坑 4）。

**提问的方式会限制答案的范围。** 改成「`batch_size=1` 一定会让 BN 崩吗？
条件换成什么才会真的崩？」之后，才容得下正确的答案。

### 6. 真 bug：`running_var` 用了 biased 方差

前五个错都在"验证"环节，这个是**实现**环节的真错误。

它活过了七关，因为关 5 用常数批（方差恒为 0，两种写法等价）。
最后是**真实训练的结果**揪出来的 —— 手写 BN 与官方 BN 差 2 个标准误，
不合理，写探针才查到（完整经过见 §六·补）。

> **这是今天最有价值的一条方法论**：
> 七关能证明的东西是有边界的。它们证明"在我设计的这些输入上，
> 两个实现一致"。**它们不能证明"在所有输入上一致"。**
>
> 所以真实训练不是"关卡之后的例行公事" —— 它本身是一道关卡，
> 而且是唯一一道用**真实分布**做输入的关卡。
> 今天如果没有跑那 5 组 25 轮，这个 bug 会一直躺在代码里。
