W5 前四天都在**解**一个 MDP：给定 `P` 和 `R`，求 `V*`。


答案不好听：凭你写的代码。而代码会错。

## 一、五元组里，只有两个东西需要「造」

```
(S, A, P, R, γ)
 ↑  ↑  ↑  ↑  ↑
 │  │  │  │  └─ 一个数，随手定（Day 29 说过它是杠杆）
 │  │  │  └──── 要造  ← 今天的主角
 │  │  └─────── 要造  ← 今天的主角
 │  └────────── 列出来就有（上/下/左/右）
 └───────────── 说「格子坐标」，你就信了 ← 今天最后要审的就是它
```

有意思的是，最难的两个（`S` 和 `P`）恰恰是最容易被当成「显然」的两个。
`A` 和 `γ` 你会认真想，`S` 你从来不想。

今天要证明的是：**这两个「显然」的东西，错起来是最贵的**，因为错了之后
**下游一切照常运行**。

## 二、`P` 是手写的：先看一个格子的一行

环境：5×5，起点随便，终点 `(0,4)`，陷阱 `(3,1)`，四动作，撞墙**留在原地**，
每走一步 `−0.04`，进终点 `+1`，进陷阱 `−1`，`γ = 0.9`。

`P` 的形状是 `(25, 4, 25)` —— **100 个 (s,a) 组合，每个组合是一行 25 个概率**。

### 2.1 手算两行

**角落 `(0,0)`**（状态 0）：

| 动作 | 去哪 | 概率 |
|---|---|---|
| 上 | (0,0) 自己 | 1 |
| 下 | (1,0) | 1 |
| 左 | (0,0) 自己 | 1 |
| 右 | (0,1) | 1 |

**非角落 `(1,1)`**（状态 6）：

| 动作 | 去哪 | 概率 |
|---|---|---|
| 上 | (0,1) | 1 |
| 下 | (2,1) | 1 |
| 左 | (1,0) | 1 |
| 右 | (1,2) | 1 |

脚本跑出来逐位一致。

**这两行都是手算的，一共 8 个数。你应该现在就在纸上写一遍**，
因为下面所有关于「写错」的讨论，都建立在你先知道「写对长什么样」之上。

### 2.2 「撞墙留在原地」是一个设计决策，不是一个细节

角落的「上」指向**自己**。这句话背后有一个选择：

| 选择 | `P[(0,0), 上]` | 后果 |
|---|---|---|
| 撞墙留在原地 | 自己 : 1 | 角落变成一个有自环的状态 |
| 撞墙随机滑开 | 下 : 0.5，右 : 0.5 | 角落没有自环，但动作语义变了 |
| 撞墙不动但**不算一步** | 自己 : 1，但 `R` 不给惩罚 | 智能体会疯狂撞墙来逃避 `−0.04` |

三种都有人用。**差别不在数学，在你想让智能体学什么。**

第三条是真实存在的坑：只要「撞墙」比「走路」便宜，最优策略就是**一直撞墙**。
这不是算法的问题，是奖励设计的问题。你今天应该记住的操作习惯：
**凡是「什么都不做」的动作，都要检查它有没有比「做事」更划算。**

### 2.3 行和 = 1，是一行断言，也是 Day 32 的全部前提

脚本实测 100 个 `(s,a)` 的行和：**最小 1.000000000000000，最大 1.000000000000000，
与 1 的最大偏差 `0.000e+00`。**

这不是巧合，是 `_successors` 里那三个概率加起来等于 1 的直接结果
（有风时是 `(1−slip) + slip/2 + slip/2`）。

Day 32 说过，`T*` 是 γ-压缩的证明里，两条前提**各用一次**：

| 前提 | 用在哪 | 它保证了什么 |
|---|---|---|
| `P ≥ 0` | 引理 1（单调性） | 逐项比较后加权求和不会反向 |
| `P·1 = 1` | 引理 2（常数平移） | `T(V+c·1) = TV + γc·1` |

**`P·1 = 1` 就是行和 = 1**。所以那句话在工程上落地成：

```python
assert np.allclose(P.sum(axis=2), 1.0), "P 的行和不为 1"
```

一行。写在你自己的环境里。**不要写在训练脚本里** —— 训练脚本拿到 `P` 的时候，
它已经错了，那时候再检查只能告诉你「错了」，不能告诉你「哪一行错了」。

## 三、两种写错，都不报错

这是今天最重要的一节。脚本把两种真实会发生的错误注入进去，看后果。

### 3.1 丢概率：无风时**完全看不出来**

```python
# 直觉写法：撞墙就不加
if blocked:
    continue          # ← 少了「留在原地」
P[s, a, next_s] += p
```

后果：角落的「上」这一行**整行是 0**（行和 0.0000），概率凭空消失了。

你可能以为这会立刻炸。**实测 `max|ΔV| = 0.000000`。**

为什么？因为那一行全 0 意味着「选这个动作，什么都没有发生，也没有奖励」，
于是这个动作的价值极低，**最优策略根本不会选它**。错的那一行被策略绕开了。

> ⚠️ **这是最危险的一种错。**
> 端到端的测试 —— 跑一遍训练、看 loss 降没降、看成功率 —— **永远抓不到它**，
> 因为错误根本没进入最优路径。它只在某些初始状态、某些探索策略下才露头，
> 然后表现为「偶尔卡在墙角」。

### 3.2 同一个 bug，加上风就显形了

把风 `slip = 0.3` 打开（每个动作有 30% 滑向垂直方向），
**同样一行代码**，`max|ΔV|` 从 `0.000000` 变成 **`0.2686`**，行和最小 `0.1500`。

道理很直接：无风时「撞墙」是少数格子的事，有风时**每一步**都有概率撞墙，
那份丢掉的概率从「很少用到」变成「一直在漏」。错的东西被放大了，不是被修好了。

**这条值得单独记**：

```
一个 bug 显不显形，取决于环境和参数，不取决于代码本身。
所以「我改了一行，测试还是全过」不能推出「这行没改坏」。
```

### 3.3 双计：行和 2.0，压缩因子 1.8

真实场景：先特判撞墙、`+= 1.0`，然后**忘了 `return` / `continue`**，
又落进通用路径再 `+= 1.0` 一次。

```
行和最大 2.0000
压缩因子 γ · 2.0 = 1.8 > 1
```

值迭代在几十轮内溢出成 `inf`。

这就是 **Day 32 实验 B 的工程版本**。那里我们构造了一个 `P` 让行和偏到 `1+δ`，
δ=0.2 时因子 `0.9 × 1.2 = 1.08`，只偏 12% 就越界。这里直接偏了 100%，所以爆得很响。

> **偏一点点的时候不会爆。** 因子 1.08 时值迭代还是「在跑」，
> 只是每轮变化都不收敛，你会以为「再跑几轮就好了」，
> 而实际上它已经在指数发散了 —— 只是还没到 `inf`。

## 四、奖励不属于动作，属于**转移**

### 4.1 一个动作，三个后继，三种奖励

`slip = 0.3`，看状态 `(0,3)` 的动作「上」：

| 后继 | 概率 | 进这一格的奖励 |
|---|---|---|
| (0,2) | 0.15 | −0.04 |
| (0,3) | 0.70 | −0.04 |
| (0,4) **终点** | 0.15 | **+1.00** |

现在回答一个问题：**「上」这个动作的奖励是多少？**

没有答案。因为它取决于你落到哪。**所以 `R` 不能定义在 `(s,a)` 上。**

### 4.2 正确的写法：先有 `r(s,a,s')`，再压成 `R(s,a)`

```
r(s,a,s')  ←  奖励属于「这一条转移」
R(s,a) = Σ_s' P(s'|s,a) · r(s,a,s')   ←  期望，加权平均
```

**取期望，不是取最大，也不是取最可能那个。** 三个写法实测：

| 写法 | `R(0,3, 上)` | `Q(0,3, 上)` | `ΔQ = ΔR` |
|---|---|---|---|
| ✅ 期望 `Σ P · r` | **0.1160** | 0.784688 | 0 |
| ❌ 用最可能后继的 `r` | −0.0400 | 0.628688 | **−0.1560** |
| ❌ 用 `max r` | 1.0000 | 1.668688 | **+0.8840** |

（`Q` 统一用正确的 `V*` 算，这样差异**只来自 `R`**，不掺下游传播。所以 `ΔQ = ΔR` 是恒等式。）

**「用最可能后继」这一行最有代表性**：`(0,3)` 的「上」有 **70% 撞墙不动**，
所以「最可能后继」是「留在原地」，奖励 −0.04 ——
于是**那 15% 进终点拿 +1 的机会被完全抹掉**。

这不是精度问题，是**信息丢失**。而且它的症状很隐蔽：
策略看起来对，但总在终点前一步犹豫 —— 因为那一步的期望奖励被算成了负数。

`max r` 那一行必然偏大，理由和 Day 31 实验 A 一模一样：**挑最大只会高不会低**。

### 4.3 那到底要不要存成 `(nS, nA, nS)`？

不必。`R` 存成 `(nS, nA)` 是完全正确的 —— **只要那个数是期望值**，
而且你是「先把 `r(s,a,s')` 想清楚，再压成 `R`」，不是「直接猜一个 `R`」。

这个顺序不能反。反了的症状是：你写得出 `R`，但**说不清它为什么是这个数**。

## 五、坐标够不够？三种环境，三个答案

前面都在说「`P` 和 `R` 写对没有」。现在问更狠的一层：
**假设 `P` 和 `R` 一个字都没写错，`S` 选对了吗？**

### 5.1 确定性环境：坐标够

`slip = 0`，从 `(r,c)` 和动作 `a` 唯一确定下一格。状态 = 坐标，`nS = 25`。

### 5.2 有风：坐标还是够

`slip = 0.3`，下一格是随机的 —— 但**随机性是「无记忆」的**：
这一阵风吹你的概率，和你之前怎么走过来的无关。

所以「坐标 + 当前动作」已经决定了下一格的**分布**，马尔可夫性成立。**`nS` 还是 25。**

这里有个容易搞混的点：**随机 ≠ 非马尔可夫。** 风是随机的，但风不影响记忆。

### 5.3 有惯性：坐标不够了

现在让环境有记忆：上一步走的方向有 70% 的概率延续（像冰面）。

这一刻，「我在这格」不再足够 —— **同样的格子，上一步往左走和上一步往上走，
下一步的概率分布完全不同。**

实测（`nS = 25 × 4 = 100`）：

| 格子 | 上一步=上 | 上一步=下 | 上一步=左 | 上一步=右 | 差 |
|---|---|---|---|---|---|
| **(3,2)** | 0.512753 | 0.391357 | **−0.546174** | 0.512753 | **1.058927** |
| (2,1) | 0.512753 | −0.546174 | 0.391357 | 0.512753 | 1.058927 |
| (4,1) | −0.598201 | 0.287577 | 0.240999 | 0.339330 | 0.937531 |

**同一个格子，只因为「上一步往哪走」，`V` 差最多 1.06。**
（有惯性这个环境里 `V` 本身的范围大约 `[−0.60, 1.00]`，所以 1.06 的差不是小数。）

所以正确的状态是 `(格子, 上一步动作)`，`nS: 25 → 100`。

### 5.4 代价是平方的

DP 每轮是 `O(nS² · nA)`（要算 `P·V`，`P` 有 `nS²nA` 个元素）。
`nS` 乘 4，**每轮代价乘 16**。

```
nS: 25  →  100      每轮代价: ×16
nS: 25  →  2500     每轮代价: ×10000   （如果再加一维连续的观测量）
```

> **这是贯穿整个 RL 的张力：**
> **状态加得越多 → 马尔可夫性越好 → 状态空间越大 → 越算不动。**
>
> W6 起函数近似（用神经网络代替表格）就是为了打破这一头。
> 但在 P1，你要**先看见它有多贵**，才知道后面那些方法到底在省什么。

### 5.5 这个 bug 长什么样

现实中的写法通常是「状态 = 坐标」，因为坐标是最顺手的。
在有惯性的环境里这么写，**代码不会报错**，`V` 会算出来，策略也能跑。

症状是：**在某些格子，策略莫名其妙地来回摆。**
具体地说，是在「刚撞完墙」的那几格 —— 因为那一格的价值取决于
上一步是被哪个动作撞的，而你的状态里没有这个信息。

于是 `V(格子)` 有两个值，你又回到了 Day 29 实验 E 的处境。

## 六、局部观测：一个**空房间**就够破掉马尔可夫性

上一节是「状态太少所以不够」。这一节是反过来：**你以为够了的那个状态，其实不够。**

把坐标换成一个看起来更「像观测」的东西：**3×3 邻域的墙形**
（周围九格哪些是墙，包括出界）。这是机器人真能看到的东西。

环境：**5×5，一面内墙都没有**，只有四周边界。

结果：

```
23 个有效状态  →  8 种观测
```

| 观测 | 格子数 | `V` 最小 | `V` 最大 | 差 |
|---|---|---|---|---|
| **0** | **8** | **0.518540** | **0.860000** | **0.341460** |
| 1 | 3 | 0.734000 | 1.000000 | 0.266000 |
| 2 | 3 | 0.344017 | 0.518540 | 0.174523 |
| 3 | 3 | 0.734000 | 1.000000 | 0.266000 |
| 4 | 3 | 0.344017 | 0.518540 | 0.174523 |
| 5 | 1 | 0.620600 | 0.620600 | 0 |
| 6 | 1 | 0.269616 | 0.269616 | 0 |
| 7 | 1 | 0.620600 | 0.620600 | 0 |

最宽那组 8 个格子：`(2,1)` 的 `V` 是 **0.518540**，`(1,3)` 的 `V` 是 **0.860000**。
**差 0.341460。** 而它们看到的 3×3 墙形**逐位相同** —— 都是 9 个 0。

所以 `V(观测)` 有两个值。**不是「算不准」，是这个数不存在。**

这和 Day 29 实验 E 是同一件事。区别只是：那次是我手搭的两个抽象状态，
这次是**一个连墙都没有的空房间** —— 最简的网格世界，
局部观测照样立刻把「离终点多远」这个信息抹掉。

> ⚠️ **整段代码没有一处会报错。**
> 你会得到一个 25 维的 `V`，画成热力图还挺好看，拿它去训练也一切正常 ——
> 直到你发现策略在几个位置之间来回震荡。

### 6.1 这一节要连着 Day 32 一起想

Day 32 证了一个很漂亮的定理：`γ < 1` 时 `T*` 是压缩，所以**有唯一不动点，迭代必然收敛**。

**它保证了「那个不动点存在且唯一」，没保证「那个不动点是你要的」。**

定理的前提是「你给的是一个 MDP」。前提不成立时，定理什么都不说 ——
它不会失效，它只是**不适用**。而数学不会提醒你「你不适用」，
它只是继续给你一个数。

```
Day 32 回答：这个方程解得出来吗？     →  解得出来
Day 33 回答：这个方程对不对？         →  得由你自己保证
```

## 七、顺带修正 Day 32 的一个读法

写这个脚本时撞到一件事，值得单独说：**这个环境的值迭代只要 9 轮。**

Day 32 说 γ=0.9 要 294 轮，这里 9 轮。差 30 倍。查下来不是 bug：

| k | 相邻差（无惯性） | 相邻差（有惯性） |
|---|---|---|
| 1 | 1.000e+00 | 1.000e+00 |
| 2 | 9.000e-01 | 9.000e-01 |
| 3 | 8.100e-01 | 8.100e-01 |
| 4 | 7.290e-01 | 7.290e-01 |
| 5 | 6.561e-01 | 6.131e-01 |
| 6 | 5.905e-01 | 5.518e-01 |
| 7 | 5.314e-01 | 4.966e-01 |
| 8 | 4.783e-01 | 4.470e-01 |
| **9** | **0.000e+00** | 2.897e-01 |

前 4 轮比值**精确等于 γ**（1.0 → 0.9 → 0.81 → 0.729），然后第 9 轮**直接变成 0**，
之后永远不动。

原因：这个 MDP 的**最优路径最长 9 步**。值迭代从 `V₀ = 0` 出发，
第 k 轮的 `V_k` 就是「做 k 步规划能拿到多少」。k 一旦超过最优路径长度，
`T*` 再作用不改变任何东西 —— **有限步精确收敛**。

> **所以 `γ^k` 是「最坏情况的界」，不是「实际速率」。**
>
> | 环境 | 收敛方式 | 轮数 |
> |---|---|---|
> | 有吸收终态，最优策略必达终态 | **有限步精确** | = 最长最优路径 |
> | 没有终态（Day 30 的 2 状态链） | 真正的几何 | ≈ `log(ε/·)/log γ` |

界不会骗你（有限步当然也满足 `γ^k` 的界），但**照着界去估轮数会估多**。

顺带：有惯性那列慢两轮，而且第 5 轮开始分岔（`6.561e-01` vs `6.131e-01`）——
那是「上一步动作」这个信息第一次进入值里。**两列在前 4 轮完全相同**，
因为惯性还没走出「第一步」的影响范围。

## 八、终态那一行

最后一件事，也是最小、最容易漏的一件事：**终态在 `P` 里怎么占一行。**

### 8.1 三种写法

| 写法 | 终态行和 | `V(终点)` | `V(陷阱)` | 全局 `max|ΔV|` |
|---|---|---|---|---|
| ✅ 自环 `P[s,:,s] = 1` | 1.0000 | 0.000000 | 0.000000 | 0 |
| ⚠️ 全零行（什么都不写） | **0.0000** | 0.000000 | 0.000000 | **0** |
| ❌ 忘记特判 | 1.0000 | **10.000000** | 5.741096 | **10.0000** |

### 8.2 全零行是「记账」问题，不是数学问题

第二行的 `V` 和第一行**完全相同**（差 `0.0e+00`）。所以它不算错。

但它让 `P·1 ≠ 1`，于是 Day 32 的引理 2（常数平移）在终态这几行失效。
结果不影响（`0 ≤ 1`，压缩性还在），但你以后每次引用昨天的定理，
都要额外加一句「除了终态那几行」。

> **自环的唯一好处，是让这类例外消失。** 值 1 分，整洁 10 分。

### 8.3 忘记特判：这个 `10` 不是随便来的

第三行是最常见的真错：终态没特判，于是智能体从终点**能走出去**，
绕一圈再回来继续领奖。

```
V(终点) = 10.000000 = 1 / (1 − 0.9)
```

**它正好等于 `1/(1−γ)`。** 这是「在终点无限次领 +1 的折现和」。

Day 29 说过一句话：

> `|G_t| ≤ R_max/(1−γ)`，两行可证，**同时是调试诊断线**：
> 你的 `V` 超过它，代码一定错。

现在它**正好等于**这个界。这就是「智能体学会了刷分」的签名。

> **操作结论**：看到 `V` 卡在 `R_max/(1−γ)` 上，第一个要查的就是终态有没有特判。

而且这个错偏得很「合理」：所有值都变大了一点，loss 曲线照常下降，
成功率甚至更高（因为它在刷分）。**唯一能抓住它的是断言 `V(终态) == 0`。**

## 十一、我这次犯的错

**① `_step` 返回坐标元组，我直接拿去当状态下标。**

```python
P[s, a, ns] += p        # ns = (1, 0) 是一个元组
```

numpy 把 `(1,0)` 当成**两个下标**，于是每次都在「下标 1」和「下标 0」各加一次。
100 个 `(s,a)` 的行和全表最大变成 **2.0000**，恰好就是实验 B 里那个「双计」错误的症状。

**我被自己的 bug 骗了一次**：第一次跑出来的行和最大值是 2.0，
我差点把它当成「`double_count` 模式生效了」写进讲义。真因是坐标系和索引没转换。

> 教训：**`P[s, a, ns]` 里 `ns` 必须是 int。** 用元组做下标时 numpy 不报错，
> 它会做「高级索引」—— 这是 numpy 里最容易静默出错的地方之一。

**② 实验 B 的第一版断言失败，但它失败得很有价值。**

我原来的断言是「丢概率一定会改变 `V`」，实测 `ΔV = 0`。
我第一反应是「断言写错了」，查下去发现是**真的没改变** —— 因为最优策略绕开了那个动作。

这条我没删掉断言，而是把环境改成两种（有风 / 无风），让它变成一个**发现**：
**有些 bug 在端到端测试里是不可见的。**

**③ 实验 C 的表格第一版读起来自相矛盾。**

我把 `R(s,a)` 和 `V*(s)` 并排放在一行里比较。但它们是两个不同下标的东西
（`V*(s)` 是对所有动作取 `max`），而且错误的 `R` 会连 `V` 一起改，
导致「用最可能后继」那一行的 `ΔV` 竟然是**正的** —— 和我正在写的结论相反。

改成**固定用正确的 `V*`，只换 `R`**，`ΔQ = ΔR` 变成恒等式，符号就对了。

> 教训：**做对照实验时，一次只让一个量变。**
> 让两个量一起变，你得到的是「净效果」，而净效果的方向可能和因果方向相反。

**④ 我一开始以为「9 轮收敛」是 bug。**

查了 `_format`、查了 `value_iteration`、以为是 `v` 没更新。
真因是「有吸收终态时值迭代有限步精确收敛」—— 一个正确的、我原来没意识到的事实。
它后来变成了讲义 §七。

> 这条和 Day 31 那个「float64 地板」是同一类：
> **看到一个和预期不符的数，先别改代码，先问「预期是不是错的」。**
