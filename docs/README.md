## 两条纪律（两起事故换来的）

1. **任何纯文本资产，先写进 `docs/` 再提交。**（`2026-10-26` 清空事故）
2. **写完一个模块就提交并 push，不要攒。**（`2026-10-27` 回滚事故）
   - 本地提交也会跟着工作区一起消失 —— `2026-10-27` 本地 git 丢了 6 个提交、
     reflog 里也没有，靠 `git fetch` 才拿回来
   - 当天的第一版是「代码 + 讲义 + 台账一起做完再提交」，一被回滚全没了；
     改成做完一块提交一块，最多丢一块

**只有 push 到远端的提交，才算真的存下来了。**

### 附：这次事故里还学到一个反面教训

`2026-10-26` 丢失时，我在上一版这个文件里写了一句「讲义正文丢了，但**代码注释没丢**，
所以从 Day 12 起改成『我写完整实现 + 逐行中文注释』是对的」。

这句话对了一半。**代码注释确实救了那次**，但它救的是「能重看」，
救不了「原本写了什么」——
课义的排版、例子、当时的引导顺序，代码注释里是没有的。

真正让这批东西活下来的，只有**进 git 并且 push**。

## 为什么讲义不放在 `notebooks/`？

`notebooks/` 的定位是「探索性代码、跑完即弃」，而讲义是**长期资产**。
混在一起的结果是：清理 notebook 的时候顺手把讲义的依赖也删了。

另外主 README 里写了「正式代码不许放 notebooks」—— 讲义属于正式资产，
放 `docs/` 才是自洽的。
