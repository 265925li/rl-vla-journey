## 四、能力盘点（这一节最该看）

### 现在能做的

**1. 从零搭一条能复现的训练流水线**
不需要抄模板。知道顺序为什么是这个顺序（种子必须在建模型之前）、
知道哪些东西不能进 `history.json`（耗时）、知道配置该怎么分层校验。

**2. 手写一个算子的前向 + 反向，并且证明它是对的**
这是 P0 最核心的能力。具体的证明手段有四种，各有各的盲区：

| 手段 | 能抓什么 | 抓不到什么 |
|---|---|---|
| 与官方实现对拍 | 数值是否一致 | 如果两边错得一样（同一套错误推导） |
| `gradcheck`（有限差分） | 解析推导的错 | 二阶导的错 |
| `gradgradcheck` | 存了中间量导致二阶断链 | 前向的错 |
| 手推校验（如 `grad_x` 应等于 W 的行和） | 完全不依赖框架的独立验证 | 只能验特例 |

**四种都用过，才知道为什么要四种。**

**3. 分辨「跑通了」和「跑对了」**
这是 P0 最值钱的一条。Day 11 实测：**十种填错里五种不报错**。
最险的是 `argmax()` 漏 `dim=1` —— train acc 恒为 0、val acc 0.99、退出码 0。

**4. 设计对照实验**
- 一次只改一处（四组正则化：A 基线 / B 只 dropout / C 只 wd / D 两个一起）
- **扫剂量，不取单点**（这条是犯过错才学会的）
- 会用标准误判断"提升"是不是噪声（`SE = sqrt(p(1-p)/n)` ≈ 0.14 个百分点）
- 知道 acc 的分辨率有多粗（6000 条验证集，正确 1 条 = 0.0167%）

**5. 做接口替换**
`mysgd` ↔ `torch.optim.SGD`、`MyCrossEntropy` ↔ `nn.CrossEntropyLoss`、
`MyLinear` ↔ `nn.Linear`。三次替换，调用方零改动。
前提是**先对拍、再替换** —— 没对拍就换，等于蒙着眼睛换零件。

**6. 模块化重构，并用逐字节对拍证明没改变行为**
`train_mnist.py` 546 行 → 40 行薄壳 + 1008 行分 8 个模块，
四项确定性指标一个比特都没变。

### 还不能做的（P1 起要补）

| 不能做 | 现在到哪一步了 |
|---|---|
| **CNN / 卷积 / 池化** | 只理解概念，没写过一行。`src/engine/` 的注册表已经为它留好位置 |
| **任何 RL 算法** | 零基础。DQN / PPO / SAC 都还没开始，P1 的主体 |
| 混合精度训练（amp + GradScaler） | 只知道 fp16 的 exp 溢出阈值是 11.1（Day 16 实测），没实操 |
| BatchNorm / LayerNorm | 知道 `model.eval()` 会切换行为，没自己实现过 |
| 数据增强 | 只用了 `ToTensor`，没做过 RandomCrop / Flip |
| 读论文复现代码 | 没有一次完整经历 |
| **盲写** | 待验。`train_step` 那 5 行还没在无参考的情况下写过 |

最后一条值得单独说：**「看懂」和「写得出」之间有一道坎。**
P0 的打法是「我写实现 + 逐行注释 + 你读懂跑通」，这条路线在
**理解效率**上是对的（12 天推完 21 天的量），但它**不能验证盲写能力**。
P1 期间必须补上这一环，否则到了要自己设计算法的时候会卡住。

## 五、五条跨天教训

### 1. 「跑通了」和「跑对了」是两件事

十种填错里五种静默不报错。它们不抛异常、不崩、曲线照样在动。
**唯一能抓到的方法是有一个独立参照物**（官方实现、有限差分、手推值、逐字节基线）。

### 2. 一个超参数只测一个点 = 什么都没测出来

这是我（AI）犯的错：Day 15 只测 `wd=5e-4` 就说"正则化没用"。
补扫后结论反了一半：

```
wd=0      → 0.9800
wd=5e-5   → 0.9804
wd=1e-4   → 0.9812   ← 峰顶，比基线高
wd=5e-4   → 0.9782   ← 过量，比基线低
```

**倒 U 型。取哪个点决定你得出哪个结论。**

### 3. 诊断出问题 ≠ 应该处理它

`gap` 从 +0.54 涨到 +1.86，看着像过拟合在恶化。
但同期 `val_loss` 从 0.0789 降到 0.0773（还在变好）。

**`gap` 是警报，`val_loss` 的绝对值才是判决书。**
这套模型是良性过拟合 —— 有富余容量，学细一点没坏处。
加正则等于**给没病的人吃药**，实测三个方案全让准确率下降。

### 4. 「完全一致」必须拆成三句话

同 seed 跑 `ce` vs `myce`：

```
首轮 train_loss   前 6 位全同          → 单步一致
次轮 val_loss    差 3.6e-03            → 多步分叉（放大了 36 万倍）
test acc         差 0.03pt，SE 是 0.17 → 终值差远小于统计噪声
```

所以正确的表述是「**单步一致、多步分叉、终值差远小于统计噪声**」，
不是「完全一样」。这个区分直接决定了「换实现之后要不要重跑 baseline」。

### 5. 说「已经存了」之前，必须从零验证

`2026-10-26` 工作区被清空，`学习计划/` 下的讲义全部丢失 ——
因为它们从未进过 git。代码一次没少，因为提交过。

**验证纪律**：`mktemp -d` → 全新 `git clone` → 在里面 `ls` 确认文件在、
跑一次脚本确认能跑 → 才删临时目录。

「我提交了所以应该存了」**不算验证过**。这次事故就是「以为存了其实没存」。

## 九、P1 第一件事：CNN

理由不是"CNN 很火"，是**它是 MNIST 这件事的收尾**：

```
MLP 到 98.0% 就到顶了
     ↓  原因：输入被摊平成 784 个独立数字，"相邻像素相关"这个信息永久丢了
     ↓
卷积保留空间结构 → 同样的数据能到 99%+
     ↓
而 VLA 里的视觉编码器，本质就是卷积 / ViT
```

而且架构上已经准备好了 —— Day 18 的注册表就是为这一刻建的：

```python
# src/engine/builtin.py 加这一段
@register_model("cnn")
def build_cnn(cfg):
    return CNN(channels=cfg.channels, ...)
```

```yaml
# configs/cnn_mnist.yaml
model: cnn
flatten: false      # ← 关键：CNN 不能摊平
```

`trainer.py` / `cli.py` **一个字都不用改**。这就是 Day 18 那次重构的回报。

## 十、一句话带走

> **P0 教的核心不是"会写 PyTorch"，是"知道怎么证明自己写对了"。**
>
> 五个手写件全部与官方实现对拍通过，误差在 `1e-9 ~ 1e-8` 量级。
> 这个能力在 P1 之后会用得更狠 —— RL 比监督学习更难调，
> 因为它**没有"正确答案"可以对比**，只有 reward 曲线。
> 到那时候，"设计一个能自动判对错的参照物"就是唯一的救命绳。
