## 二、卷积到底在干什么

### 2.1 摊平丢了什么（用具体例子）

MNIST 的一张图是 `(1, 28, 28)`。MLP 的第一行是：

```python
x = x.view(B, -1)      # (B, 1, 28, 28) → (B, 784)
```

摊平之后的第 137 号位置，和它右边那个数（第 138 号）、下面那个数（第 165 号）
在数值上**还在**，但**「相邻」这件事在模型的眼里消失了**。

于是 MLP 能学到的只有：

> 「第 137 个位置的值大不大」

而不是：

> 「这里有一个竖直的笔画边缘」

这两者的区别是致命的。想让它认出一个竖边，MLP 得在 28 个不同位置
**各学一遍**（每个位置一套独立权重）。而同一个竖边出现在左上角和右下角，
在它看来是两件毫不相干的事。

### 2.2 卷积的做法：一个窗口扫全图

```
        一张 28×28 的图
    ┌────────────────────┐
    │ ▓▓░  ░▓▓  ░░▓▓     │
    │  ▓▓▓ ▓▓░  ░▓▓░     │     ┌───┐
    │   ▓▓▓▓░   ░▓░      │  ←  │3×3│ 窗口，9 个权重
    │                    │     └───┘
    │       ↑            │
    │    窗口在这里       │     扫过所有位置
    └────────────────────┘
```

窗口滑过每一个位置，每次都做同一件事：

```
out[o, i, j] = Σ  patch[i, j] · W[o]  + b[o]
              c,u,v
```

关键是 **Σ 覆盖的范围是局部的**（`C_in × 3 × 3`，不是全图 784）。

### 2.3 「参数共享」四个字的全部含义

同一套 3×3 权重在整张图上**重复使用**。于是：

- 学到的东西是「左暗右亮 = 竖边」这种**与位置无关**的模式
- 一个模式只要学会一次，**全图通用**
- 参数从 `784 × 784` 降到 `9`

实测这个差距有多大（`src/utils/conv.py` 关 6）：

```
Conv2d(1, 16, k=3)            160 参数     ← 16×1×3×3 + 16
等价的逐位置全连接        9,847,040 参数   ← 784×(16×784) + 16×784
─────────────────────────────────────────
比值                          61,544 倍
```

**六万一千倍。** 这就是为什么 CNN 在小数据上能赢。

> ⚠️ 但注意措辞：不是「CNN 参数少」。我们今天的 CNN 有 206,922 个参数，
> 比 MLP 还多。真正少的是**卷积那部分**（4,800，占 2.3%），
> 97.7% 的参数都在最后两个全连接层。
> 准确的说法是：**CNN 把参数花在了「提取特征」之外的地方，而特征提取本身几乎免费。**

## 三、三个必背公式

### 3.1 输出尺寸

```
H_out = floor( (H_in + 2·padding − dilation·(kh − 1) − 1) / stride ) + 1
```

常用特例（记住这三个就够）：

| 配置 | 效果 | 例 |
|---|---|---|
| `k=3, s=1, p=1` | **尺寸不变**（"same" 卷积） | 28 → 28 |
| `k=2, s=2, p=0` | **尺寸减半** | 28 → 14 |
| `k=3, s=2, p=0` | 减半再少 1 | 28 → **13** |

⚠️ **第三个就是我今天踩的坑**。下意识会写 14，实际是 `(28−3)//2+1 = 13`。

它的后果不在卷积层暴露，而是在**两层之后接全连接层时**：

```
conv(k=3, s=2, p=0) 之后是 (1, 32, 13, 13)，不是 (1, 32, 14, 14)
如果按 14 算：32×14×14 = 6272
实际展平后：32×13×13 = 5408
→ 全连接层报 mat1 and mat2 shapes cannot be multiplied
→ 而报错位置在**全连接层**，离真正的错因隔了两层
```

所以关 3 专门验这件事：六个配置手算 vs 实际，一个都不能错。

### 3.2 参数量

```
卷积层： C_out · (C_in · kh · kw + 1)
池化层： 0                    ← 无参数，这也是它不占参数量的原因
全连接： in · out + out       ← 和 MLP 一样
```

今天这个 CNN 逐层拆开（这是 `expected_params_cnn()` 里手算的，和程序对数一致）：

```
conv1  1→16  k3 p1        160
conv2  16→32 k3 p1      4,640
fc1    1568→128       200,832     ← 光这一层就占 97%
fc2    128→10           1,290
──────────────────────────────
合计                  206,922     ← 程序数出来也是 206,922
```

> **一个值得记住的观察**：97.7% 的参数在全连接层。
> 这是 2012 年 AlexNet 那种早期 CNN 的典型形态，
> 也是后来「全局平均池化（GAP）」被发明的原因 —— GAP 直接把
> `(B, C, 7, 7)` 平均成 `(B, C)`，把 200,832 个参数压到 **0**。
> P1 后面会做这个实验。

### 3.3 感受野

```
rf_out   = rf_in + (k − 1) · jump_in
jump_out = jump_in · stride
```

直觉：每过一层 k×k 卷积，视野向外扩 k−1 圈；
但扩的是**上一层格子的间距**（jump），不是原图的一个像素。

今天这个网络的官方追踪（`src/models/cnn.py` 的 `receptive_field_trace`）：

| 层 | 输出尺寸 | 感受野 | 有效步长 |
|---|---|---|---|
| input | 28 | 1 | 1 |
| conv1 k3 p1 | 28 | 3 | 1 |
| pool1 2×2 | 14 | 4 | 2 |
| conv2 k3 p1 | 14 | 8 | 2 |
| pool2 2×2 | 7 | **10** | 4 |

**最后每个神经元在原始图上看 10×10 的范围。** 输出却只有 7×7 —— 也就是说，
相邻两个输出神经元的感受野是重叠的。这个重叠是好事（平移不变性的来源）。

**为什么大家都用 3×3（VGG 的核心论点）**：

```
两层 3×3：感受野 5×5，参数 18
一层 5×5：感受野 5×5，参数 25
→ 同样视野，堆小卷积省 7 个参数（25 → 18），还多一次非线性
```

> ⚠️ **这里我自己算错过一次**。第一版把两层 3×3 的感受野写成了 7×7 ——
> 因为我从 `rf=3` 出发又加了一次 `(3−1)·1`，等于数了三层。
> 正确起点是 `rf=1, jump=1`，连过两个 3×3 得 5。
> 是 `return rf_2x3 == 5` 这个 assert 当场抓住的 —— **自检代码要断言，不能只打印。**

## 四、手写卷积：让三种实现互相指认

### 4.1 朴素版（定义）

`conv2d_naive()`：四层循环 + 一句 `(patch * weight[o]).sum()`。

这是**定义**。慢到不能用（实测比 im2col 慢 4958 倍），但它的正确性
不需要任何论证 —— 它就是公式本身。

### 4.2 im2col（实现）

`conv2d_im2col()`：核心只有一句话：

> **卷积 = 把每个窗口摊平成一列 + 一次矩阵乘**

```
输入 (N, C, H, W)
  ↓ F.unfold：每个位置抠出 C×kh×kw 的窗口，摊平成一列
(N, C·kh·kw, H_out·W_out)
  ↓ weight.reshape(C_out, C·kh·kw) @ col
(N, C_out, L) → view 成 (N, C_out, H_out, W_out)
```

为什么快：矩阵乘是 BLAS/cuBLAS 里优化了四十年的算子。
代价是内存 —— `col` 是输入的 **9 倍**（k=3 时）。

### 4.3 为什么要三种实现，而不是两种

只对拍「手写 vs 官方」时，如果差 `1e-7`，你**无法判断**是：

- (a) 我写错了，还是
- (b) 官方用了 Winograd / FFT 等算法，本来就有舍入差

有朴素版这个「定义级正确」的第三方在，就能定位到底是哪个错：

```
实测（关 2，双精度）：
  朴素  vs 官方      3.55e-15 ~ 8.88e-15     ← 求和顺序不同
  im2col vs 官方     0.00e+00  ←★ 逐位相同
  im2col vs 朴素     3.55e-15 ~ 8.88e-15
```

### 4.4 「逐位相同」意味着什么

im2col 版和 `F.conv2d` 的结果**一个比特都不差**（`0.00e+00`）。

这说明 PyTorch 在 FP64/CPU 路径上走的就是 im2col + GEMM —— 我的实现和它在
**同一条数值路径**上，连加法顺序都一样。而朴素版差 `1e-15`，纯粹是因为
`.sum()` 的累加顺序和矩阵乘的累加顺序不同。

这个观察有用：它告诉你「差 1e-15」和「差 1e-7」是**两种性质不同的差**。
前者是加法顺序，后者才是算法不同。

## 五、反向传播：三个梯度的形状

### 5.1 三个公式

```
前向： out = conv(x, W, b)
       x:(N,C_in,H,W)   W:(C_out,C_in,kh,kw)   b:(C_out,)

反向： grad_out:(N,C_out,H_out,W_out)

       ∂L/∂b = grad_out 在 (N, H_out, W_out) 上求和      → (C_out,)
       ∂L/∂W = Σ_n  grad_out[n] @ col[n].T               → (C_out, C_in·kh·kw)
       ∂L/∂x = fold( W_flat.T @ grad_out )                → (N, C_in, H, W)
```

**记不住就从形状反推**（Day 17 的老办法）：

要让 `(C_out, C_in·kh·kw)` 出来 → `(C_out,L) @ (L,K)`
要让 `(N,K,L)` 出来 → `(K,C_out) @ (N,C_out,L)`，所以 W 要转置

### 5.2 为什么 ∂L/∂W 要跨样本求和，∂L/∂x 不要

这是卷积反向最容易糊涂的地方，根因是**参数共享**：

```
W 是同一套权重，被 N 个样本、每个样本的 L 个位置**共用**
  → 每个样本都对它贡献一次梯度 → 必须把 N 个样本加起来

x[n] 只属于第 n 个样本，别的样本影响不到它
  → 不需要跨样本求和
```

对照 Day 17 的 Linear：那里 W 也共享，所以 `grad_out.T @ x` 里已经隐含了
跨样本求和。卷积这里是「N 和 L 两个维度都要求和」，所以那行是：

```python
grad_w = torch.matmul(g2d, col.transpose(1, 2)).sum(0)   # ← .sum(0) 不能少
```

**漏掉 `.sum(0)` 的实测后果**（关 4 反例，N=4）：

```
正确（4 个样本求和）  平均梯度 7.6175
错误（只算 1 个样本） 平均梯度 3.3285
→ 差了 2.3 倍
→ 形状完全合法 (C_out, K) = (3, 18)，不报错，loss 照降
```

### 5.3 为什么 ∂L/∂x 用 fold 而不是「反着卷积一遍」

数学上 `∂L/∂x` 等于「grad_out 与翻转 180° 的 W 做全卷积」，公式漂亮但实现绕
（要处理 padding 的裁剪）。

`fold` 是 `unfold` 的逆运算：把 `(N, C·kh·kw, L)` 的列**加回**原图位置。
重叠区域自动累加 —— 正好就是链式法则要的「每个输入像素被几个窗口用到，
它的梯度就是那几个窗口贡献之和」。

> 一句话：**unfold 把重叠的窗口摊开，fold 把梯度按重叠次数加回去。**

### 5.4 一个必须注意的细节：存 x，不存 col

Day 16 的坑①在这里重演。`forward` 里如果 `ctx.save_for_backward(col)`，
一阶导会完全正确，**二阶导全是 0**：

因为 `col` 是 `x` 经过 `unfold` 得到的中间量，不是叶子张量。
autograd 记录不到「col 是怎么从 x 来的」，`gradgradcheck` 里的 `grad_x` 就是 0。

正确做法：**存输入 `x`，backward 里重新算一次 `col`**。代价是一点算力
（这也是手写卷积比官方慢 23% 的原因之一），换来二阶导正确。

**② CNN 的 val_loss 最低到 0.0413，MLP 是 0.0773 —— 低了 46%。**

这个数字比准确率更有说服力。准确率只有 10000 个离散点、分辨率 0.01pt；
loss 是连续的，能看出「模型有多确信」。

## 八、手写卷积跑完整训练

`--set conv=my` 把整个模型的卷积层换成 `MyConv2d`，其它一个字不动：

```powershell
& $PY scripts\train.py --config configs\cnn_mnist.yaml --set conv=my --tag cnn_myconv
```

结果：

| | 官方 `nn.Conv2d` | 手写 `MyConv2d` | 差 |
|---|---|---|---|
| test acc | 0.9889 | 0.9880 | 0.09pt = **0.5 SE** |
| best val acc | 0.9878 | 0.9885 | 手写版**还高一点** |
| epoch 1 train_loss | 0.3214 | 0.3207 | 7e-4 |
| epoch 10 train_loss | 0.0094 | 0.0091 | 3e-4 |
| 耗时/epoch | 10.6s | 11.8s | +11% |

### 8.1 一个和 Day 16/17 不同的现象

Day 16（换 loss）时首轮 train_loss **前 6 位全同**，Day 17（换 Linear）也是
`0.00e+00`。今天换卷积，**首轮就差了 7e-4**。

为什么？因为换的深度不同：

```
Day 16：换的是「调用位置」——     同一个 kernel，只是从 F.xxx 换成手写包装
Day 17：换的是「整条数值路径」——  x@W.t() 换成手写，但仍是同一个 cuBLAS
Day 22：换的是「算法本身」——      cuDNN 的卷积 kernel vs im2col+GEMM
```

cuDNN 在 fp32 上可能用 Winograd 或隐式 GEMM，和我的 im2col 不是同一条路径。
**算法不同，首轮就不可能逐位相同。** 这不是「写错了」，是预期之内。

判据仍然成立：差 0.09pt < 0.5 SE → **终值差远小于统计噪声**。

### 8.2 手写版更慢的原因

`forward` 里为了二阶导正确，`backward` 要重新跑一次 `unfold`（见 §5.4）。
官方实现可以在 kernel 里直接复用。

两次跑出来的倍率是 +26.8%（101.3 → 128.5s）和 +11.5%（105.8 → 118.0s），
差得挺大 —— 因为耗时的噪声本来就有 ±10%，而这两个实现的差距就在噪声边缘。
**能确定的只是「手写版不更快」，不能给出精确倍率。**

这 10~25% 是**正确性的代价**，不是写得烂。要精确定量得跑多次取中位数，
但那对学习目标没有价值 —— 记住「重算中间量换二阶导正确」这个取舍就够了。

```
MLP:  0.1489 → 0.1105 → 0.0955 → 0.0840 → 0.0904 → 0.0789 → 0.0792 → 0.0824 → 0.0787 → 0.0773

```

同时：

- `train_loss` 还在往下走（0.0192 → 0.0094）
- `gap` 从 +0.64 涨到 +1.22
- `wnorm` 单调涨（17.39 → 18.55）

**三条同时出现，就是真过拟合。** 这和 MLP 那个「gap 涨但 val_loss 还在降」的

### 这引出了 P1 接下来要做的三件事

1. **早停**：ep7 就停，val 0.9873。但 Day 15 的教训是 acc 判据和 loss 判据
   会给相反结论，要在 CNN 上重验一次。
2. **数据增强**（RandomCrop / RandomRotation）：CNN 有平移不变性，
   增强正好对上它的先验。这是「对症下药」，不是「试试看」。
3. **全局平均池化（GAP）**：把 200,832 个 FC 参数压到 0，
   看能不能既减少过拟合又保持精度。

## 十、七个静默陷阱

### 1. `weight` 的形状是 `(C_out, C_in, kh, kw)`

TensorFlow 是 `(kh, kw, C_in, C_out)`。互转时漏一次 `permute`，
在 `C_in == C_out == kh == kw` 的方阵上**形状合法、能跑、loss 也降** ——
和 Day 17 的转置错误一模一样。

### 2. `flatten` 忘了关

会报错（`Conv2d` 收到 2 维输入），**但报在 conv1，错因在 yaml**。
所以 `build_cnn` 里提前拦掉了，报错信息直接说「去改配置」：

```
model=cnn 但 flatten=true。CNN 需要 4 维输入 (B,C,H,W)，
必须在配置里写 flatten: false。
```

### 3. `∂L/∂W` 漏 `.sum(0)`

形状合法 `(C_out, K)`、不报错、loss 照降，但梯度小 N 倍（实测 N=4 时小 2.3 倍）。

### 4. 输出尺寸算错

`(28−3)//2+1 = 13`，不是 14。报错在**两层之后的全连接层**。

### 5. 池化和激活没有参数

参数量公式里不该出现它们。写进去会得到自己对不上自己的公式。

### 6. 感受野多算/少算一层

我今天就犯了：把两层 3×3 写成 7×7（实际 5×5）。
`assert rf_2x3 == 5` 抓住了。**自检代码要断言，不能只打印。**

### 7. `isinstance(m, nn.Conv2d)` 会静默跳过 `MyConv2d`

Day 17 的坑在卷积上重演。`MyConv2d` 直接继承 `nn.Module`，不是 `nn.Conv2d`
的子类，所以任何「遍历模型找卷积层」的代码（初始化、剪枝、统计 FLOPs）
都会**静默跳过它**。

正确写法是鸭子类型：`hasattr(m, "weight") and m.weight.dim() == 4`。

这保证了 P1 后面加 DQN / PPO 的时候，早停、存盘、日志、曲线这些

> ⚠️ 一个反而值得记的细节：`registry.py` 里那几处**行尾注释**
> 写的是 `# cfg.model = "mlp" / "cnn" / ...`，如果把这种也算成「代码提到了 cnn」，
> 验证就会失败。所以「不影响行为」的准确判据是
> **代码行有没有变**，而不是「文件里有没有出现过这个词」。
> 用 grep 验收时要看清是注释还是语句。
