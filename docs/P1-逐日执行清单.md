1. **Day 是顺序编号，不是日期。** 一天可以是一整个下午，也可以是两个晚上。
   打不上勾就不进下一天，但**允许一天吃掉两天的量**（P0 就干过）。
2. **每个 W 的最后一天是收口日**，只做三件事：对账、写跨天结论、更新台账。

   而这类东西在决策点 A 上会直接暴露。

### Day 25 · BatchNorm（今天）

**为什么排在这里**：Day 24 测出 baseline 到 ep7 就见顶、aug3 到 ep20，
说明瓶颈是「收敛太早」而不是「精度不够」。BN 是治这个最直接的手段。
同时它是 P0 复盘 §四 挂的第二笔账。

| 环节 | 内容 |
|---|---|
| 数学 | 训练态（批内统计）vs 推理态（running stats）**两套公式** |
| 手写 | `MyBatchNorm2dFunction` 的 4 行反向 |
| 七关 | 训练态前向 / 三个梯度 / gradcheck / 两种模式必须不同 / running stats 手算 / momentum 语义 / conv bias 失效 |
| 剂量 | 无 BN / BN 只在 conv 后 / BN 加在 fc 前 / BN + 放大学习率 |
| 轮数 | **25 轮**（Day 24 的教训：轮数不够会让结论反过来） |

**今天最容易翻车的四个点**（要写进讲义）：
1. 忘了 `model.eval()` —— 不报错，但验证结果全错
2. BN 让 conv 的 `bias` 失效 —— 参数量手算会多算 32 个
3. `momentum=0.1` 是「记住 90% 历史」，和教科书写法相反
4. `batch_size=1` 时批内方差为 0，BN 直接崩

### Day 26 · 混合精度

**为什么值得单独一天**：这台机器是 **GTX 1660 Ti（sm_75，无 Tensor Core）**，
所以 amp 的收益会比论文里的数字小得多。**先测出「在这台机器上值不值」**，
而不是照搬「amp 能快 2 倍」的说法。

- 学 `GradScaler` 解决的到底是什么问题：fp16 的梯度下溢（不是上溢）
- **静态 loss scaling vs 动态 scaling**：`scale` 为什么会自己变小
- 关键坑：`scaler.unscale_()` 必须在 `clip_grad_norm_()` **之前**调用
- 关键坑：fp16 下 `exp` 溢出阈值是 11.1（P0 已知），所以 CE 的 log-sum-exp 必须用 fp32 算
- 交付：`fp32 / fp16+scaler` 两条曲线对拍，记录 `scale` 的完整轨迹

### Day 27 · 数据加载提速

Day 24 之后每轮 13.55s，其中 CNN 前反向 9.48s，剩下 **4.07s（30%）** 是数据加载与拷贝。

- 起手先做 **Amdahl**：把 4.07s 优化到 0 最多 1.43×
- `num_workers>0` 的**真正难点不是设个数字**，是 collate 里的 `torch.Generator`
  被 fork 到子进程后**每个 worker 拿到同一个状态** → 4 个 worker 产生的增强完全一样
- 正确做法：`worker_init_fn` 里按 `worker_id` 派生独立 seed，或者干脆在 collate 里用
  `torch.randint` 从全局 RNG 抽（子进程的全局 RNG 会被 PyTorch 自动按 base_seed 打散）
- 验收：`num_workers=0` vs `num_workers=4` 的结果**必须逐位一致**
  （做不到就别改，这是 Day 24 立下的规矩）

### 每天的重点提示

**Day 29 · MDP 五元组**
- 五个要素：`(S, A, P, R, γ)`。**`P` 和 `R` 是两个东西，不要合并**。
- 关键区分：**回报 `G_t`（随机变量）** vs **值函数 `V(s) = E[G_t | S_t=s]`（期望）**
- 手推「为什么 `G_t = R_{t+1} + γ G_{t+1}`」—— 这个递归是后面所有东西的种子
- 坑：`γ=1` 且任务无限期 → 回报可能发散。`γ<1` 是收敛性的前提

**Day 30 · 贝尔曼期望方程**
- `V^π(s) = Σ_a π(a|s) Σ_{s',r} p(s',r|s,a)[r + γ V^π(s')]`
- **验证方式很关键**：对有限 MDP，这个方程是**线性方程组** `V = R^π + γ P^π V`，
  可以直接 `(I - γP^π)^{-1} R^π` 求精确解。手写的迭代解必须收敛到这个值。
- 这是本周唯一能拿到「精确答案」的地方，**务必用到极致**

**Day 31 · 贝尔曼最优方程**
- `V*(s) = max_a Σ p(s',r|s,a)[r + γ V*(s')]` —— 注意 `max` 的位置
- 关键理解：`V*` 是**所有策略里最好的那个**，不是某个策略的值
- 坑：最优策略可能不唯一，但 `V*` **唯一**。断言时要断言值，不要断言策略

**Day 32 · 压缩映射（你的数学优势区）**
- 要证的：`‖T V1 − T V2‖∞ ≤ γ‖V1 − V2‖∞`
- 要用的：Banach 不动点定理 → 值迭代以 `γ^k` 的速率收敛
- **能自己把证明写出来**，不看书。这是判断「真懂」还是「记住结论」的分水岭
- 顺带算：要达到 `ε` 精度需要迭代多少轮 → `k ≥ log(ε(1-γ)/R_max) / log γ`

**Day 33 · GridWorld**
- **第一个自己写的环境**。它是 P1 后面所有实验的靶场，设计好一点
- 交付物要有：`5×5` 和 `10×10` 两种尺寸、随机风（可选）、起终点可配
- 关键坑：**状态转移矩阵的形状**是 `(nS, nA, nS)` 还是 `(nS, nA, nS, ...)`，
  定下来之后全程别改，否则后面每天都要重新推一遍索引
- 验收：手算一个 `2×2` 的转移矩阵，与代码比

**Day 34 · 策略迭代**
- 两步循环：**策略评估**（解线性方程组或用迭代）→ **策略改进**（贪心）
- 手写时最容易错的地方：策略改进要用**当前的 `V^π`**，不是上一步的
- 收敛判定：策略不再变化。注意是**策略**不变，不是值不变

**Day 35 · 值迭代 + 收口**
- 值迭代 = 把「评估」和「改进」压成一步（直接对 `V` 取 max）
- 对比三种 DP：策略迭代 / 值迭代 / 截断策略迭代
- **收口要回答的问题**：为什么值迭代通常更快，但在什么情况下策略迭代更省？

### 每天的重点提示

**Day 36 · Monte Carlo**
- MC 的核心：**必须等 episode 结束**才能算 `G_t`（这就是它只能用于 episodic 任务的原因）
- 两个变体：**首次访问**（只统计第一次经过 `s`）vs **每次访问**（每次都算）
- 数学结论：两者都是无偏的，但首次访问的方差略小
- 坑：用增量式更新 `V ← V + α(G − V)` 而不是存所有 `G` 再平均，否则内存爆

**Day 37 · TD(0)**
- `V(S_t) ← V(S_t) + α[R_{t+1} + γV(S_{t+1}) − V(S_t)]`
- 那个方括号叫 **TD error**，是 RL 里最重要的一个量，后面 DQN 的 loss 就是它的平方
- **和 Day 30 的贝尔曼方程对照看**：TD 就是把「期望」换成「一次采样」
- 关键：TD **有偏但方差小**，MC **无偏但方差大**。为什么？Day 39 专门讲

**Day 38 · n-step TD**
- `n=1` 是 TD(0)，`n=∞` 是 MC，中间是连续谱
- **验收必须做到 `n=1` 与 Day 37 的实现逐位一致** —— 这是证明「重构没改行为」的老办法
- 坑：episode 末端的处理，`n` 步不够时要提前截断

**Day 39 · 偏差–方差（本周理论核心）**
- 要用**数学**讲清楚，不是画个图说「你看方差变小了」：
  - MC 的目标 `G_t` 是 `V^π(s)` 的无偏估计
  - TD 的目标 `R + γV(S')` 的期望等于 `V^π` **只有当 `V = V^π` 时**，
    而训练中 `V` 一直在变 → 目标在移动 → 有偏
- 实验：固定 episode 数，跑 50 个 seed，画估计值的分布
- **这一天的结论要能一句话说清**：「TD 用偏差换方差」

**Day 40 · TD(λ)**
- `λ` 控制往回看多远，`λ=0` 退化 TD(0)，`λ=1` 是 MC
- eligibility trace 的两种视角：**前向**（理论，看未来）vs **后向**（实现，记过去）
- 坑：`λ=1` 的离线版才是 MC，在线版不是。断言时要说清楚是哪种

**Day 41 · 论文 1**
- 首选：**Sutton (1988) "Learning to predict by the methods of temporal differences"**
  —— 就是 TD 的原始论文，和本周内容严丝合缝

### 每天的重点提示

**Day 43 · ε-greedy 与 GLIE**
- ε-greedy 不是万能的：`ε` 固定 → 永远在最优解附近抖动（无法收敛到最优策略）
- **GLIE**（Greedy in the Limit with Infinite Exploration）：`ε` 要随步数衰减到 0，
  且每个状态要被访问无限次。这是表格法收敛的前提条件
- 坑：`ε` 衰减太快 → 没探索够就锁死；衰减太慢 → 最后还在乱走

**Day 44 · Sarsa**
- 名字来自五元组 `(S, A, R, S', A')` —— **注意它需要下一个动作 `A'`**
- 更新式：`Q(S,A) ← Q(S,A) + α[R + γQ(S',A') − Q(S,A)]`
- **它是 on-policy**：估的是「我实际执行的这个 ε-greedy 策略」
- CliffWalking 上的经典现象：Sarsa 学到**安全路径**（绕远路），因为它知道
  「我会偶尔乱走，掉下去就完了」

**Day 45 · Q-Learning**
- 更新式：`Q(S,A) ← Q(S,A) + α[R + γ max_a Q(S',a) − Q(S,A)]`
- **区别只有一处：`Q(S',A')` 换成 `max_a Q(S',a)`**
- **它是 off-policy**：估的是「贪心策略」，而执行的是 ε-greedy
- CliffWalking 上的经典现象：Q-Learning 学到**贴着悬崖的最优路径**，
  因为它的目标策略不会乱走

**Day 46 · 这一天的价值在于「为什么」**

要能回答这三个问题，才算真懂：

1. **为什么 Q-Learning 能用旧数据？**
   因为它的更新目标 `r + γ max Q(s',·)` 与「数据是怎么来的」无关 ——
   目标只用到了 `(s, a, r, s')`，不需要 `a'`。
2. **为什么 Sarsa 不能？**
   因为它的目标含 `Q(s', a')`，而 `a'` 是**按当前策略采出来的**。
   策略一变，旧数据的 `a'` 就不再代表当前策略。
3. **off-policy 的代价是什么？**
   需要「覆盖」：要估计的策略用到的 `(s,a)`，行为策略必须访问到。
   否则那些 `Q(s,a)` 永远不更新。

**Day 47 · FrozenLake**
- 随机环境（冰面滑），比 CliffWalking 难：**同样的动作结果不确定**
- 这时 Q-Learning 的方差会明显变大，`ε` 的调度更关键
- 要求跑 4 个 seed，报告均值和标准差 —— **单 seed 的结论一律不认**（Day 24 的教训）

**Day 48 · 论文 2**
- 首选：**Watkins & Dayan (1992) "Q-learning"** —— Q-Learning 的收敛性证明
- 或者：**Rummery & Niranjan (1994)** 关于 Sarsa 的原始报告
- 交付：`docs/paper-02.md`

**Day 49 · W7 收口**
- 一张对比表：Sarsa vs Q-Learning 在 CliffWalking 上的回报曲线、路径图
- 要回答：「在什么任务上你会选 Sarsa 而不是 Q-Learning？」

### 每天的重点提示

**Day 50 · 致命三要素（Deadly Triad）**

这是 P1 最有理论分量的一天。三要素**同时出现**才危险：

```
函数逼近（用网络代替表格）
    +  自举（用估计值更新估计值，即 TD）
    +  off-policy（数据分布 ≠ 目标策略）
    =  可能发散
```

- 缺任何一个都安全：表格法不自举也行、on-policy 的自举也行
- **必须亲手复现一次发散**：去掉目标网络 + 加大学习率，看 Q 值爆到 `inf`
- 只有亲眼见过它崩，才会真正理解目标网络为什么重要

**Day 51 · DQN 三组件**

每个组件治一个病，**要能一一对应**：

| 组件 | 治什么病 | 不装会怎样 |
|---|---|---|
| 经验回放 | 样本相关性（相邻帧高度相关，违反 iid） | 训练震荡，学不动 |
| 目标网络 | 自举的目标在移动（追自己的尾巴） | 发散或震荡 |
| 梯度裁剪 | 偶发的巨大梯度 | 一次异常样本毁掉权重 |

⚠️ 注意 **Day 24 的老规矩**：这些都要用「扫曲线」验证，不能测单点。

**Day 52 · ReplayBuffer**
- 环形缓冲区的实现细节：`pos = (pos + 1) % capacity`
- **验收**：容量为 5 的 buffer 塞进 8 条，采样结果必须是后 5 条
- 坑：`random.sample` vs `torch.randint` —— 前者不能向量化，慢 10 倍以上

**Day 53 · 手写 DQN（约 200 行）**
- 结构：`QNetwork` + `ReplayBuffer` + `epsilon_greedy` + `train_loop`
- **必须手写**，不能调 `stable-baselines3`。后者只用来做 baseline 对比
- 复用自己的资产：`src/engine/` 的训练循环能不能复用？
  大概率不能（RL 没有 epoch / batch 的概念），但**试一试**，能复用多少算多少

**Day 54 · 曲线不涨的排查顺序**（主计划 §三 的原文，要背下来）

```
reward 尺度  →  ε 衰减  →  学习率  →  种子  →  网络初始化
```
- 顺序不能乱：前面的错会伪装成后面的症状
- 交付一份**排查清单**，写清每一步「看到什么现象 → 指向什么问题」

**Day 55 · CartPole 打通 + LunarLander**

- LunarLander 是连续状态 + 稀疏奖励，明显更难，**允许不达标但要记录原因**
- 这台机器是 1660 Ti 6GB，LunarLander 完全跑得动，不会卡显存

**Day 56 · Double DQN + Dueling + P1 收口**

两个改进都指向同一个问题：**Q 值高估**

| 改进 | 做法 | 治什么 |
