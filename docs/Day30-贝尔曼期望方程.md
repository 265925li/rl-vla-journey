## 一、推导：三步

### 1.1 起点

```
G_t = R_{t+1} + γ G_{t+1}                                    （Day 29 的恒等式）
```

### 1.2 第一步：两边取条件期望 `E_π[· | S_t = s]`

```
V^π(s) = E_π[ G_t | S_t = s ]
       = E_π[ R_{t+1} + γ G_{t+1} | S_t = s ]              （代入恒等式）
       = E_π[ R_{t+1} | S_t = s ] + γ E_π[ G_{t+1} | S_t = s ]   （期望线性）
```

**这一步没有任何技巧，只有"期望是线性的"。** 但它把一个问题拆成了两个：
「下一步拿多少」和「之后还剩多少」。

记住这个拆分，后面 MC 和 TD 的区别就是「第二项怎么估」。

### 1.3 第二步：把第一项按「动作 → 下一步」展开

`E[R_{t+1} | S_t = s]` 里的随机性有两层：先按 `π` 抽动作，再按 `P` 走世界。
所以用**全期望公式**（也叫 tower property）一层一层剥：

```
E_π[R_{t+1} | S_t = s]
  = Σ_a π(a|s) · E_π[ R_{t+1} | S_t = s, A_t = a ]                  ← 先对动作求期望
  = Σ_a π(a|s) Σ_{s'} Σ_r p(s', r | s, a) · r                       ← 再对下一状态和奖励求期望
```

最后一行就是"奖励的期望"：对 `(s', r)` 的联合分布加权求和。

**这一步是最容易跳步的地方。** 注意两件事：

1. **`Σ_a π(a|s)` 在外面**，因为动作是 agent 的选择，不依赖世界。
2. **`p(s', r | s, a)` 是联合分布**（Day 29 §3.3 说过），所以它对 `r` 求和就得到期望奖励。

### 1.4 第三步：第二项 —— 这里用掉马尔可夫性

`E_π[G_{t+1} | S_t = s]` 这个写法有问题：**它带着历史**（`S_t = s`）。
但 `G_{t+1}` 是从 `t+1` 时刻开始的未来，凭什么要依赖 `t` 时刻的状态？

答案是：**它确实不依赖，但这需要马尔可夫性来保证。**

```
E_π[ G_{t+1} | S_t = s, A_t = a, S_{t+1} = s' ] = E_π[ G_{t+1} | S_{t+1} = s' ]
                                                  ╰──────────────────────────╯
                                                  这一步用掉了马尔可夫性：
                                                  「给定现在，未来与过去独立」
                                                          = V^π(s')
```

**这是整周唯一一次真正用掉马尔可夫性的地方，一定要看清它用在哪。**

如果没有马尔可夫性，右边会变成 `E[G_{t+1} | 整段历史]`，
它不是一个只依赖 `s'` 的函数，`V^π(s')` 这个记号就没有意义，整个 DP 体系崩塌。
Day 29 实验 E 那个「`V(c)` 不存在」，说的就是这件事。

### 1.5 合起来

把 1.3 和 1.4 拼回去（注意第二项也要先对动作、再对下一状态求期望）：

```
┌─────────────────────────────────────────────────────────────────────┐
│  V^π(s) = Σ_a π(a|s) Σ_{s'} Σ_r p(s', r | s, a) [ r + γ V^π(s') ]  │
└─────────────────────────────────────────────────────────────────────┘
                                        ↑
                            这就是贝尔曼期望方程
```

如果奖励只依赖 `(s, a)`（今天这个环境就是），写成矩阵形式更清爽：

```
V^π(s) = Σ_a π(a|s) [ R[s,a] + γ Σ_{s'} P[s,a,s'] V^π(s') ]
```

**读法**：站在 `s`，按 `π` 抽一个动作 `a`（加权平均），
拿 `R[s,a]`，然后按 `P` 走到某个 `s'`（加权平均），从那里起算值 `γV^π(s')`。

**这就是"一步看 + 递归"**：把一个无限长的求和，压成了"一步"加"下一处的值"。

### 1.6 它到底省掉了什么

不省的话，`V^π(s)` 的定义要这么算：

```
V^π(s) = Σ_轨迹 p(τ) · G(τ)        ← 对所有轨迹求和
```

长度 30、每步 2 个动作的轨迹有 `2^30 = 1,073,741,824` 条。
贝尔曼方程把它换成 `n` 个未知数的线性方程组，`n = 2` 时是 2 个方程。

**从"枚举指数多条轨迹"到"解一个 n 元一次方程组"** —— 这是 DP 存在的全部理由，
也是 Day 32 那个压缩映射要保证的东西。

## 二、把动作边缘化：`P^π` 和 `R^π`

### 2.1 定义

给定 `π` 之后，动作维可以彻底消掉：

```
P^π(s, s') = Σ_a π(a|s) P(s, a, s')          策略下的"状态转移矩阵"
R^π(s)     = Σ_a π(a|s) R(s, a)             策略下的"期望即时奖励"
```

**这两个量只依赖 `π` 和环境，不依赖 `V`。** 所以算一次就够了，
后面所有迭代都在常数矩阵上做。

### 2.2 手算（对着脚本实验 A 核）

`π` 处处是 0.5，所以每个数都是"两个动作的平均"：

```
P^π 第 0 行：0.5×0.9 + 0.5×0.5 = 0.70      0.5×0.1 + 0.5×0.5 = 0.30
P^π 第 1 行：0.5×0.2 + 0.5×0.0 = 0.10      0.5×0.8 + 0.5×1.0 = 0.90

R^π：0.5×1 + 0.5×3 = 2.0        0.5×2 + 0.5×0 = 1.0
```

结果：

```
P^π = [[0.7, 0.3],
       [0.1, 0.9]]              R^π = [2.0, 1.0]
```

实测（脚本实验 A）：**`P^π` 最大差 `0.000e+00`，`R^π` 最大差 `0.000e+00`**。

### 2.3 一条必须自己做的自检

```
P^π 两行的和 = 1.000000000000000 / 1.000000000000000
```

**`P^π` 也必须是随机矩阵（每行和为 1）。** 这条检查 30 秒能做完，
能当场抓住两类错误：`π` 没归一、边缘化时下标搞错。

> 这条和 Day 25 的 `running_var` 是同一类教训：
> 一个量本该满足某条恒等式，就去检查它。**检查成本极低，漏掉的代价极高。**

## 三、矩阵形式：它是一个线性方程组

### 3.1 写成矩阵

把 `n` 个状态的值排成列向量 `V`，第二章的方程对每个 `s` 都成立，写成一起：

```
V = R^π + γ P^π V
```

移项：

```
(I − γP^π) V = R^π
```

**看到这里应该有一个反应：「这是一次方程，可以直接解」。**
后面所有 DP、TD、Q-Learning 都在解（或近似解）这个式子。

### 3.2 为什么 `(I − γP^π)` 一定可逆

不是所有矩阵都敢随便求逆。这里可逆是有保证的，而且证明只有一行：

```
(I − γP)⁻¹ = I + γP + γ²P² + γ³P³ + ...            （Neumann 级数）
```

右边收敛，因为：

```
‖γP‖∞ = γ · max_s Σ_{s'} |P(s,s')| = γ · 1 = γ < 1
```

（`P` 每行和为 1，所以它的 ∞-范数恰好是 1。）

于是级数绝对收敛，`(I − γP)` 可逆，而且

```
‖(I − γP)⁻¹‖∞ ≤ 1/(1−γ)                    γ=0.5 时 ≤ 2
```

**这个级数还顺便解释了 `V` 是什么**：把 `V = (I−γP)⁻¹R` 展开，

```
V = R + γPR + γ²P²R + γ³P³R + ...
  = 「现在的奖励」+「一步之后的奖励」+「两步之后的奖励」+ ...
```

`P^k R` 就是"走 k 步之后期望拿到的奖励"。**所以 `V` 是折扣奖励之和，
而贝尔曼方程只是把这个无限和压成了递归。** 这句话值得停一会儿。

### 3.3 精确解

```
V^π = (I − γP^π)⁻¹ R^π
```

手算（`γ=0.5`）：

```
I − γP^π = [[1 − 0.35,  −0.15  ],      det = 0.65×0.55 − 0.15×0.05
            [ −0.05,     1 − 0.45]]          = 0.3575 − 0.0075 = 0.35

(I − γP^π)⁻¹ = (1/0.35) [[0.55, 0.15],
                         [0.05, 0.65]]

V = (1/0.35) [[0.55, 0.15],   [2]        (1/0.35) [1.25]     [3.571428571]
              [0.05, 0.65]] · [1]   =            [0.75]  =  [2.142857143]
```

分数形式是 **`V = [25/7, 15/7]`**。脚本实测打印的就是这两个（`Fraction` 还原）：

```
V^π        = [3.571428571, 2.142857143]
分数形式   = [25/7, 15/7]
```

### 3.4 验方程的通用办法：残差

把解代回贝尔曼方程右边，看是不是原样回来：

```
R^π + γP^π V = [3.571428571, 2.142857143]
最大残差     = 4.441e-16
```

`4.441e-16` 是 float64 的舍入量级，实质上是 0。

**这个动作要变成肌肉记忆**：以后你推完任何一个方程（包括 Day 31 的最优方程），
第一件事都是「把解代回右边，看残差」。
它比"看起来对不对"强一万倍，而且成本是 3 行代码。

## 四、两条独立的路求同一个 `V^π`

### 4.1 路一：直接解

`np.linalg.solve(I − γP^π, R^π)`，一次到位，误差 0。

代价：`O(n³)`。`n = 10000` 个状态时是 `1e12` 次运算 —— 不可行。
（`n` 是状态数，不是样本数。GridWorld 10×10 才 100 个，还很轻松；
Atari 的像素状态"个数"天文数字，所以 W7 之后必须用函数逼近。）

### 4.2 路二：不动点迭代（= 策略评估）

```
V_0 = 0
V_{k+1} = R^π + γP^π V_k
```

**注意这个式子和贝尔曼方程长得一模一样，唯一区别是左边多了下标 `k+1`。**
意思是："拿上一版的值当作真值，算一遍右边，得到下一版"。

这就是**策略评估**（policy evaluation）—— Day 34 的策略迭代会用到它。

### 4.3 实测：每一轮误差乘上一个不超过 `γ` 的系数

`γ = 0.5`，从 `V = [0, 0]` 出发：

| 轮 | `V[0]` | `V[1]` | 与精确解的误差 | 误差比 |
|---|---|---|---|---|
| 0 | 0.000000000 | 0.000000000 | 3.571e+00 | — |
| 1 | 2.000000000 | 1.000000000 | 1.571e+00 | 0.4400 |
| 2 | 2.850000000 | 1.550000000 | 7.214e-01 | 0.4591 |
| 3 | 3.230000000 | 1.840000000 | 3.414e-01 | 0.4733 |
| 5 | 3.490700000 | 2.065600000 | 8.073e-02 | 0.4895 |
| 10 | 3.568980838 | 2.140417846 | 2.448e-03 | 0.4991 |
| 20 | 3.571426187 | 2.142854759 | 2.384e-06 | 0.5000 |
| 30 | 3.571428569 | 2.142857141 | 2.328e-09 | 0.5000 |
| 40 | 3.571428571 | 2.142857143 | 2.273e-12 | 0.5000 |

**误差比那一列在收敛到 0.5000 —— 正好是 `γ`。**

这条要读得仔细一点：它是「**不超过** `γ`」而不是「等于 `γ`」。
前几轮只有 0.44~0.47，因为误差在两个分量上的比例在变，
而 ∞-范数取的是最大那个分量，最大值换人时比值就会偏小。

**收敛速度完全由 `γ` 决定。** `γ = 0.99` 时每轮只缩 1%，要 100 轮才缩到 37%。
这就是为什么 `γ` 大的任务（比如长期规划）DP 收敛得慢。

### 4.4 `ε` 精度需要多少轮（实测对上了理论）

要 `‖V_k − V^π‖∞ < ε`，需要

```
k ≥ log(ε / ‖e_0‖) / log γ
```

实测：

```
收敛到 1e-12 实际用了 42 轮
理论上界 log(1e-12/3.571429)/log(0.5) = 41.70 → 取整 42 轮
```

**实测 = 上界，卡得死死的。** 换成教科书常用的形式
`k ≥ log(ε(1−γ)/R_max)/log γ` 会得到 42.45 → 43 轮，更松一点
（因为它不利用"你实际的初始误差可能更小"）。

两条路最终：

```
直接解    V = [3.57142857, 2.14285714]
迭代 42 轮 V = [3.57142857, 2.14285714]
差         5.680e-13
```

### 4.5 什么时候必须用迭代

| | 直接解 | 迭代 |
|---|---|---|
| 代价 | `O(n³)` | `O(n²)` 每轮 × `k` 轮 |
| 精度 | 精确 | 几何收敛，可控 |
| 什么时候用 | `n` 小（本周） | `n` 大，或 `P` 根本写不出来（W6） |

**而且迭代法有一个致命优势：它只需要「`P^π V` 这个乘法」，不需要 `P` 本身。**
等你到了无模型的情形（W6），拿不到 `P`，但可以用采样估出 `P^π V`
—— 那就是 TD 学习。**所以迭代形式才是通向 W6 的那条路，直接解只是今天的验算工具。**

## 五、一个不报错的坑：`P` 的方向

### 5.1 两种写法，差一个转置

数学书写的是：

```
V(s) = R(s) + γ Σ_s' P(s'|s) V(s')
```

`numpy` 里 `P^π @ V` 是「行乘列」，而 `P^π[s, s']` 恰好是「行 = s、列 = s'」，
**两者对得上**。

但如果你把 `V` 想成行向量，就会写成 `V @ P^π`，那等价于用了 `P^T`，
解的是另一个方程 `(I − γP^T)V = R`。

### 5.2 实测：差 16%，而且不报错

```
正确的 (I − γP^π)V = R^π     V = [3.571428571, 2.142857143]
写反成 (I − γP^T)V = R^π     V = [3.285714286, 2.714285714]
两个答案差                   0.571428571

把「写反的解」代回正确的方程，残差 = 0.328571
把「正确的解」代回正确的方程，残差 = 4.441e-16
```

相对差 **16.0%**。不会报错、不会 `nan`、不慢 —— 只是答案错。

**为什么这个坑必须讲**：它是"静默失效"里最难查的一类。
你后面写 DQN、PPO，代码里到处是 `P @ V`、`V @ W` 这种形状相近的乘法，
写反了只会看到"训练不收敛"，不会看到任何异常。

**唯一的防线是 §3.4 那个残差。** 写完就代回去，一秒就知道对不对。

## 六、贝尔曼方程给了什么、没给什么

### 6.1 给了

- **把"整条轨迹的期望"压成"一步 + 递归"**：指数 → 多项式。
- **把"评估策略"变成"解线性方程组"**：有唯一解、有精确解、有收敛速率。
- **一个可以离开 `P` 的形式**（迭代形式）：W6 的 TD 就长在这里。

### 6.2 没给

- **它假设 `P` 和 `R` 已知。** 现实里几乎从来不知道。
- **它只回答"这个 `π` 有多好"，不回答"怎么变好"。** 那是 Day 31 的最优方程。
- **它只对"有限状态"直接可用。** 连续状态要么离散化，要么函数逼近。

### 6.3 实测：采样 vs 解方程，差距有多大

如果没有 `P` 和 `R`，只能按 `π` 跑轨迹、取平均（这就是 W6 的蒙特卡洛）。
实测（`γ=0.5`，`V^π(0) = 3.571428571`，单条轨迹回报的 `σ = 1.066276`）：

| 轨迹数 `N` | 40 次重复的估计均值 | 偏差 | 估计值的 std | 实测 `std×√N` |
|---|---|---|---|---|
| 10 | 3.598136 | 0.026708 | 0.299345 | 0.9466 |
| 100 | 3.556322 | −0.015106 | 0.105807 | 1.0581 |
| 1000 | 3.564913 | −0.006516 | 0.035438 | 1.1207 |
| 10000 | 3.570522 | −0.000906 | 0.009556 | 0.9556 |

三条读数：

1. **`std` 按 `1/√N` 缩。** 看最后一列，稳定在 `σ ≈ 1.066` 附近。
   **轨迹多 100 倍，精度只多 10 倍** —— 这是采样的天花板，不是实现问题。
2. **偏差可以忽略（最大 2.67%），波动不能。** 符号还在变，没有系统性方向 ——
   采样估计是**无偏但高方差**的。`N=10` 时 `std` 有 0.299，而真值才 3.571。
3. **解方程一次就是精确的。** 长度 30 的轨迹要穷举 `2^30 = 1,073,741,824` 条。

**所以：有 `P` 和 `R` 就解方程（本周）；没有就采样（W6）。**
采样不是更现代的方法，它是没模型时**唯一**能做的事。
今天把有模型这条路走通，就是为了给 W6 一个对拍对象 ——
那时你可以问"我的 TD 估计离精确值差多少"，而不是"看起来收敛了"。

## 七、今天的过关标准（仍然是纸上的）

**① 不看讲义，把 §1.2–§1.5 的推导写一遍。**

写的时候注意三处不能跳：
- 1.3 的「全期望公式」两步（先对 `a`，再对 `s', r`）
- 1.4 的「去掉历史」那一步 —— **在哪用掉了马尔可夫性**

### 8.3 昨天那个 `1/(1+γ)`，今天两行就推出来了

Day 29 §2.4 里，为了说明「马尔可夫性被破坏」的严重程度，
我们量了 `V(A) − V(B)`，并用代码发现它等于 `1/(1+γ)`。当时是**先看数、后找理由**。

今天有了贝尔曼方程，两行就够。Day 29 那条链的方程是：

```
V(A) = 1 + γV(B)
V(B) = 0 + γV(A)
```

两式**相减**，令 `d = V(A) − V(B)`：

```
d = 1 + γV(B) − γV(A) = 1 − γ(V(A) − V(B)) = 1 − γd
d(1 + γ) = 1        →        d = 1/(1+γ)
```

`γ=0.9` 时 `1/1.9 = 0.526316`，与 Day 29 实测完全一致。

**这件事的意义不在于多了一个证法，而在于它示范了一件事**：
昨天需要"跑代码才发现的常数"，今天用方程就能推出来。
**方程比数字更有解释力** —— 这也是这一周值得花在推导上的原因。

顺带把 Day 29 那句"下界 0.5"也说清了：
`γ ∈ [0,1)` → `1/(1+γ) ∈ (0.5, 1]`，`γ→1` 时取到下界 0.5。
