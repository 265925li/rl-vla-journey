## 1. 先诊断：你的模型过拟合了吗？

先看 Day 13 那一跑的完整记录（`outputs/2026-10-22_170822_mnist_full10/history.json`）：

| epoch | train_loss | train_acc | val_loss | val_acc | gap |
|---|---|---|---|---|---|
| 1 | 0.2997 | 0.9137 | 0.1489 | 0.9553 | **−4.16** |
| 2 | 0.1076 | 0.9677 | 0.1105 | 0.9672 | +0.06 |
| 3 | 0.0757 | 0.9766 | 0.0955 | 0.9712 | +0.54 |
| 4 | 0.0532 | 0.9843 | 0.0840 | 0.9748 | +0.95 |
| 5 | 0.0412 | 0.9874 | 0.0904 | 0.9727 | +1.47 |
| 6 | 0.0304 | 0.9907 | 0.0789 | 0.9792 | +1.15 |
| 7 | 0.0223 | 0.9937 | 0.0792 | 0.9782 | +1.55 |
| 8 | 0.0179 | 0.9949 | 0.0824 | 0.9785 | +1.64 |
| 9 | 0.0131 | 0.9969 | 0.0787 | 0.9790 | +1.79 |
| 10 | 0.0096 | 0.9979 | 0.0773 | 0.9793 | **+1.86** |

（`gap = train_acc − val_acc`，单位是百分点）

### 1.1 三条证据

**证据一：loss 的差距在拉大**

```
第 2 轮：train 0.1076   val 0.1105   → 差 0.003（几乎一样）
第 10 轮：train 0.0096   val 0.0773   → 差 8.05 倍
```

模型的训练 loss 掉到了验证 loss 的 **1/8**。这不是"学得更好"，
这是"训练集上的表现已经不能预测新数据上的表现"了 —— 过拟合的定义。

**证据二：准确率挤不出空间了**

```
第 6 轮  val_acc = 0.9792
第 10 轮 val_acc = 0.9793     ← 多训 4 轮，涨了 0.0001
```

而验证集是 6000 条，**正确 1 条 = 0.0167%**。
所以 0.0001 的差距 = **0.006 条样本**，纯属四舍五入的噪声。
后面 4 轮在验证集上**一点用都没有**。

**证据三：gap 单调往上爬**

```
+0.06 → +0.54 → +0.95 → +1.47 → +1.15 → +1.55 → +1.64 → +1.79 → +1.86
```

（第 5 轮那个 1.47 是个小回落，之后继续爬）

1.86 个百分点 ≈ 验证集上 112 条样本的差距。模型在训练集上多认对 112 条，
在验证集上没有相应的收获 —— 那 112 条是"背下来的"。

**结论：过拟合确实存在，但不算严重。** 测试集 98.00% 说明泛化还行，
只是"最后几轮纯属浪费"。这个判断很重要：过拟合不是"有/没有"，
是"到什么程度、值不值得治"。

### 1.2 陷阱：第 1 轮的 gap 为什么是负数？

`gap = -4.16`，train_acc 比 val_acc 还低 4 个点。这看着像"模型在训练集上表现更差"，
其实是个**统计学假象**：

| | train_acc | val_acc |
|---|---|---|
| 在哪些数据上算 | 54000 条训练集 | 6000 条验证集 |
| 用的是哪个时刻的模型 | **整个 epoch 里所有时刻的平均** | **epoch 结束后那一刻** |

第 1 轮开始时模型是随机权重（准确率约 10%），跑到第 422 步才到 95%。
中间那些很差的步骤把平均值拉下去了，所以 train_acc=0.9137。
而 val_acc 是这 422 步都跑完之后，用最终的模型算的，得到 0.9553。

**两个数的"时间口径"不一样，直接比就是不公平的。**

```
train_acc = 这一轮的平均水平（从很笨到比较聪明）
val_acc   = 这一轮结束时的瞬时水平
```

所以：**gap 从第 2 轮开始看才有意义。第 1 轮的负数不要解读。**

这个坑在别的场景也会遇到 —— 只要你在"训练中途"和"训练结束"之间比较数字，
就要先问一句：这两个数是在同一时刻量的吗？

### 1.3 陷阱：val_acc 的第 4 位小数是假的

6000 条验证集，1 条 = 0.0167%。所以：

| 这个数字 | 真实含义 |
|---|---|
| 0.9792 | 5875 条对（5875/6000 = 0.979167） |
| 0.9793 | 5876 条对（5876/6000 = 0.979333） |
| 0.9782 | 5869 条对 |
| 0.9807 | 5884 条对 |

`0.9792` 和 `0.9793` 之间只差 **1 条样本**。它们可能是同一个模型。
**报数字时写 4 位小数是骗自己**，写 2 位（98%）就够了。

但这引出一个真问题：既然 acc 这么粗，那用什么当"有没有进步"的判据？
答案是 **loss**（连续值，分辨率高得多）。第 5 节会实测这个差别有多要命。

## 2. 过拟合到底在发生什么

不用背定义，看数字：

```
参数个数  = 203530
训练样本  = 54000
商        = 3.77      ← 平均每张图"分到"3.77 个参数
```

听起来还好？但换个角度：MNIST 只有 10 个类别，一张 28×28 的图的信息量
远小于 784 个独立数字（相邻像素高度相关）。模型的**有效自由度**远大于"10 类"需要。

所以模型有足够的"容量"去做这件事：

```
不是"学会把 7 认成 7"，而是"记住这 54000 张图各自对应哪个标签"
```

前者能推广到新图，后者不能。当训练 loss 一路降到 0.0096（几乎为零）时，
它已经在做后者了。

**一句话记住**：过拟合 = 模型把训练集里的**噪声**也当成了规律。

（为什么噪声会被学进去？因为噪声在训练集上是"确定"的 —— 那个像素就是那个值。
模型没法区分"这是 7 的特征"还是"这是扫描时的手抖"。）

### 三种治法的思路

| 武器 | 一句话原理 | 类比 |
|---|---|---|
| Dropout | 每次随机关掉一部分神经元，逼模型不依赖任何单个神经元 | 不许一个人扛全队，人人都得会 |
| Weight Decay | 惩罚大权重，逼模型用"更平缓"的函数 | 不许把结论建在一个极端证据上 |
| Early Stopping | 在验证集开始变差时停下 | 见好就收 |

## 3. 三个武器，一个一个算

### 3.1 Dropout

#### 它做的运算

训练时，对每个神经元的输出（假设是 `x`），抛一枚硬币：

```
以概率 p      →  输出 0
以概率 1-p    →  输出 x / (1-p)
```

**关键：`p` 是"丢弃概率"，不是"保留概率"。** `dropout=0.2` 是丢掉 20%。

**关键：活着的那部分要除以 `(1-p)`。** 这一步叫 inverted dropout，为什么必须除？

```
假设某个神经元输出恒为 x = 10，p = 0.5

不除：E[输出] = 0.5 × 0 + 0.5 × 10 = 5      ← 期望值变成了原来的一半！
除以：E[输出] = 0.5 × 0 + 0.5 × (10/0.5) = 10   ← 期望值不变 ✅
```

不除的话，训练时下一层收到的输入尺度只有推理时的一半，
训练和推理的行为不一致，模型会学歪。除以 `(1-p)` 让**期望值保持不变**，
于是推理时什么都不用做（这就是为什么叫 "inverted" —— 把缩放挪到了训练阶段）。

用 PyTorch 的话，`nn.Dropout(0.2)` 帮你做完这两步，你只需要保证
**训练时 `model.train()`、推理时 `model.eval()`**。

#### 为什么这样能防过拟合

每一步训练，模型都是在一个**不同的子网络**上训练（因为丢的神经元每次都不同）。
一个有两层 256 宽的网络，可能的子网络有 `2^512` 种。

效果是：**没有任何一个神经元可以"垄断"某个特征**。
如果某个神经元专门记"第 137 号像素是黑色就判 8"，
它有一半概率被丢掉，这条规则就不成立了 —— 模型被迫学更冗余、更鲁棒的特征。

推理时，用的是完整的网络，它近似等于"所有子网络预测的平均"。
（严格说是几何平均的近似，这是 Dropout 原论文的论证方式。）

#### 三个必须知道的陷阱

**陷阱 1：忘了 `model.eval()`**

这是 Dropout 最经典的坑。如果推理时还在丢神经元：

- 不报错
- 准确率会掉，但**掉多少取决于运气**（每次前向丢的都不一样）
- 你会以为"模型训崩了"，其实是评估代码写错了

Day 13 的时候 `model.eval()` 注释里写着"对纯 MLP 没有影响" ——
**从今天起它有影响了**。这两行在 `train_mnist.py` 里本来就写好了：

```python
def train_one_epoch(...):
    model.train()   # ← 打开 Dropout
    ...

@torch.no_grad()
def evaluate(...):
    model.eval()    # ← 关掉 Dropout，这一步现在真的在起作用
```

**陷阱 2：开了 Dropout 之后，train_loss 可能**高于** val_loss**

这个会让第一次用 Dropout 的人非常困惑。看今天实测的 B 组（`dropout=0.2`，前两轮）：

```
epoch 1  train loss=0.3161 acc=0.9081  |  val loss=0.1504 acc=0.9547  |  gap=-0.0466
epoch 2  train loss=0.1305 acc=0.9609  |  val loss=0.1152 acc=0.9677  |  gap=-0.0068
```

train 比 val **差**（loss 更高、acc 更低）。这不是 bug，两个原因叠加：

1. 训练时每步都在随机丢 20% 的神经元，任务**变难了**，loss 自然更高
2. 验证时 Dropout 关掉，用的是满血网络，任务**变简单了**

所以：**加了 Dropout，gap 变负是好事，不是坏事的反面。**
判据要换：不看 gap 的正负，看 **val_loss 有没有下降**。

**陷阱 3：`dropout=1.0`**

所有神经元永远被丢光，模型输出恒为 0，准确率恒为 10%（瞎猜），
**一个错都不报**。所以我在 `MLP.__init__` 和 `Config.__post_init__`
两处都加了范围校验，让它在读配置的那一秒就炸。

> 这也解释了一条通用原则：**凡是"配置写错会静默失效"的参数，都要在入口校验。**
> 你现在应该能体会为什么 `Config.__post_init__` 里堆了那么多 `if`。

### 3.2 Weight Decay（L2 正则）

#### 它做的运算

原损失函数加一项惩罚：

```
L_total = CE(logits, y) + (λ/2) · Σ w²
                          └──────────┘
                          weight_decay 就是这里的 λ
```

求导（这一步你应该能秒推）：

```
∂L_total/∂w = ∂CE/∂w + λ·w
```

所以梯度里多了一项 `λw`，参数更新变成：

```
w  ←  w − lr·(∂CE/∂w + λw)
   =  w − lr·∂CE/∂w − lr·λ·w
```

注意最后那一项：**每更新一步，`w` 就额外缩小 `lr·λ` 倍**。
这就是"weight decay"（权重衰减）这个名字的由来 —— 它做的就是让权重不断变小。

而"权重变小"和"函数变平滑"是等价的（在局部看，`w` 越小，
输入扰动引起的输出变化越小）。而**平滑的函数更不容易拟合噪声**。

算一下我们的配置下这个衰减有多快：

```
lr = 0.1, λ = 5e-4
每步缩小系数 = 1 − lr·λ = 1 − 5e-5 = 0.99995
一个 epoch 422 步 → 0.99995^422 = 0.9791
10 个 epoch       → 0.9791^10 ≈ 0.809
```

**光靠衰减，10 轮后权重会被压到 80.9%。**

但实测降到了 **58.4%**（`wnorm` 28.851 → 16.845，−41.6%）。为什么比理论狠这么多？

因为**我们开着 `momentum=0.9`**。动量对梯度的等效放大是 `1/(1-0.9) = 10 倍`，
而 `λw` 是混在梯度里的，所以它**也被放大了 10 倍**。

> **这是个值得单独记住的交互：`weight_decay` 和 `momentum` 会互相放大。**
> 你在 yaml 里写 `weight_decay: 5e-4`，实际作用效果远不止那个数字。
> 换优化器（比如关掉 momentum）时，同一个 wd 值的效果会完全不同。

这就是为什么我加了 `weight_norm()` 这个指标 ——
开了 wd 之后这个数应该变小，**没变小就说明 wd 没生效**。

#### 陷阱：SGD 里它是 L2，Adam 里它不完全是

这是个值得提前知道的坑（现在不用管，等你用 Adam 时会撞上）：

- **SGD**：`g += λw` 然后统一更新。这跟"在损失里加 L2 项再求导"是**完全等价**的
- **Adam**：它会把梯度除以二阶矩（`g / sqrt(v)`）。`λw` 这一项也被除了，
  于是**大权重的衰减被压小了**，效果与 L2 不等价
- **AdamW**：把 `λw` 从梯度里拿出来，直接作用在参数上（解耦），这才是"真 wd"

一句话：**看论文里写 "weight decay" 的时候，要确认它用的是 SGD 还是 Adam/AdamW。**
我们今天用的是 SGD，所以 `weight_decay=5e-4` 就是标准 L2。

#### 陷阱：λ 太大会欠拟合

`λ` 把权重往 0 拉，拉过头了模型就"记不住任何东西"，train 和 val 双双变差。
这时候 gap 会很小 —— **但你不能说"没有过拟合所以很好"**。
判断依据永远是 **val_loss / val_acc 的绝对值**，不是 gap 的大小。

（这是最容易搞混的一点：gap 小 ≠ 模型好。一个瞎猜的模型 gap 恒为 0。）

### 3.3 Early Stopping（早停）

#### 它做的事

每一轮看验证集指标，如果连续 `patience` 轮都没有改善，就停下。

`patience` 是"耐心值"，含义是"我愿意再等几轮看看"。
`patience=3` = 连续 3 轮没进步就停。

#### 陷阱 1：判据选 acc 还是 loss？—— 结论会**相反**

这是今天最有意思的一个发现。用 Day 13 的真实数据（patience=3）：

**按 val_acc 判：**

```
ep6  0.9792  ← 新高，计数器归零
ep7  0.9782  没超过 0.9792 → bad = 1
ep8  0.9785  没超过        → bad = 2
ep9  0.9790  没超过        → bad = 3  ← 停！
```

**按 val_loss 判：**

```
ep6  0.0789  ← 新低，归零
ep7  0.0792  没低于 0.0789 → bad = 1
ep8  0.0824  没低于        → bad = 2
ep9  0.0787  低于 0.0789   → bad = 0  ← 重置！
ep10 0.0773  低于 0.0787   → bad = 0  ← 还在变好
```

**同一份数据，acc 说"ep6 之后就没进步了"，loss 说"一直在进步"。**

谁对？看 1.3 节算过的：acc 的 0.9782 / 0.9785 / 0.9790 之间的差距
只有几条样本，本来就是噪声。**loss 是连续值，更能反映"模型真的在变好还是变差"。**

所以默认判据用 `loss`。但 acc 也不是完全没用 ——
你最终的交付目标是准确率，所以**最后还是要看 acc**，只是不要拿它当早停判据。

代码里我让两个计数器**同时更新**，日志会同时打印两个值，
就是为了让你自己看见这个矛盾：

```
⏹ 早停：按 acc 判据已连续 3 轮没改善（patience=3）
   另一个判据此时是：val_acc 连续 3 轮没新高、val_loss 连续 0 轮没新低
```

#### 陷阱 2：`1e-6` 这个容差

```python
improved_by_loss = va_loss < best_val_loss - 1e-6
```

为什么不直接写 `va_loss < best_val_loss`？

因为浮点数的抖动是真实存在的。假设 loss 是 `0.07890000` 和 `0.07889999`，
差 `1e-8`，肉眼看是同一个数，但如果判成"有进步"，计数器就会一直被重置，
**早停永远不触发**（等于这个功能白写了）。

`1e-6` 是"最小可感知改善"：小于它的改善当成没有。
这个数字没有理论依据，是工程经验 —— 关键是**要有**这个容差，
而且要意识到它的存在（不然你会困惑"为什么 loss 变了但没算进步"）。

#### 陷阱 3：停下来了，权重必须是"最好的那一版"

早停触发的那一轮，模型权重**已经变差了**（正是因为它变差才触发早停）。
所以绝对不能拿当前权重去测测试集。

正确的做法（Day 13 就已经写好了）：训练过程中每轮检查，
验证集创新高就存一份 `best.pt`，最后 `load_state_dict` 回来再测。

```python
if improved_by_acc:
    best_acc = va_acc
    torch.save(model.state_dict(), best_path)   # 存盘
...
model.load_state_dict(torch.load(best_path, map_location=device))  # 最后载回来
```

> ⚠️ 这里有个我刚写代码时差点踩的 bug，值得记：
> `improved_by_acc` 必须在**更新 `best_acc` 之前**算。
> 如果写成先 `best_acc = va_acc` 再 `va_acc > best_acc`，
> 后者**恒为 False**（因为已经相等了），早停计数器会一路涨，第 2 轮就停。
> 这种 bug 不报错，只是行为错 —— 属于最难查的一类。

## 4. 今天的代码改了什么（逐处读）

一共四处。每一处我都写了逐行注释，这里讲"为什么这么改"。

### 4.1 `src/models/mlp.py` — MLP 支持 dropout

**改动**：`__init__` 多一个参数 `dropout: float = 0.0`，
在 `Linear → 激活` 之后插入 `nn.Dropout(dropout)`。

```python
for _ in range(n_layers - 1):
    layers.append(nn.Linear(last, hidden))
    layers.append(act_cls())
    if dropout > 0:
        layers.append(nn.Dropout(dropout))   # ← 新增
    last = hidden
```

三个要点：

1. **`dropout=0` 时不插入**，所以 Day 13 的行为一个字都没变
   （这就是"默认值要选不改变原行为的那一个"）
2. **顺序是 Linear → 激活 → Dropout**。放激活前面也能用，但惯例是后面。
   原因：ReLU 之后的 0 本来就是死的，再丢它等于没丢（白丢），
   丢在 ReLU 前面才等价于"这个神经元这次不存在"。
3. **`nn.Dropout` 没有参数**。所以 `count_params_manual()` **一个字都不用改**，
   `203530` 这个数还是 203530。这是个值得记住的事实：
   **参数量不变，模型行为变了。** 参数量不是衡量模型复杂度的唯一指标。

（顺带：`MLP` 里也加了 `0 <= dropout < 1` 的校验，和 `Config` 里重复了。
重复校验不是坏事 —— `MLP` 也可能被别的地方单独 new 出来，不经过 `Config`。）

### 4.2 `src/utils/config.py` — 两个新字段 + 校验


### 4.3 `scripts/train_mnist.py` — 早停 + 两个新指标

**改动一**：`build_model` 把 `dropout` 传下去（一行）。

**改动二**：新增 `weight_norm()` 函数，统计 `sqrt(Σ p²)`。
进 `history` 的 `wnorm` 字段，用来验证 wd 有没有真的生效。

**改动三**：`rec` 里加了两个字段

```python
"gap": round(tr_acc - va_acc, 6),      # 过拟合的直接读数
"wnorm": round(weight_norm(model), 6), # 看 wd 有没有生效
```

两者都是**确定性**的值，所以不影响 `history.json` 的复现性对比。
（这是 Day 13 定下的规矩：只有墙钟时间不能进去。）

**改动四**：早停逻辑，两个计数器

```python
best_val_loss = float("inf")
bad_by_acc = 0
bad_by_loss = 0

for epoch in ...:
    ...
    improved_by_acc = va_acc > best_acc          # 必须在存盘前算！
    if improved_by_acc:
        best_acc = va_acc
        torch.save(model.state_dict(), best_path)

    improved_by_loss = va_loss < best_val_loss - 1e-6
    bad_by_acc = 0 if improved_by_acc else bad_by_acc + 1
    bad_by_loss = 0 if improved_by_loss else bad_by_loss + 1
    if improved_by_loss:
        best_val_loss = va_loss

    if cfg.early_stop_patience > 0:
        bad = bad_by_acc if args.es_metric == "acc" else bad_by_loss
        if bad >= cfg.early_stop_patience:
            stopped_at = epoch
            break
```

注意 `bad_by_acc = 0 if improved else bad + 1` 这个写法 ——
它是"要么归零、要么加一"，写成 `if/else` 也一样，只是这样更短。
**读的时候不要看花眼**：`0 if A else B` 是"如果 A 则取 0，否则取 B"。

**改动五**：`plot_curves` 从两张图变三张，第三张是 gap。

### 4.4 `scripts/run_ablation.py` — 新增，一次跑四组

这个脚本是今天唯一"从零新增"的东西，它教的是**做实验的方法**：

```python
GROUPS = [
    {"name": "A_baseline",     "dropout": 0.0, "wd": 0.0},
    {"name": "B_dropout",      "dropout": 0.2, "wd": 0.0},
    {"name": "C_weight_decay", "dropout": 0.0, "wd": 5e-4},
    {"name": "D_both",         "dropout": 0.2, "wd": 5e-4},
]
```

三个设计原则：

1. **A 是参照物**。没有 A，B/C/D 的数字毫无意义（"98.1% 算好吗？"没参照就答不了）
2. **B 和 C 各只改一个变量**。这样"谁起的作用"才有答案。
   如果只跑 A 和 D，就算 D 变好了，你也不知道是 dropout 还是 wd 的功劳
3. **四组用同一个 seed**。否则差异里混进了"这次运气好不好"

还有一处实现细节值得看：**为什么用 `subprocess` 开子进程跑，而不是在同一进程里循环？**

```python
proc = subprocess.run(cmd, cwd=ROOT)
```

因为 PyTorch 的随机状态、CUDA 上下文在同一个进程里会**残留**。
第二组实验用的"随机初始化"其实已经被第一组影响过了，
四组就不是真正独立的。开新进程 = 全新随机状态。

代价是每组重新 import torch、重新读数据，多花几秒。**值得。**

### 实测结果（四组，seed 都是 0，各跑 10 轮）

| 组 | dropout | wd | 末轮 train | 末轮 val | gap | best val loss | 权重范数 | **test acc** |
|---|---|---|---|---|---|---|---|---|
| **A_baseline** | 0 | 0 | 0.9979 | 0.9793 | +0.0186 | **0.0773** | 28.851 | **0.9800** |
| B_dropout | 0.2 | 0 | 0.9893 | 0.9750 | +0.0143 | 0.0800 | 27.419 | 0.9775 |
| C_weight_decay | 0 | 5e-4 | 0.9859 | 0.9737 | +0.0122 | 0.0904 | **16.845** | 0.9782 |
| D_both | 0.2 | 5e-4 | 0.9788 | 0.9728 | **+0.0059** | 0.0894 | 17.612 | 0.9754 |

#### 结论一：在 wd=5e-4 这个剂量下，三个正则化都让 test acc 下降

```
A 0.9800  ←  最好的
C 0.9782  −0.18 个百分点
B 0.9775  −0.25 个百分点
D 0.9754  −0.46 个百分点    ←  加得最多，掉得最狠
```

#### 补测：剂量扫描推翻了这个结论的一半 ⚠️

> 这部分是**当天下午补做**的。最初只测了 `wd=5e-4` **一个点**就下了
> "正则化没用"的结论 —— 那是个不完整的结论。补扫剂量之后发现完全不是这么回事：

| wd | test acc | best val_loss | 权重范数 | gap（末轮） |
|---|---|---|---|---|
| 0（基线） | 0.9800 | 0.0773 | 28.851 | +0.0186 |
| 5e-5 | 0.9804 | 0.0766 | 26.127 | +0.0178 |
| **1e-4** | **0.9812** | **0.0733** | 23.998 | +0.0166 |
| 5e-4 | 0.9782 | 0.0904 | 16.845 | +0.0122 |

**这是一条倒 U 型曲线：**

```
test acc
 0.9812 |            ●  ← 1e-4 峰顶
 0.9804 |      ●        ← 5e-5
 0.9800 |  ●            ← 0（基线）
 0.9782 |                    ●  ← 5e-4 掉下悬崖
        +--------------------
         0    5e-5  1e-4  5e-4   wd
```

`val_loss` 同样呈 U 型（越低越好，所以是反过来）：`0.0773 → 0.0766 → 0.0733 → 0.0904`。

**所以正确的说法是：**

- ❌ "正则化没用" —— 错
- ❌ "正则化有用" —— 也不对
- ✅ **"剂量在 5e-5 ~ 1e-4 之间有用，超过 1e-4 开始反噬"**

1e-4 时 `val_loss` 从 0.0773 降到 0.0733，**降了 5.2%**，这是真实的改善。

**但 test acc 那 0.12 个百分点不能当回事**：

```
测试集 10000 条，p ≈ 0.98
标准误 SE = √(p(1-p)/n) = √(0.98 × 0.02 / 10000) ≈ 0.0014 = 0.14 个百分点

0.9812 − 0.9800 = 0.12 个百分点  <  0.14
```

**差距比一个标准误还小，统计上不显著。** 换句话说：重跑一次换个 seed，
这个"提升"可能就没了。而 `val_loss` 降 5.2% 是连续量的改善，噪声小得多，这个更可信。

#### 这条补测为什么比原来那个结论值钱

它暴露了一个方法论错误，而这个错误你以后一定会犯第二次：

> **一个超参数只测一个值，什么都说明不了。**
> 你永远不知道测的那一个点是在峰顶、在坡上、还是已经掉下悬崖了。

原来那个"三个全输"的结论错在哪？错在**把 5e-4 这个剂量下的结果，当成了方法本身的性质**。
实际上 5e-4 是**过量剂量** —— wnorm 从 28.851 压到 16.845（−41.6%），
模型被捆得太死，连该学的规律也学不进去了。这就是 3.2 节说的"λ 太大会欠拟合"。

**"调参"的本质就是扫曲线，找峰值位置** —— 不是"试一下看有没有用"。

**这不是实验失败，这是今天最值钱的一个结论。**

#### 结论二：但两个武器**确实都生效了**

先证明它们不是"白加了"：

**weight decay 生效的证据** —— 权重范数

```
A（无 wd）：28.851
C（有 wd）：16.845     降了 41.6%
```

`λw` 那一项真的在起作用，把权重压掉了四成。3.2 节算过纯衰减只能压到 80.9%，
实测压到 58.4% —— 多出来的那部分是 **`momentum=0.9` 把 `λw` 也放大了 10 倍**造成的。

**dropout 生效的证据** —— train 侧变难了

```
A（无 dropout）：train_acc 0.9979   train_loss 0.0096
B（有 dropout）：train_acc 0.9893   train_loss 0.0711
```

训练集上的准确率从 99.79% 掉到 98.93%，loss 涨了 7 倍。
这正是 dropout 的预期效果：**训练变难了**（每步都在随机丢人）。
（注意 B 组 train_loss 0.0711 和 val_loss 0.0894 差距很小 ——
3.1 节解释过，这不是 bug。）

**gap 也确实被压住了**：0.0186 → 0.0059（D 组），压掉了 2/3。

#### 结论三：所以问题出在哪？—— 这个过拟合**很轻，收益窗口很窄**

回到第 1 节的证据：`gap` 从 +0.54 爬到 +1.86，看着像在恶化。
但当时我们漏看了一个数：

```
baseline val_loss：
    ep6  0.0789   ←  触底
    ep10 0.0773   ←  又降了，还在变好
```

**gap 在扩大的同时，val_loss 还在下降。** 这意味着什么？

模型确实在训练集上"记得更细"（gap 扩大），
但它多学的那些东西**对验证集也是有用的**（val_loss 下降）。

真正的恶性过拟合长这样：

```
ep1   train 0.05  val 0.12
ep5   train 0.01  val 0.15   ← val 开始往上走了
ep10  train 0.001 val 0.28   ← 越来越差，这才叫过拟合到伤泛化
```

我们的情况是 —— **val_loss 还在降，泛化没被伤到。**
这叫"良性过拟合"：模型有富余容量，学得细一点没坏处。

**病很轻，所以药的可操作窗口很窄。** 剂量刚好（1e-4）能挤出一丁点收益，
剂量一过量（5e-4）就立刻反噬：

- dropout 0.2 把有效容量砍了一刀 → 连该学的规律也学不全 → test acc 掉 0.25
- wd 5e-4 把权重压掉 41.6% → 模型能表达的函数变简单了 → test acc 掉 0.18
- 两个一起上 → 掉 0.46
- 而 wd 1e-4（压掉约 17%）→ 升 0.12（不显著）

**这就是"过度正则化"（over-regularization）。** 它的症状和欠拟合一样，
但成因不同：欠拟合是模型太小，过度正则是**你把一个够用的模型强行捆住了**。

> 一句话：**正则化是刹车，不是方向盘。** 它只能让模型变"笨"，
> 不能让它变"聪明"。所以只有在"模型确实太自由、在记噪声"的时候才踩，
> 而且要知道**该踩多深**。踩过头比不踩还糟。

#### 结论四：下一步该干什么

记住了这张表，下面是**这一跑真正教给你的东西**（按重要性排）：

1. **一个超参数只测一个值，等于什么都没测出来。** 这是今天最贵的一课 ——
   我自己就先犯了这个错（只测 wd=5e-4 就下结论），补扫剂量后结论直接反了一半。
   以后凡是"某某设置有没有用"的问题，答案都是**扫一条曲线**，不是取一个点。
2. **诊断出过拟合，不等于应该治它。** 判据要两条一起看：
   - `gap` 扩大：警报响了
   - `val_loss` 绝对值有没有变差：**判决书**
3. **正则化只能做减法。** dropout 减容量、wd 减权重、早停减轮数。
   所以它的适用前提是"模型容量过剩"。我们的模型只是**轻微**过剩，
   所以最优剂量下也只能挤出 0.12 个百分点（还不显著）。
4. **MNIST + MLP 的天花板就在 98% 附近。** 即使扫到最优剂量（wd=1e-4）
   也只到 **0.9812**。这个架构的输入形式（摊平成 784 个独立数字，
   丢掉了"相邻像素相关"这个信息）决定了它到顶了。
   **想真正往上必须换架构（CNN），调正则化只能在小数点后第二位打转。**
5. **`wnorm` 这个指标做对了** —— 它是"wd 有没有生效"的直接证据。
   以后调任何超参数，都要先找这样一个"能证明它真的生效了"的观测量。
   否则你可能调了半天，其实参数根本没传到。

> 顺带一个不要过度解读的点：D 组的 wnorm（17.612）比 C 组（16.845）**大**。
> 直觉上"dropout + wd 应该压得更狠"，实际不是。原因是 dropout 让梯度
> 噪声变大，每个参数收到的有效梯度信号变弱，权重长得更慢；但它同时也
> 让激活值的尺度变化，两者互相干扰。
> **单次实验的小差异不要硬编故事** —— 要下结论得跑多个 seed 看方差。

### 早停判据实测（同一份数据，两种判据）

同一个 seed、同一份数据、同样的 `patience=3`，只换判据：

| 判据 | 实际跑了几轮 | 停在哪 | best val acc | **test acc** |
|---|---|---|---|---|
| `--es-metric acc` | **9** | ep9 | 0.9792 | **0.9782** |
| `--es-metric loss` | **10**（没触发） | 跑满 | 0.9793 | **0.9800** |

**第 3.3 节的推演完全成立：**

```
按 acc 判：ep6=0.9792(新高) → ep7 0.9782(1) → ep8 0.9785(2) → ep9 0.9790(3) → 停
按 loss 判：ep6=0.0789(新低) → ep7 0.0792(1) → ep8 0.0824(2) → ep9 0.0787(重置) → ep10 0.0773(重置)
```

acc 判据在第 9 轮停下，**省了 1 轮 8.9 秒，代价是 test acc 掉了 0.18 个百分点**（18 条测试样本）。

**用 8.9 秒换 0.18 个百分点的准确率，这笔账怎么算都亏。**

#### 还暴露了一个更深的问题：验证集上的"最好"不等于测试集上的"最好"

仔细看这两行的对比：

```
es_acc  停在第 9 轮，best.pt 存的是 ep6 的权重（val_acc 0.9792）
es_loss 跑满 10 轮，best.pt 存的是 ep10 的权重（val_acc 0.9793）
                                        ↑ 验证集上只差 1 条样本
                    测试集上：0.9782  vs  0.9800   ↑ 差了 18 条
```

**验证集上只差 1 条，测试集上差了 18 条。**

原因：你是在 6000 条验证集上"挑出表现最好的那一版"。
6000 条里的"最好"，有很大成分是**这一版恰好在这 6000 条上比较顺手**。
换到 10000 条测试集上，这个"顺手"就消失了。

有个正式的名字：**对验证集过拟合**（validation-set overfitting，也叫选择偏差）。

这也是为什么：
- `val_acc` 的 4 位小数毫无意义（1.3 节算过）
- 测试集**只能用一次**（`mnist.py` 里那段注释讲的就是这个）
- 同样的道理，在 RL 里"挑 reward 最高的那个 checkpoint"也有一样的问题

#### 那早停还有用吗

有用，但要看**什么时候**用：

| 场景 | 早停的作用 |
|---|---|
| 训练 100 轮、第 30 轮就开始过拟合 | 省 70 轮，**非常值** |
| 训练 10 轮、第 9 轮才刚饱和（我们的情况） | 省 1 轮，**毫无意义** |

早停的价值和"过拟合出现的早晚"成正比。我们这个模型 10 轮才刚摸到天花板，
早停根本没有发挥空间。**换到 P1 里那些训练上百轮的模型，它才会变成刚需。**

## 6. 三句话带走

**第一句：过拟合的判据是 loss 的差距，不是 acc 的高低。**

```
train_loss 0.0096  vs  val_loss 0.0773    → 差 8 倍，这才是过拟合的读数
train_acc 99.79%   vs  val_acc 97.93%     → 差 1.86 个百分点，是同一个事实的另一种说法
```

`gap` 是警报，**`val_loss` 的绝对值才是判决书**。

**第二句：正则化是刹车，不是方向盘 —— 而且必须知道该踩多深。**

它只能让模型变"笨"，不能让它变"聪明"。所以：
- 病重（val_loss 抬头）→ 踩下去有用
- 病轻（我们：val_loss 还在降）→ 踩了收益极小
- 踩过头（wd 5e-4）→ 比不踩还糟（0.9800 → 0.9782）

同一个 wd，扫一条剂量曲线：

```
wd:      0      5e-5    1e-4    5e-4
acc:   0.9800  0.9804  0.9812  0.9782
                  ↑ 缓坡  ↑ 峰   ↑ 悬崖
```

**"要不要用"是个错问题，"用多少"才是真问题。**

**第三句：一个超参数只测一个点，等于什么都没测出来。**

今天我自己就先犯了这个错：只跑 `wd=5e-4` 就得出"正则化没用"的结论，
补扫剂量后结论反了一半。这是**做实验最常犯的一个错**，也是最容易自欺的一个 ——
因为一个点也能画出一张表，看起来很有说服力。

**以后凡是"某某设置有没有用"的问题，答案都是扫一条曲线，不是取一个点。**

## 6.5 三个武器的分工（一张表记牢）

| | 它改什么 | 什么时候用 | 用错会怎样 |
|---|---|---|---|
| Dropout | **有效容量**（每次随机关一部分神经元） | 模型大、数据小、层数深 | 训练变慢，容量不够时掉点 |
| Weight decay | **参数大小**（把 w 往 0 拉） | 权重范数虚高、函数太抖 | 剂量过大会欠拟合 |
| Early stopping | **训练轮数**（见好就收） | 训练上百轮、后期开始变差 | 轮数本来就少时毫无意义 |

三者的共同点：**都只会让模型变简单。** 没有一个是"让模型更强"的。
（让模型更强的办法是：更多数据、更好的架构 —— 那是另一条路。）
