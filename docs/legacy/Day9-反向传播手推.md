# 一、先破除一个误解：反向传播不是"算法"

大多数人第一次学反向传播，会以为它是一套需要背下来的规则（"这个要转置、那个要 sum"）。**不是。**

它只有一条数学内容：**链式法则**。剩下的全是**记账**。

## 1.1 一个标量的三层链，看清"本地导数 × 上游梯度"

设

```
z1 = w1·x + b1
a1 = relu(z1)
z2 = w2·a1 + b2
L  = (z2 - t)² / 2
```

求 `∂L/∂w1`。链式法则展开：

```
∂L/∂w1 = ∂L/∂z2 · ∂z2/∂a1 · ∂a1/∂z1 · ∂z1/∂w1
```

逐项算，每一项都极其简单（这就是关键）：

| 项 | 值 | 这个名字 |
|---|---|---|
| `∂L/∂z2` | `z2 - t` | 上游梯度（从 loss 传来的） |
| `∂z2/∂a1` | `w2` | **本地导数**（这一层的） |
| `∂a1/∂z1` | `1[z1 > 0]` | **本地导数** |
| `∂z1/∂w1` | `x` | **本地导数** |

**每个节点只需要知道自己的本地导数**。它不知道 loss 长什么样、不知道前面有几层——上游传下来一个数，它乘上本地导数，往下传。

> **这就是反向传播的全部内容**：前向时把中间值（`z2`、`a1`、`z1`）存下来，反向时按相反顺序，每站"上游梯度 × 本地导数"，传下去。
>
> 那些"要转置""要 sum"的规则，**不是新规则**——是链式法则在矩阵形式下必然长成那样。第五节会用形状把这件事讲成机械操作。

## 1.2 为什么必须存中间量（`cache`）

看表里第三行：`∂a1/∂z1` 需要知道 `z1` 的符号。`z1` 是前向算出来的中间值，**反向时已经不存在了**——除非你在前向时把它存下来。

所以每个 `forward` 都要返回一个 `cache`，`backward` 只吃 `cache`，**不重算前向**。这不是"为了省事"，是省掉一整次前向计算；而且重算的话，你还得保证两次算出来的 `z1` 一模一样（浮点不保证）。

```python
def forward(params, X):
    z1 = X @ params["W1"] + params["b1"]
    a1 = np.maximum(z1, 0.0)
    z2 = a1 @ params["W2"] + params["b2"]
    p  = softmax(z2)
    return p, {"X": X, "z1": z1, "a1": a1, "p": p}     # ← cache
```

注意 `p` 也存了。因为 `∂L/∂z2` 那个漂亮形式里只有 `p`，没有 `z2`。

# 二、热身：3 个类，先在纸上算一遍

正式推之前，先做一个**能用手算完成**的小例子，让你亲眼看到那个"漂亮形式"。

## 2.1 设定

```
z = [2.0, 1.0, 0.1]      ← logits（W2·a1+b2 的输出，3 个类）
y = 0                    ← 正确类别是第 0 类
```

## 2.2 前向：softmax 然后取对数

```
exp(z) = [7.389056, 2.718282, 1.105171]        ← e^2, e^1, e^0.1
Σ      = 11.212509
p      = [0.659001, 0.242433, 0.098566]        ← 每项除以 Σ
```

检查：`0.659 + 0.242 + 0.099 = 1.000` ✅

```
L = -log p[0] = -log(0.659001) = 0.417030
```

## 2.3 现在不要推，先"作弊"量一次

用有限差分算出真实梯度（不看任何公式）：

```python
h = 1e-6
∂L/∂z[i] ≈ (L(z + h·eᵢ) - L(z - h·eᵢ)) / (2h)
```

结果：

```
有限差分 = [-0.340999, 0.242433, 0.098566]
```

## 2.4 现在盯着这两个数组看

```
p        = [0.659001, 0.242433, 0.098566]
梯度     = [-0.340999, 0.242433, 0.098566]
             ↑                  ↑        ↑
           差 1.0           完全相同  完全相同
```

而 `y = 0`，所以 onehot 是 `[1, 0, 0]`。

```
p - onehot = [0.659001-1, 0.242433-0, 0.098566-0]
           = [-0.340999,   0.242433,   0.098566]
```

**一模一样。**

## 2.5 换一个 y 验证

同样的 `p`，令 `y = 2`：

```
L = -log p[2] = -log(0.098566) = 2.317030      ← loss 大了很多，因为预测对的是 0.099
p - onehot = [0.659001, 0.242433, -0.901434]
```

`y=2` 时从 `p[2]=0.099` 里减 1，得到 `-0.901`——**梯度最大的那个分量，正是"最该被提高却最低"的那个类**。

## 2.6 两个立刻可以用的自检

**自检 1：每行加起来必须是 0。**

```
p - onehot 的三项之和 = 0.659 + 0.242 + 0.099 - 1 = 0
```

为什么必然为 0？因为 softmax 的三个输出**永远加起来等于 1**。你把 `z` 整体平移（`z + c`），`p` 完全不变，loss 也完全不变——**说明梯度在任何方向上都不能有"全 1 分量"**。这是数学上强制的。

> 这条检查极其好用：**你的 `dlogits` 如果行和不是 0，一定错了**（通常是漏了 onehot 或者 `1/N` 位置不对）。

**自检 2：模型完美时梯度为 0。**

如果 `p = onehot`（预测完全正确，`p[0]=1`），那么 `p - onehot = 0`，梯度全零。合理：已经全对了，不该再动。

# 三、正式推导

现在把第二节的观察**证明**出来。

## 3.1 前向的完整链条（符号表）

```
X  : (N, D)      输入，N 个样本，每个 D 维
W1 : (D, H)      第一层权重
b1 : (H,)
z1 = X @ W1 + b1        (N, H)
a1 = relu(z1)           (N, H)
W2 : (H, C)      第二层权重
b2 : (C,)
z2 = a1 @ W2 + b2       (N, C)      ← logits
p  = softmax(z2)        (N, C)      ← axis=-1，每行归一化
L  = -mean_i log p[i, y[i]]         ← 标量
```

**记住这张表的形状**，第四节全靠它。

## 3.2 第 1 步：`∂L/∂z2` —— 今天唯一需要"真推"的地方

这是整个反向传播里唯一一个**不能靠机械规则得到**的结果——因为 softmax 和 CE 各自都不平凡，但合起来会塌缩成极简形式。**这是你今天要证明的东西。**

### 路线图（不是答案）

**① 先写单个样本的 loss。** 设只有一个样本，`y` 是正确类别下标。

```
L = -log p_y
```

**② 写 `p_i` 的表达式。** softmax 分母是全部类的指数和：

```
p_i = e^{z_i} / Σ_j e^{z_j}
```

**③ 求 `∂p_y/∂z_k`。** 这里要对 `k` 分两种情况，因为 `z_k` 同时出现在**分子**（当 `k=y` 时）和**分母**（永远）。用商的求导法则：

```
∂p_i/∂z_k = p_i · (δ_ik - p_k)
```

> `δ_ik` 是 Kronecker delta：`i==k` 时为 1，否则 0。
> **不要抄这条**——自己用商法则推一遍，分 `i==k` 和 `i≠k` 两种情形。推完你会看到为什么它能写成这种紧凑形式。

**④ 代回 `∂L/∂z_k`。** `∂L/∂z_k = -1/p_y · ∂p_y/∂z_k`（链式法则，`L` 对 `p_y` 求导那一步）。

**⑤ 化简。** 把 ③ 的结果代进去，`p_y` 会约掉。

### 你应该得到的

化简之后，形式简单到你会怀疑自己算错了。填这里：

```
∂L/∂z_k = ______________________
```

如果推出来不是 `p_k - δ_yk` 这种"只含 p 和 onehot"的形式，说明中间某步代数错了。**回去查 ⑤ 的约分。**

### 怎么确认推对了

把 `z = [2, 1, 0.1]`、`y = 0` 代进去，应该得到 `[-0.341, 0.242, 0.099]`——第二节有限差分量的那个。（**这就是为什么先做热身**：你现在手里有一个已知正确答案，推导卡住时可以反复对照。）

### ⑥ 推广到 batch + mean

两个改动，都很机械：

**改动一（batch）：** `N` 个样本各自独立，`∂L/∂z2` 是逐行的事情，形状是 `(N, C)`。

**改动二（mean）：** 这是**最容易漏的一处**。`L = (1/N) Σ_i L_i`，所以

```
∂L/∂z2 = (1/N) · Σ_i (∂L_i/∂z2_i)
```

矩阵形式就是：

```python
dlogits = (p - onehot) / N        # ← 少了 /N 就是最常见的那个 bug
```

> `N=1` 的时候 `/N` 等于 1，**这个 bug 完全不显形**。所以用小 batch 调不通的地方，大 batch 可能会暴露——第五节的实测数据会让你看到这件事有多夸张。

## 3.3 第 2 步：`∂L/∂W2` 和 `∂L/∂b2`

现在往上走一层。`z2 = a1 @ W2 + b2`。

这一层的本地导数不需要推导——**线性层的导数就是"另一个因子"**，和标量时 `z = w·x` 的 `∂z/∂w = x` 是同一件事。难点全在**形状**：

```
z2 : (N, C) = a1(N,H) @ W2(H,C) + b2(C,)
```

`∂L/∂W2` 的形状必须和 `W2` 一样，是 `(H, C)`。手上有的两个量是 `a1 (N,H)` 和 `dlogits (N,C)`，只有一种拼法能得到 `(H,C)`：

```python
dW2 = a1.T @ dlogits      # (H,N) @ (N,C) = (H,C)  ✅
```

`∂L/∂b2`：`b2` 被广播加到每一行，所以它的梯度是**把所有行的贡献加起来**：

```python
db2 = dlogits.sum(axis=0)  # (C,)  ← axis=0 消掉 N 那一维
```

> 回顾 Day 5 那句话：**`axis` 是被消掉的那一维**。`(N,C).sum(axis=0)` 消掉 N，剩 `(C,)`，正好是 `b2` 的形状。**形状对上了，就不需要记规则。**

## 3.4 第 3 步：`∂L/∂a1` 和 `∂L/∂z1`（ReLU）

**先算 `∂L/∂a1`。** `a1` 通过 `a1 @ W2` 影响 `z2`。又是线性层，又是"另一个因子"，但要转置——原因只有形状：

```
da1 必须 (N,H)。手上是 dlogits (N,C) 和 W2 (H,C)。
只有 dlogits @ W2.T = (N,C) @ (C,H) = (N,H)  ✅
```

```python
da1 = dlogits @ params["W2"].T
```

**再算 `∂L/∂z1`。** ReLU 是逐元素的，所以这里不是矩阵乘，是**逐元素乘**：

```
a1 = max(z1, 0)   →   ∂a1/∂z1 = 1 if z1 > 0 else 0
```

```python
dz1 = da1 * (z1 > 0)
```

> **为什么是 `*` 而不是 `@`**：因为 ReLU 不混合不同位置——`a1[i,j]` 只依赖 `z1[i,j]`。逐元素函数，逐元素导数。
> 每次写完一行，问一句"这一层混了位置吗？"混了用 `@`，没混用 `*`。**这条比背规则可靠。**

## 3.5 第 4 步：`∂L/∂W1` 和 `∂L/∂b1`

和第 2 步完全同构，只是把 `a1` 换成 `X`：

```
z1 : (N, H) = X(N,D) @ W1(D,H) + b1(H,)
dW1 要 (D,H)  →  X.T @ dz1 = (D,N) @ (N,H) = (D,H)  ✅
db1 要 (H,)   →  dz1.sum(axis=0)                    ✅
```

## 3.6 汇总

```python
dlogits = (p - onehot) / N
dW2 = a1.T @ dlogits
db2 = dlogits.sum(axis=0)
da1 = dlogits @ W2.T
dz1 = da1 * (z1 > 0)
dW1 = X.T @ dz1
db1 = dz1.sum(axis=0)
```

**七行。** 这就是整个两层网络的反向传播。你今天推的所有东西，落地就是七行。

> 但注意：**先自己推，再对这张表**。顺序反了，你今天什么都没得到——因为三个月后你只会记得"当时对着文档抄过七行"。

# 四、形状凑法：唯一需要的自检工具

矩阵求导里"该不该转置"是最容易懵的地方。**不要背规则，看形状。**

## 4.1 一张表

| 梯度 | 必须的形状 | 因为 |
|---|---|---|
| `dlogits` | `(N, C)` | 和 `z2` 同形 |
| `dW2` | `(H, C)` | 和 `W2` 同形 |
| `db2` | `(C,)` | 和 `b2` 同形 |
| `da1` | `(N, H)` | 和 `a1` 同形 |
| `dz1` | `(N, H)` | 和 `z1` 同形 |
| `dW1` | `(D, H)` | 和 `W1` 同形 |
| `db1` | `(H,)` | 和 `b1` 同形 |

**规律：每个梯度的形状永远等于它对应的参数的形状。** 这不是巧合——`∂L/∂W` 里 `L` 是标量，对矩阵求导是"逐元素求偏导"，自然同形。

## 4.2 反例：写错但能跑通的三种

这是最需要警惕的部分——**下面三种写法 numpy 都不会报错**：

| 错误写法 | 算出来形状 | 为什么能跑 |
|---|---|---|
| `dW2 = dlogits.T @ a1` | `(C, H)` | `(C,N)@(N,H)` 合法，只是转错了 |
| `da1 = dlogits @ W2` | 报错 | `(N,C)@(H,C)` 内维 `C≠H` |
| `dW1 = dz1.T @ X` | `(H, D)` | `(H,N)@(N,D)` 合法，只是转错了 |

前两个里的第一个和第三个**在 `C==H` 或 `D==H` 时会连形状都对**——然后你拿到一个"形状正确、数值全错"的梯度，对拍时报一个莫名其妙的误差，你会以为是自己公式推错了。

> **所以骨架里每一行后面都加了 `assert` 检查形状。** 这是我特意放的：让"转错了"在形状这一关就死掉，而不是拖到最后对拍。
>
> 这一条对你尤其重要——你的排障习惯是"先看报错在哪一行"，那就要让错误**尽早报**。

## 4.3 一句话总结转置的方向

> **让"求和的那一维"对齐。**
> `dW2 = a1.T @ dlogits`：要把 `N` 消掉（因为 `N` 个样本的贡献要累加到同一个 `W2` 上）。`a1.T` 是 `(H,N)`，`dlogits` 是 `(N,C)`，`N` 在中间相遇被消掉，剩 `(H,C)`。

# 五、四种写错方式，实测代价

我用同一份数据把四种常见错误都跑了一遍（`N=8, D=5, H=4, C=3`），得到真实误差：

| 错误 | `dW2` 最大误差 | 相对倍数 |
|---|---|---|
| 正确 | 2.8e-17 | 0.0× |
| **漏掉 `/N`** | **1.514** | **7.0×** |
| 在 `p-onehot` 上又套了一次 softmax | 0.266 | 1.2× |
| **忘记 ReLU 导数**（`dz1 = da1`） | — | 见下表 |

## 5.1 关键发现：错误的"可见性"随 batch 大小反向变化

我扫了五个 batch 大小，看同一个 bug 差多少倍：

| N | 漏 `/N` 的相对倍数 | 忘记 ReLU 的相对倍数 |
|---|---|---|
| 1 | **0.0×**（完全看不出来） | 2.39× |
| 4 | 3.0× | 2.09× |
| 16 | 15.0× | 1.63× |
| 64 | 63.0× | **0.78×** |
| 256 | **255.0×** | 0.84× |

看这两列的走向：

- **漏 `/N` 的相对倍数 = `N - 1`**，精确得可怕。`N=1` 时**完全没有误差**（除以 1 等于没除），`N=256` 时梯度大 255 倍。
- **忘记 ReLU 的相对倍数反而随 N 下降**，到 `N=64` 时只有 `0.78×`——**误差比真实值还小**，你盯着数字看根本不像错了。

> **这是一个真正反直觉的结论**：同一份代码，用小 batch 和用大 batch，暴露出来的 bug 完全不同。
> - 用 `N=1` 调试 → 漏 `/N` 隐身
> - 用 `N=64` 调试 → 忘 ReLU 隐身
>
> **所以对拍必须至少在两个不同的 N 上做。** 骨架里我设了 `N=8`（主检查）和 `N=100`（第二组），就是这个原因。

## 5.2 「误差 0.78 倍」比「误差 255 倍」更危险

255 倍那种，你一眼就知道炸了。0.78 倍那种，梯度看起来"很正常"——大小合理、符号合理、训练甚至能跑（loss 会下降，只是降得更慢、收敛到更差的地方）。

**这种 bug 只能靠独立裁判抓。** 这就是第六节的有限差分。

## 5.3 一个"写错了但完全不影响"的例子

ReLU 的导数在 `z1 == 0` 那一点没有定义（左导数 0、右导数 1）。代码里写 `z1 > 0` 还是 `z1 >= 0`？

实测：**两者误差完全相同（0.0）**，因为连续分布下 `z1` 恰好等于 0 的概率是零。

> 结论：这个细节**在随机输入下不重要**。但如果你的输入里有大量精确的 0（比如 `b1` 初始化成 0 且这一层输入全零的退化情形），就会不一样。**知道它不重要，也是知识**——省得你为了一个无所谓的边界跟自己较劲。

## 5.4 顺带：`float32` 够不够

清单要求误差 `< 1e-5`。实测：

| 精度 | 与 float64 参考的误差 |
|---|---|
| float64 | 3e-17 |
| float32 | **3e-8** |

`3e-8` 远小于 `1e-5`，所以**用 `float32` 也能满足清单要求**。但作业骨架里我用的是 `float64`——因为对拍的目的不是"够用"，是"证明公式同一份"。`float32` 的 `3e-8` 里混着舍入误差，会掩盖真正的公式错误（真错了通常差 1e-1 量级，仍然分得开，但没必要给自己留模糊地带）。

# 六、有限差分：唯一的独立裁判

Day 8 已经讲过原理，这里只说它在**多层网络**上的用法差异。

## 6.1 不再是"对 x, y 各扰一次"

Day 8 的 `f(x,y)` 只有两个参数。现在有 `W1(5,4) + b1(4) + W2(4,3) + b2(3) = 39` 个参数。

做法：**逐元素扰动**。对每个参数矩阵的每个元素：

```python
for 每个元素 (i, j):
    old = params[k][i, j]
    params[k][i, j] = old + h;  Lp = loss(params)
    params[k][i, j] = old - h;  Lm = loss(params)
    params[k][i, j] = old
    grad[k][i, j] = (Lp - Lm) / (2*h)
```

`39` 个参数就是 `78` 次前向。对小网络完全可行，对大网络（百万参数）不可能——**这就是为什么必须有反向传播**。

> 这句话值得记住：**有限差分是 `O(参数个数)` 次前向，反向传播是 `O(1)` 次前向**。这不是"快一点"，是能不能用的区别。有限差分只配当裁判，不配上场。

## 6.2 `h` 用多少

Day 8 测过 U 型曲线，最优点在 `1e-5` 附近。这里用 `h=1e-5`，实测误差 `1.8e-11`。

`h=1e-5` 而不是 `1e-8` 的原因：`1e-8` 时 `L(x+h)` 和 `L(x-h)` 的前 8 位有效数字相同，相减全被舍入吃光。

## 6.3 三方对拍的判读

跑完会看到这样一张表（本机实测）：

```
param   numpy vs torch        numpy vs 有限差分
--------------------------------------------
W1          5.551e-17            1.712e-11
b1          2.776e-17            6.826e-12
W2          2.776e-17            1.808e-11
b2          2.776e-17            1.555e-11
```

怎么读：

| 现象 | 含义 |
|---|---|
| 两列都 `< 1e-9` | 三方一致，收工 |
| numpy vs torch 大、numpy vs 有限差分小 | **torch 那边你对拍写错了**（比如没取 `.grad`、用了不同的 loss reduction） |
| numpy vs torch 小、numpy vs 有限差分大 | **有限差分那边坏了**（`h` 太大/太小，或者参数没还原） |
| **只有 `W1`/`b1` 错，`W2`/`b2` 完全对** | **错在 `da1` 或 `dz1`**。因为 `dlogits` 和 `W2` 那一行是对的（否则 `W2` 的梯度也会错）。九成是 `dz1` 忘了乘 ReLU 导数 |
| **两列都大、四个参数全错** | **`dlogits` 错了**。这时看第五节的表：误差是 `N-1` 倍 → 漏 `/N`；1.2 倍 → 多套了 softmax |

> **第四行那种"部分参数错"的模式，比误差数值更有诊断价值。**
> 反向传播是一条链，错在第 3 站，第 1、2 站的计算仍然是干净的——**所以"哪些梯度对了"直接告诉你"链在哪断的"**。
>
> 这也是我给 `main()` 加 `[1a]` 那道单独检查的原因：先用有限差分把 `dlogits` 单独验一遍，验过了再去查后面。**一次只怀疑一个东西**，比同时怀疑七行有效得多。

四个分支里，只有最后两个是"今天没学会"。前两个都是对拍脚手架的问题——**但你不能假设它们不存在**，因为把好的梯度误判成坏的，比 bug 本身更耗时。

# 八、报错对照表

| 报错 / 现象 | 原因 | 修法 |
|---|---|---|
| `AssertionError: dlogits 形状应为 (8,3)` | onehot 构造错了，或者 `p` 的行列反了 | `onehot[np.arange(n), y] = 1.0` 单独一层，别在 `p` 上原地改 |
| `AssertionError: 每行和应为 0，实测 ...` | 漏了 onehot（只用了 `p`），或 `/N` 加在了错误的位置 | 检查 `dlogits = (p - onehot) / N` 这个整体 |
| `AssertionError: dW2 形状应为 (4,3)` | 转置方向反了 | 看 4.3：让 `N` 那一维在中间相遇 |
| `ValueError: matmul: Input operand 1 has a mismatch...` | `@` 两边内维不等 | 打印两边 `.shape`，按 4.1 的表倒推 |
| `numpy vs torch` 误差 `~1e0`，`vs 有限差分` 也 `~1e0`，**四个参数全错** | **`dlogits` 公式错了** | 按第五节定位：`N-1` 倍 → 漏 `/N`；`1.2` 倍 → 多套了 softmax |
| **只有 `W1`/`b1` 错，`W2`/`b2` 误差 `<1e-16`** | **`dz1` 少了 ReLU 导数** | 脚本会直接打印这个判断。`dz1` 必须是 `da1 * (z1 > 0)` |
| `numpy vs torch` 误差大，但 `vs 有限差分` 小 | torch 对拍写错了 | 检查 `.grad` 取的是不是 `None`、loss reduction 是否为 `mean` |
| `RuntimeError: element 0 of tensors does not require grad` | `torch.tensor(params[...])` 忘了 `requires_grad=True` | 骨架里已写好，别删 |
| 误差 `~1e-2` 但两边思路都对 | 某处用了 `float32` | 对拍统一 `float64` |
| 有限差分误差大（`>1e-6`） | `h` 设成 `1e-8` 或更小 | 用 `h=1e-5` |
