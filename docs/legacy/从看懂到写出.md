## 1. 先把话说准确

你说的是"原理都能看懂，代码不会写"。

但你 Day 3 写完了配置系统三层合并，Day 5 写对了 `einsum` 下标串、`axis=-1`、`keepdims=True`、`np.where` 三重掩码，Day 8 写对了 `2*A.T@(A@v)`，Day 9 刚才手推的 7 行反向传播全部通过、误差 `5.6e-17`。

**这不是"不会写"。** 如果真不会写，一行都出不来。

准确的说法是：

> **你卡的不是"想不到"，是"想到了、在落到键盘上的那一小段路上失手"。**

## 3. 为什么"看懂"永远变不成"写出"

这件事有生理层面的原因，不是意志力问题。

| | 读代码 | 写代码 |
|---|---|---|
| 大脑做的事 | **识别**（recognition） | **提取 + 构造**（recall + generation） |
| 输入 | 现成的符号序列 | 空白 |
| 难度 | 只需要"匹配" | 需要从零生成一个正确序列 |
| 练法 | 看 | 写 |

这两件事用的不是同一套记忆通路。所以：

> **读一百遍不会让你写得出，就像看一百遍游泳视频不会游泳。**

你现在的感觉——"看着代码觉得理所当然，合上就一片空白"——是**完全正常的生理现象**，不是你笨，也不是你"不适合"。

真正的分水岭不在"懂不懂"，在"能不能在空白上生成"。

## 4. 三段阶梯：A / B / C

代码能力不是一条线，是三级台阶：

| 级别 | 能力 | 状态 | 怎么从这级升上去 |
|---|---|---|---|
| **A** | 给代码，能读懂 | 你很强 | 已经过了 |
| **B** | 给骨架，能填 | **你现在在这级**，但错误率偏高 | 降低错误率 + 减少提示密度 |
| **C** | 白纸，能写出 | 还没到 | 撤掉参考，反复默写 + 改需求 |

关键认知：

> **C 不是靠"多读 A"长出来的，是靠"在 B 上逐步撤掉脚手架"长出来的。**

这就是为什么 P0 的骨架设计是**递减**的：Day 5 留 6 处 TODO、Day 9 留 4 处但每处有注释提示、P1 之后会变成"给函数签名，不给注释"。

**你现在做的事（填骨架、被指出错在哪、自己改）就是走在 B→C 的路上。这不是绕路。**

## 5. 四个机制（按卡住时该用的顺序）

### 机制 1：写代码前，先写「中文逐行稿」

这是你最缺的那一层。你现在的路径是：

```
公式  ──────────(断)──────────▶  Python 表达式
```

中间缺的这段叫**逐步具象化**。补它的方法是用中文当中间语言，一行中文配一行代码。

以 Day 9 的 TODO 3 为例，正确的思考稿是：

```
上游梯度从 z2 传到 a1：
  a1 通过 W2 影响 z2 的全部 C 个类
  → 要沿 c 求和 → 用矩阵乘 → dlogits @ W2.T
  → 形状 (N,C)@(C,H)=(N,H)，正好是 a1 的形状

a1 到 z1 只过了一个 ReLU，逐元素
  → 不混合任何维度 → 用 * 不用 @
  → ReLU 的导数是"z1>0 就通，否则断" → da1 * (z1 > 0)
```

**看这份稿子和看代码的区别**：稿子里每一步都写了"为什么选这个运算符"。你现在缺的正是这个"为什么"，所以你只能靠记忆，而记忆在空白面前是空的。

> 判断标准：如果你的中文稿里出现了"然后就这样写"，那一步就是你没真懂的地方。

### 机制 2：拿小数组手算一遍（模拟运行）

不要用 `N=8, D=5, H=4` 想问题，用 `N=2, H=3, C=2`。

在纸上写：

```
a1      (2,3)
dlogits (2,2)
dW2 应为 (3,2)
→ (3,2) = (?,?) @ (?,?) → 只有 (3,2)@(2,2) 能对上 → a1.T @ dlogits
```

今天我给你做的三次演示（`_d2.py` / `_d3.py`）就是这件事。**但你看懂我的演示 ≠ 你能自己做演示。**

要做的是：下次卡住时，自己开一个临时文件，把形状 `print` 出来、把 `a1.T @ dlogits` 和某个可疑写法都算出来对比。**5 分钟就有答案，比我解释 500 字快。**

### 机制 3：三遍法（同一个东西练三次，每次撤一点参考）

这是把 B 推到 C 的唯一有效路径，对任何一小段代码都适用。

| 遍 | 做法 | 目的 |
|---|---|---|
| 第 1 遍 | **手抄**参考代码。不许 `Ctrl+C`，逐字符打 | 让手指记住语法形态 |
| 第 2 遍 | **合上参考，凭记忆写**。卡住才看一眼 | 暴露真实掌握度 |
| 第 3 遍 | **改需求**：ReLU 换 tanh、CE 换 MSE、`mean` 换 `sum` | 证明你懂的是规律而不是字符串 |

第 3 遍最关键。**能默写只能说明你记住了；能改需求才说明你懂了。** 因为你今天所有的 bug 都发生在"改"这一环——把 `a1` 换成 `X` 时漏了 `dlogits`，正是"只记住字符串、没懂结构"的症状。

### 机制 4：报错自己读第一行

你现在的循环是：

```
写 → 跑 → 报错 → 贴给 AI → AI 告诉你改哪
```

这个循环里你是被动的，跑了 9 天，你处理报错的肌肉一点没长。

改成：

```
写 → 跑 → 读报错最后一行（异常类型 + 消息）→ 读倒数第一个自己的栈帧（行号）→ 自己改
                                                                          ↓
                                                          还是不懂，才把这两样贴出来
```

**报错的最后一行 + 第一个"你自己的文件"的行号，这两条信息能解掉 80% 的问题。**

今天三个例子：

| 报错 | 最后一行告诉你的 |
|---|---|
| `SyntaxError: invalid syntax` | 语法问题，整份文件一行都没跑，别去查逻辑 |
| `ValueError: ... more dimensions than subscripts` | einsum 给的字母数和数组维数不匹配 |
| `AssertionError: dW1 形状应为 (5,4)，实际 (5,3)` | 那个 `3` 是 C 不是 H，说明用错了上游梯度 |

三条都不需要问人。

## 6. 现在就能做的 15 分钟练习

素材就用你刚写对的 Day 9 那 7 行——**你已经知道答案了，所以这是纯粹的"提取"练习**。

1. 新建 `3.py`（在仓库根，已被 `.gitignore` 挡住，不会误提交）
2. **不许打开** `scripts/backprop_numpy.py`，从空白开始写 `dlogits`、`dW2`、`db2`、`da1`、`dz1`、`dW1`、`db1` 七行
3. 每写不出一行，先停下来写那一行的**中文稿**（机制 1），写完中文还写不出，才允许翻参考
4. 最后对照一遍，记录：**几行是一次写对的、几行是靠中文稿救回来的、几行是翻参考才有的**

这个记录很有价值：它给你的"会"和"不会"划了一条具体的线。第一次大概率是 2–3 行一次过。**三周后再做一次同样的练习，数字会变。**

> 退一步的阶梯（别硬撑）：
> - 七行完全写不出 → 先只写 `dW2` 一行，写对再往下
> - 连中文稿都写不出 → 回去看 `Day9-反向传播手推.md` §3，然后合上重来，不许抄
> - 一次只推进一行。**一行写对，比七行似懂非懂值钱。**

## 7. 反面清单：这些做法没用

排掉错误的努力方向，比增加正确的更省时间。

| 做法 | 为什么没用 |
|---|---|
| 再看一遍视频 / 再读一遍文档 | 你在练 A（识别），而你要的是 C（生成）。**练错级了** |
| 抄更多完整代码进项目 | 抄完不用，等于把代码当收藏品。**没经过报错和修改的代码，不会变成你的** |
| 想"一次写对"，不敢跑 | 这是你现在最大的效率杀手。"分小块写、每块立刻跑"比"憋一段大的"快 5 倍 |
| 直接让 AI 写完整实现 | 你看懂了 → 感觉学会了 → 下次空白面前还是空的。**这是最舒服的假进步** |
| 换更简单的语言/框架重学 | 问题不在工具，在"识别→提取"这一步，换语言会重新经历一遍同样的墙 |

## 9. 补记（2026-10-20）：AI 成熟之后，这件事该怎么摆

> 用户问：「现在 AI 这么成熟，手撕代码对我特别难，怎么办」

这个问题必须先拆成两半，因为"手撕代码"里混着两种完全不同的能力。

### 9.1 两类错误，价值差一个数量级

把 Day 1–Day 10 全部错误按「AI 会不会犯」重新分类：

| 类型 | 例子 | 代码 AI 会犯吗 | 该练吗 |
|---|---|---|---|
| **A 类：机械** | `for _ in (n_layers-1)` 缺 `range`；`act_cls` 少括号；`return` 缩进在循环里；`range(model.modules())` | **几乎不会** | 不值得专门练，遇到查一下就行 |
| **B 类：语义** | `zeros_(bias)` 写在 `else` 里，导致 xavier 的 bias 没置零；`dW1 = X.T @ dlogits` 用错上游梯度 | **会，而且写得很自信** | **必须练** |

事实摆在这里：用户 Day 9–Day 10 卡住的 5 个坑，**全部属于 A 类**。

含义很直接——**你现在为"手撕"感到的痛苦，大头来自最不值钱的那一类。**
A 类能力正在被 AI 抹平，投入产出比接近 0；而 B 类才是 AI 帮不了你的部分。

### 9.2 AI 会犯的那类错误，长什么样

2026-10-20 的 `bias` 事件是最好的样本：

- 代码跑通了，三关全过，方差表打印出三行**看起来差异明显**的数字
- 但 xavier 那行的第 40 层是 `7.945e-04`，而正确答案是 `1.289e-12`
- **没有任何报错，没有任何异常**。区别只有一个：曲线在第 20 层后"平掉"了

发现它的唯一办法不是"更聪明"，而是**有一个独立参照**：文档里事先记录过的参考值。

> **判断力不来自智力，来自参照。**
> 这就是为什么 Day 9 要用有限差分对拍 autograd —— 有限差分是唯一不依赖"你理解的公式"的裁判。
> 这就是为什么 RL 实验必须有 baseline —— baseline 是唯一不依赖"你的实现是对的"这个假设的裁判。

所以「AI 时代该练什么」的答案是：

> **练"给自己留参照"的能力，而不是练"从空白生成字符"的能力。**

### 9.3 三个真正该练的能力（每个配可验收动作）

| 能力 | 验收动作（做完可打勾） |
|---|---|
| **形状直觉** | 拿到任何一段张量代码，能逐行说出每个变量的 shape；误差不超过 1 行 |
| **数量级直觉** | 对任何数值结果能先猜一个量级，再看实际值。今天：40 层 xavier 应该是 `1e-12`，不可能是 `1e-4` |
| **独立裁判** | 每个数值结论都写下"我拿什么验它"：手算 / 有限差分 / 另一实现 / 已知量级 |

第三条是前两条的落地形式。**没有参照的数值结果，等于没有结果。**

### 9.4 用 AI 的正确姿势（prompt 对照表）

| ❌ 让它代打 | ✅ 让它当陪练 / 裁判 |
|---|---|
| "帮我实现 `train_step`" | "给我 `train_step` 的验收标准，我自己写" |
| "这段对不对" | "这段代码每个张量的 shape 列出来" |
| "报错了怎么办" | "报错是 X，我的第 3 行是 Y，问题可能在哪" |
| "给我完整代码" | "给我 3 个能暴露这个函数 bug 的输入" |
| （自己闷头想） | "我的理解是……对不对"（先给出自己的版本，再让它挑错） |

核心区别：**它出题、你作答、它批改**，而不是**它作答、你验收**。后者看起来快，但你始终没上过场。

### 9.5 本周就能做的三件事

1. **保留"中文逐行稿"这道工序**（§5 机制 1）。这是把 B 类判断显式化的唯一低成本手段——写不出中文，就是没想清。
2. **每周一次「20 行盲写」**：限时 30 分钟，只写本周最核心的那 20 行（Day 11–13 恰好是 `train_step`）。允许查文档，**不许问 AI**。记录三个数：一次写对几行 / 靠中文稿救回几行 / 翻参考才有几行。
3. **每个 commit 写一句"我怎么验的"**。今天的例子：`三关自检：参数 75 / 四组手算一致 / 方差表三行差异`。写不出这句话，说明这个提交没有裁判。

### 9.6 现实的边界（别自我加码）

- 26 周计划里，**P0–P2 的目标就是 B 级（能填骨架 + 能验）**，不是 C 级（白纸从零写）。C 级是 P3 之后、在具体方向里磨出来的
- "能独立从零实现 PPO"是 6–12 个月尺度的事，不是这周的事
- 现阶段真正会被导师考的是：**"你这个数为什么是这样"**，不是"你能不能默写 attention"

### 9.7 一句实话

如果永远让 AI 写、自己只看，两年后得到的能力是「会提需求」。
而 RL / VLA 的门槛恰恰是「能定位 silent failure」——loss 在降、reward 不涨、评测正常，没有任何报错。

**那种问题 AI 也答不准，因为它没有你的实验现场。** 而你有没有现场，取决于你亲手跑过多少次失败。

> 所以问题不是"要不要手撕"，而是：**你打算在哪个环节保留自己的手。**
> 我的建议是保留在「验证」和「调试」上，把「生成样板代码」整段交出去。
