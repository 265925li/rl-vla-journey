# docs/legacy/ —— P0 原始讲义（抢救回来的）

这个目录里的文件**不是我自己写的整理版**，而是 `2026-10-23` 那一版工作区的快照。

## 怎么来的

时间线（两起事故，一正一反）：

```
2026-10-23 15:18   工作区快照的最后时刻。这些讲义写在仓库外的 学习计划/ 里，
                   从未进过 git
2026-10-26         工作区被清空 → 学习计划/ 全部丢失，只有代码因提交过而幸存
                   （当时的应对：把讲义改写进 docs/ 并提交，见上一级 README）
2026-10-27         工作区被回滚到 10-23 的快照
                   → 这批讲义**意外回来了**，9752 行一行不少
                   → 代价是另一头：Day 17–21 的 6 个提交从本地 git 消失
                     （从 GitHub fetch 后恢复）
```

**所以这个目录是「回滚事故的副产品」。** 它本来应该永久消失了。

## 和上一级 `docs/` 的关系

两套并存，不是重复，是**两个不同的版本**：

| | `docs/Day1x-*.md` | `docs/legacy/Day1x-*.md` |
|---|---|---|
| 来源 | 事故后重新整理 / 从对话里重建 | 10-23 的原始写作 |
| Day 11–15 | **没有**（当时认为永久丢失） | **有，完整** |
| Day 16 | 640 行，重写版 | 642 行，原始版，内容完全不同 |
| 定位 | 精简、带实测数字、可查阅 | 详细、带填空引导、按天推进 |

举例：`legacy/Day11-数据集与训练循环.md`（525 行）是当时那份正文，
上一级 README 曾经把它列在「已丢失（正文无法重建）」里 —— 现在可以划掉了。

## 使用建议

- **想查某个结论/数字** → 用上一级 `docs/` 的整理版（更紧凑，都有实测支撑）
- **想重看当时的推导细节、填空引导** → 用这里的原始版
- **`P0-逐日执行清单.md`（966 行）只有这里有** —— 它是 P0 那 21 天的完整任务清单，
  P0 已收口，留作历史记录
- `P0-每日打卡看板.html` 同理，是可以点开的 checkbox 看板（localStorage 记进度）

## 顺手记一条纪律

这批文件能回来纯属运气（正好赶上一个早于删除时刻的快照）。
**运气不是策略。** 所以它们现在在 git 里，而且已经 push。

上一级 README 里那条「只有 `git clone` 能救回来的东西，才算真的存下来了」，
今天应该再补半句：**只有 push 到远端的提交才算，本地提交也会跟着工作区一起没。**
