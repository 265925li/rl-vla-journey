总体设计思路

你的情况有一个关键错配：理论不会卡你，代码会卡死你。数学强的同学学 RL 最常掉的坑是——公式全懂、能讲 PPT，但代码跑不起来，于是永远停在"看懂"层面。

所以这份计划和通用路线图有三点不同：① 前 3 周不碰 RL，只补工程；② 每个算法必须手写一遍，调包库只做对照 baseline；③ 每 6 周设一个显式的方向决策点。

三条并行主线：理论线（优势区，快推不恋战）· 代码线（瓶颈，慢嚼写透）· 论文线（W6 起每周 1–2 篇）。

P1

RL 理论地基：MDP → TD → DQN

W4–W8 · 100–125h

主教材用 赵世钰《强化学习的数学原理》（B 站，中文重推导，正好吃你的数学优势），辅以 Sutton & Barto 第 1–9 章。

知识清单
  • MDP 与贝尔曼方程：回报、值函数、贝尔曼期望方程与最优方程 —— 必须能手推；压缩映射与不动点
  • 动态规划：策略迭代、值迭代、截断策略迭代
  • 无模型预测：MC、TD(0)、n-step TD、TD(λ)；用数学讲清偏差–方差权衡
  • 无模型控制：Sarsa、Q-Learning、ε-greedy、GLIE；on-policy vs off-policy 的本质
  • 值函数逼近：致命三要素（函数逼近 + 自举 + off-policy）、DQN 的经验回放与目标网络
  • DQN 改进链：Double → Dueling → Prioritized Replay → Noisy Net → Rainbow
  • 探索与利用：UCB、Thompson Sampling、熵正则化
代码任务
验收：能手推贝尔曼最优方程并解释值迭代为何收敛；能不背课文地讲清 DQN 每个组件为什么存在；CartPole 稳定拿到接近满分。
P2

策略优化：PG → PPO → SAC

W9–W14 · 120–150h

从"估价"转向"直接优化策略"。PPO 是本阶段核心，必须手写一遍并跑通 MuJoCo。

知识清单
  • 策略梯度：策略梯度定理（对数技巧 / 似然比两种推导）、REINFORCE、baseline、reward-to-go
  • Actor-Critic：A2C/A3C、优势函数、GAE(λ) —— 再一次的偏差–方差权衡
  • 信赖域方法：TRPO 的 KL 约束与单调改进；PPO 的 clipped surrogate，必须能解释 clip 在约束什么
  • 连续控制：DDPG → TD3（双 critic / 延迟更新 / 目标平滑）、SAC（最大熵、重参数化、自动调温）
  • 工具链：Gymnasium API（terminated vs truncated）、MuJoCo、SB3 作对照、VectorEnv、种子可复现
代码任务
验收：能解释 PPO 的 clip 在做什么；手写 PPO 在 MuJoCo 上曲线合理；完整复现过一篇工作。

★ 决策点 A · 第 14 周末

到这里你已经真正知道 RL 是什么了。做一次显式决策，三选一：

A · 算法 / 理论本身离线 RL、多智能体、探索机制、收敛性保证 —— 最吃你的数学优势，可冲理论/算法类论文
B · RL for LLMRLHF → DPO → GRPO、过程奖励模型、推理模型、Agent RL —— 当前最热、工业界岗位最多，但工程量大
C · 具身智能 / VLA机器人策略学习，RL + 模仿学习 + 多模态 —— 直接进入 P3，软硬结合，天花板高
决策依据：别看"哪个方向火"，回头看 W9–W14 这六周里，你写哪部分代码时最不觉得累。这个体感信号比理性分析更可靠，因为它反映了你能不能长期忍受这件事的日常。
P3

VLA 与具身智能入门

W15–W20 · 120–150h

W15 先花一周补齐 Transformer（手写 multi-head attention，不用 nn.Transformer），否则后面全是黑箱。

知识清单
  • 视觉语言基础：ViT、CLIP（对比学习）、SigLIP、DINOv2，视觉 token 与语言 token 如何对齐
  • 模仿学习 / 行为克隆：BC、DAgger、协变量偏移；动作表示（离散 token vs 连续 chunk）
  • 代表方法：Diffusion Policy、ACT（Action Chunking Transformer）
  • VLA 谱系：RT-1(2022) → RT-2(2023，动作当 token) → OpenVLA(2024，开源 7B) → Octo → π0 / π0-FAST(流匹配)
  • 关键问题：动作 tokenization、跨本体泛化、推理频率、数据规模与来源
  • 评测与仿真：LIBERO、SimplerEnv、RoboMimic、CALVIN；MuJoCo、Isaac Lab、Genesis
  • RL × VLA 交叉地带：VLA 初始化 + RL 微调、奖励设计、sim2real 域随机化、偏好对齐迁移
代码任务
验收：能画出完整 VLA 技术路线图，讲清 RT-1 → RT-2 → OpenVLA → π0 每一代解决了上一代的什么问题。
P4

相邻方向速览 + mini 课题

W21–W24 · 100–120h

速览的价值不是"学会"，而是 排除法 —— 看清哪些东西你完全不感兴趣。每个方向只花 1–2 天。

速览清单
  • 世界模型：Dreamer v3、Genie、World Models —— 用学到的模型做规划
  • 多智能体 RL：MADDPG、QMIX、MAPPO —— 核心难题是信用分配与非平稳性
  • LLM 后训练：RLHF → DPO → GRPO、过程奖励模型、推理模型
  • 离线 RL：CQL、IQL、Decision Transformer（把 RL 变成序列建模）
  • 效率与安全：样本效率、安全 RL、可解释性
mini 课题（本计划最重要的产出）
  • 题目候选：复现 + 消融｜VLA 模块改造｜RL 微调 BC 并量化提升｜小模型 GRPO 对齐复现
产出清单
验收：手上有一个完整作品 + 一套方法 + 对 3–5 个方向的实际体感。

三个必须先处理的坑
  1. PATH 里的 python 不是 conda 的 —— 指向 C:\...\Programs\Python\Python312（独立安装，无 torch）。直接 pip install 会装进这个野生 Python，然后你在 conda 环境里怎么都 import 不到。用完整路径 & "E:\anaconda\envs\pytorch\python.exe" 脚本.py。注意：conda activate 在本机 PowerShell 里无效（conda 4.10.3 未初始化 PowerShell），别依赖它，或用 Anaconda Prompt。
  2. pytorch 环境里 RL 依赖一个都没有 —— 已装 torch/torchvision/numpy/tensorboard；缺 gymnasium、stable_baselines3、scipy、matplotlib、pandas。
  3. conda 4.10.3 是 2021 年的版本，老式解算器装现代包会极慢甚至解不出依赖；且未对 PowerShell 初始化。另有 pingyeling 幽灵环境条目（目录已不存在）需要清理。
任务能否本地跑说明
DQN / PPO / SAC（CartPole）轻松模型只有几层 MLP
PPO / SAC（MuJoCo）可以显存占用 < 1GB，压力在 CPU 和内存

LeRobot + ACT / Diffusion Policy可以小型 CNN / Transformer，几百 MB

7B 模型 4-bit 推理勉强权重约 4GB，做 demo 可以
7B 模型 LoRA / QLoRA 微调不行4-bit 权重 ~4GB + 激活 + 优化器，6GB 必 OOM
FlashAttention-2不支持需要 sm_80+（Ampere）
TF32 / 原生 bf16不支持Turing 无 Tensor Core；torch 报 bf16 可用是软件模拟，反而更慢

训练精度结论

Turing 上就用 fp16 + GradScaler，或干脆 fp32（RL 的网络小，fp32 也不慢）。不要用 bf16。

需要 7B 以上微调时：本地负责开发调试，云端负责大任务（Colab / Kaggle / AutoDL / 学校集群）。注意 T4 也是 sm_75，同样没 Tensor Core；要快就选 A100 / L40S / 4090。

另外 CUDA_PATH 指向 CUDA 11.3，与 torch 自带的 cu126 不一致——日常训练无影响，但编译自定义 CUDA 算子时会出问题（部分机器人与 VLA 包需要）。

每周节奏模板

避坑清单

针对"编程弱"的专项提示 —— 这几条比上面所有内容加起来更能决定你能否走完。

  1. 不要在没跑通玩具问题前上大项目。CartPole 都没稳，别碰 MuJoCo。
  2. 一次只引入一个新概念。跑通再加下一个。同时改三处，出错你归不了因。
  3. 报错先读完整 traceback。最后一行是错误类型与原因，往上数第三行才是出错位置。
  4. 复制别人的代码必须逐行能解释，否则等于没写。看不懂就追问到底。
  5. 不要开三条线并行。RL 和 VLA 分阶段走，不要同时学。
  6. 不要追求"看完所有课"。课程只是骨架，代码任务才是主体。
  7. 曲线不好别急着调超参。先查环境有没有 bug、数据对不对、reward 定义是否符合预期。超参是最不该先怀疑的东西。
  8. 每天提交 Git。不是为了好看，是为了你敢改代码。
